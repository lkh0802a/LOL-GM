# LOL_GM_SPEC.md

> LOL GM 최상위 설계 명세. 구현 전 전체 코드베이스를 분석하고 본 문서를 기준으로 기존/부분/신규/삭제 기능을 분류한다. 충돌 시 최신 본 명세를 우선한다. UI만 있는 가짜 기능, TODO 대체, 의미 없는 독립 수치/슬라이더를 금지한다.

## 개발 범위와 현재 진행 기준

전체 문서는 최종 목표이며 기능을 임의 삭제하지 않는다. 현재는 승인된 전체 23단계와 깊이 보강, 확인된 UI·엔진 개선을 진행한다. 현재 구현 상태와 다음 작업은 [DEVELOPMENT.md](DEVELOPMENT.md)를 따른다. 다음 핵심 루프는 계속 유지해야 한다.

`새 게임 → 팀 선택 → 날짜 진행 → 로스터 → 밴픽 → 경기 → 결과/통계 → 순위 → 일정 진행 → 플레이오프 → 시즌 종료 → 다음 시즌`

- 미래 기능과 호환되는 데이터 구조를 먼저 설계한다.
- 미구현 미래 기능을 가짜 UI/TODO로 미리 만들어두지 않는다.
- Phase 1부터 UI는 **모바일 퍼스트**로 설계한다. 스마트폰 세로 화면을 우선하고 PC/태블릿으로 확장한다.
- 외부 배포/PWA/클라우드 운영 최적화는 핵심 게임 골격이 안정된 뒤 진행한다.

## 승인된 UI 전면 재설계

기존 내부 기능과 화면의 괴리를 해소하기 위해 정보 구조·내비게이션·각 도메인 화면을 구단 운영 흐름 중심으로 전면 재설계한다. [DEVELOPMENT.md의 12.3–12.5](DEVELOPMENT.md#ui-전면-재설계--승인된-현재-범위)가 현재 작업 기준이다. 엔진/공유 명령, 직접 운영 기본값, 의미 있는 선택, 권한 및 저장·게임 기록 호환성은 유지한다. 현재 상태 → 가능한 행동과 조건 → 실행 → 결과와 이유 → 저장·재접속까지 연결되어야 화면 교체 완료다. 미구현 화면이나 장식용 제어를 완료로 제시하지 않는다. 집중 UI 검사는 진행하되 최종 장기/기기/TalkBack QA의 선행 조건은 그대로 유지한다.

## 1. 핵심 철학

목표: LoL 프로씬 전체를 장기간 시뮬레이션하는 Football Manager형 경영 게임.

제품 방향은 **모바일 퍼스트 웹 게임**이다. 현재 단계에서는 로컬 실행 가능한 핵심 게임을 우선 완성하되, UI/라우팅/데이터 구조는 이후 외부 URL 배포와 서버 저장 구조로 확장하기 어렵지 않게 설계한다.

핵심 순환:
`선수/챔피언/전술/팀워크/폼 → 밴픽/경기 → 실제 통계 → 평가/메타/명성/가치 → 패치/영입/육성/재정 → 다음 경기`

- 원인 데이터와 파생 데이터를 분리한다. 티어/팀전력/메타 등은 가능한 한 실제 데이터에서 파생.
- 모든 주요 수치는 실제 엔진에서 사용. 장식용 수치 금지.
- 모든 값을 0~100으로 강제하지 않는다. %, 금액, 계수, 횟수 등 적절한 단위 사용.
- 내부 계산은 정밀하게, UI는 읽기 쉽게.
- 깊이는 옵션 개수가 아니라 시스템 상호작용에서 만든다.
- 플레이어 팀만이 아니라 모든 활성 AI 팀/리그가 같은 세계에서 진행된다.
- 장기 세이브에서 현실 초기 상태로부터 독자적인 역사/메타/경제/선수 세대가 형성되어야 한다.

## 2. 새 게임/팀 선택

기본 1부 팀 수:
- LCK 12
- LPL 16
- LCP 12
- LEC 12
- LCS 10
- LSA 10

팀 수/규정은 데이터 기반으로 두고 새 게임에서 임의 팀 수 입력은 제거한다.

첫 시즌 시작 방식:
- 모든 활성 구단은 선수 0명의 백지 로스터로 시작한다.
- 기존에 생성된 선수는 삭제하지 않고 전원 글로벌 FA 풀로 이동하며 기존 계약은 제거한다.
- 독립 구단 감독은 팀 선택 후 FA 풀에서 1군과, 보유 시 산하 2군 로스터를 직접 구성한다. 소유 2군 감독 시작은 모구단 AI가 같은 시장/등록 규칙으로 선수단을 구성한다.
- 독립 구단은 플레이어 조직 등록 이후 AI가 남은 FA 풀에서 전 세계 로스터를 구성한다. 소유 2군 시작은 모든 구단의 AI 구성을 먼저 끝내고 배정된 선수단을 확인한다.
- 필수 포지션, 1군/2군/통합 로스터 인원, 외국인 규정, 연봉 예산, 샐러리캡/플로어를 충족하기 전에는 시즌을 개막할 수 없다.
- 첫 시즌 흐름은 `세계 생성 → 팀 선택 → 글로벌 FA 로스터 구성 → 등록 마감 → 시즌 개막`으로 고정한다.

팀 선택:
- 1부 독립 구단: 가능.
- 2부 독립 구단: 가능.
- 1부 구단 소속 2군/Academy: 감독 선택 가능. 모구단이 선수단을 구성하고 선수 영입·계약·방출·1·2군 이동을 담당한다. 플레이어는 배정된 선수의 경기·밴픽·전술·훈련·육성을 관리한다. (2026-10-01 사용자 변경)
- 강등/승격한 독립 구단은 해당 디비전에서도 플레이 지속 가능.

선택 UI는 `지역 → 리그 → 디비전 → 팀` 구조로 하고 1부/2부, 독립/2군, 프랜차이즈/인증, 승격·강등 가능 여부를 명확히 표시한다. 팀 카드에는 재정, 선수단, 시설, 명성, 최근 성적, 구단 목표 등 실제 상태를 보여준다.

## 3. 팀 이름/브랜딩

가상 팀 이름을 전면 검토한다.
- 자동생성/촌스러운 이름 최소화.
- 짧고 기억하기 쉬운 현대적 e스포츠 브랜드 지향.
- `지역명+Gaming/Esports`, Dragon/Phoenix/Titan류 상투어 남발 금지.
- 자연스러운 2~4자 약칭.
- 동일 지역 유사명/중복명 방지.
- 독립 2부팀도 독자 브랜드 보유.
- 1부 소속 2군은 모구단과 관계가 명확한 `Academy/Challengers` 계열 규칙 사용.
- 승격해도 독립팀 브랜드 유지.

## 4. 선수

선수는 독립적인 커리어 엔티티다.

기본:
- 이름, 나이, 국적, 주/부 포지션, 소속, 1/2군, 계약, 연봉, 시장가치, 명성.
- 능력 예: 라인전, 교전, 한타, 포지셔닝, 딜링, 생존, 시야, 오브젝트 판단, 로밍, 운영, 사이드, 판단, 안정성, 공격성, 집중력, 적응력, 기복, 챔피언 학습/메타 적응.
- 포지션별 중요도/평가식을 다르게 한다.
- 폼, 컨디션, 피로, 사기, 경기 감각, 팀/전술 적응은 기본 실력을 압도하지 않는 범위에서 사용.

챔피언 숙련:
- 선수×챔피언별 실제 숙련도.
- 공식전, 스크림, 훈련, 기존 경험, 선수 특성, 챔피언 난이도에 따라 변화.
- 급성장 금지. 장기 미사용/대규모 리워크 시 일부 재적응 가능.

경기 기록:
- K/D/A, KDA, KP, CS, CS차, 골드, 골드차, GPM, 딜/DPM, 받은 피해, 시야, 오브젝트 관여, 라인 우위, 한타 기여, 평점 등 엔진이 실제 생성 가능한 데이터.
- 포지션별 평점 공식을 다르게 한다.

성장:
- 나이, 잠재력, 출전, 경쟁 수준, 훈련, 스크림, 코칭, 시설, 성장 성향, 현재 수준을 반영.
- 잠재력은 확정 미래치가 아니며 환경에 따라 도달점이 달라진다.
- 성장곡선/전성기/쇠퇴 시점은 선수별 차이 허용.
- 신규→성장→전성기→쇠퇴→은퇴의 완전한 생애주기.
- 제한적인 포지션 전환/부포지션 습득 지원.

커리어:
- 시즌별 팀/디비전/출전/통계/계약/이적/우승/국제전/개인상 저장.
- MVP, 결승 MVP, 포지션 베스트, 신인상, 국제대회 MVP 등은 실제 성과 기반.
- 명성은 능력과 분리하며 성과/우승/국제전/수상/커리어에서 파생.

## 5. 선수 역할/만족도

계약/로스터 역할: 핵심 주전, 주전, 경쟁, 후보, 유망주 등.

예상 출전시간과 실제 기용 차이가 장기간 크면 만족도/재계약/이적 의사에 영향.

불만 원인 후보:
- 출전 부족, 2군 이동, 계약, 팀 성적, 역할, 국제대회 기회, 커리어 목표.

불만은 과도하게 발생하거나 경기력을 즉시 붕괴시키지 않는다. 이적 요청/철회 가능.

## 6. 신인/스카우팅

장기 세이브용 신규 선수 생성:
- 지역/포지션별 자연스러운 공급.
- 평범→준수→좋은 유망주→희귀 특급의 분포.
- 매년 엘리트 과잉 생성 금지.
- 이름/국적/나이/능력/잠재력/챔피언 풀/성향 생성.
- 일반 경로: `신인 → 2부/Academy → 경기 → 성장 → 스카우팅 → 1부`.

스카우팅:
- 실제 능력/잠재력을 처음부터 완전 공개하지 않는다.
- 어린/해외/2부/저표본 선수일수록 불확실성 증가.
- 관찰로 추정 범위가 좁아진다. 잠재력은 끝까지 일부 불확실성 유지.
- 지역/선수/대회/포지션/계약상태/저평가 유망주 검색.
- 보고서는 추정 능력 + 실제 경기 데이터 + 성장 추세 + 챔피언 풀을 함께 분석.
- 오래된 보고서는 신뢰도 감소 가능.

## 7. 계약/이적시장

계약:
- 현실적인 기간.
- 기본 연봉, 계약금, 성과/우승/국제전 보너스, 바이아웃, 팀/선수 옵션 등 필요한 조항 지원.
- 모든 계약에 모든 조항을 강제하지 않는다.

시장가치:
`나이+능력+잠재력 추정+폼+최근 성과+계약잔여+포지션+국제전+명성+수요+리그경제`
에서 파생. 시장가치≠실제 이적료.

경쟁 시장:
- 플레이어/AI 모두 같은 선수에게 경쟁 가능.
- 관심→관찰→내부평가→공식제안→협상 흐름.
- FA/계약만료/유망주/국제전 활약 선수는 경쟁 증가 가능.
- 선수는 최고 연봉만 보지 않고 출전시간, 팀/리그 명성, 국제전 가능성, 코칭/시설, 로스터, 커리어 단계, 계약조건을 비교.
- 다른 팀의 정확한 제안은 항상 공개하지 않는다.
- 협상 지연 중 경쟁팀에 선수를 빼앗길 수 있다.
- 자기 팀 선수도 자동 재계약 불가.
- 관심목록/쇼트리스트/영입 후보 A-B-C 지원.
- AI는 1순위 실패 시 합리적인 대안으로 이동.
- AI끼리도 이적/FA/재계약/방출 발생.
- 연쇄 이적시장 가능.
- 임대 기간은 반시즌/한 시즌으로 제한하고 조기복귀는 계약상 리콜 조항이 있을 때만 허용한다.
- 임대료 0원, 연봉 0~100% 분담, 완전이적 옵션/의무 조항을 지원한다.
- 임대 출발은 시즌 이적 2회 제한에서 1회를 사용하며 복귀는 추가 이적으로 세지 않는다.
- 상호 계약 해지는 오프시즌에만 가능하고, 구단 일방 방출은 계약별 보장액/보장비율에 따라 정산한다.
- 선수 불만은 이적요청보다 관계 악화와 재계약 의향 하락을 중심으로 작동하며, 명시적 이적 희망은 심각한 불화에서만 드물게 발생한다.
- 시즌 최종 국제대회 종료 후 14일은 현 소속팀 독점 재계약 협상 기간이고, 15일째부터 타 구단 접촉/협상을 허용한다.

## 8. 2부/2군

모든 주요 지역에 실제 2부 생태계를 둔다.

2026-10-04 사용자 확정 표기: 1부는 L로 시작하는 3글자 약칭을 유지하고,
2부는 지역별 3글자 약칭을 사용한다. 새 게임 기본 구성은 다음과 같다.

| 지역 | 1부 | 2부 |
| --- | --- | --- |
| 한국 | LCK | LKC |
| 중국 | LPL | LDL |
| 유럽 | LEC | LEA |
| 북미 | LCS | LNA |
| 아시아태평양 | LCP | LPA |
| 남미 | LSA | LSC |

LCK/LPL/LEC/LCS/LCP와 LDL은 익숙한 대회 약칭을 유지한다. LSA 및 새 2부 약칭은
게임의 가상 표기이며 실제 대회 규정이나 현재 실존 대회 이름을 주장하지 않는다.
남미는 브라질만이 아닌 통합 남미 생태계이고, 기존 라틴아메리카 확장 지역은
북미 산하의 중미·카리브(LCA, 하부 LAC)로 분리한다. 국적 구현은 아직
국가별 목록이 아닌 출신/로컬 지역 코드 기반이다. BR/LA 키는 저장 호환성을 위해
유지하며, 구단/선수의 새 게임 생성·스카우팅·로컬 자격은 이 지역 단위를 따른다.
주요 지역과 앞으로 출범하는 추가 리그는 2부를 필수 운영한다. 신설 시 1·2부를
함께 생성하며 사무국은 필수 2부만 폐지할 수 없다. 새 가상 리그도 중복 없는
L 시작 3글자 1·2부 약칭을 배정한다. 과거 저장의 선택적 2부 설정은 소급 강제하지 않는다.

추가 확정 방향: 통합 지역의 1부는 공동 운영하고 2부는 국가별로 편성한다.
구단 연고국·2군 육성/운영국·하부 리그 참가국을 별도로 명시하고 공식 경기·순위·영입·육성에 연결한다.
이 국가별 편성은 아직 구현 전이며 현재 지역 단위 2부를 완성으로 간주하지 않는다.
국가별 하부 편성 자체가 통합 권역 로컬 자격이나 국제 슬롯을 자동 분리하지 않는다.

기존 저장은 브라질/LLA의 지리와 구단/자격/대회 ID를 자동으로 재배치하지 않는다.
명칭 정리는 실제 경기·성적 기록을 지우거나 과거 지역 귀속을 바꾸지 않는다.

- 1부 소속 2군/Academy + 독립 2부 구단 혼재 가능.
- 2부는 실제 일정/경기/순위/통계/밴픽/성장/이적을 시뮬레이션.
- 2부 경기 수준을 고려하여 1부 통계와 동일 가치로 평가하지 않는다.
- 독립팀은 규정상 승격 가능, 2군은 일반적으로 모구단과 같은 1부에 승격 불가.
- 2부 국제대회 지원. EMEA Masters는 2부 국제대회 계층.

2군 의무:
- 프랜차이즈팀: 필수.
- 혼합제 인증팀: 필수.
- 혼합제 비인증팀: 선택.
- 일반 승강제팀: 선택.
- 의무 여부는 리그명이 아니라 라이선스/규정 데이터에서 파생.

선택 운영 AI는 재정, 유망주, 시설, 로스터, 육성 전략, 비용을 보고 판단. 2군에는 연봉/스태프/시설/운영비가 들고 공식 경기 경험/육성/로스터 안정 등의 이익이 있다.

1군↔2군 이동은 등록 규정으로 무제한 악용을 막는다.

승격/강등 시 라이선스, 재정, 스폰서, 선수 선호도, 2군 의무 등이 새 규정에 맞게 변경될 수 있다.

## 9. 구단/시설/스태프

팀 전력은 단일 숫자가 아니라 선수/팀워크/전술/코칭/폼에서 파생:
- 초/중/후반, 라인전, 교전, 한타, 운영, 오브젝트, 시야, 사이드, 밴픽, 팀워크, 메타 적응, 안정성 등.

팀워크:
- 전체 호흡, 포지션/선수간 시너지, 로스터 경험, 전술/조합 숙련.
- 로스터 대변경 시 즉시 완벽한 팀 금지.

시설:
- 훈련, 선수육성, 데이터 분석, 스카우팅 등 서로 실제 효과가 다른 것만.
- 투자비/유지비/업그레이드 기간/효과.
- 시설은 성장 효율과 선수의 팀 매력도에도 영향.

스태프는 감독(사용자)/코칭팀/분석팀/스카우팅팀으로 분리한다.
- 사용자 자신이 감독이며 별도의 범용 수석코치 슬롯은 두지 않는다.
- 코칭팀은 최대 9명까지 고용 가능하다. 전략/육성/퍼포먼스 코치와 TOP/JGL/MID/ADC/SUP 포지션 코치를 조합할 수 있다.
- 분석팀은 코치 슬롯과 분리하며 최대 4명까지 고용 가능하다.
- 스카우팅팀은 별도 부서로 최대 6명까지 고용 가능하다.
- 구단 고용 상한과 대회 현장 등록 상한은 별개다. 지역/국제 사무국은 대회별 스태프 등록/현장 인원을 별도로 제한할 수 있다.
- 밴픽, 전술, 육성, 메타/상대 분석, 선수관리, 데이터 활용 등 실제 시스템에 영향.
- AI 스태프도 계약/이동/해임 가능.
- 감독 교체 시 팀 운영 방향이 변할 수 있다.
- 기존 `team.coach`는 즉시 삭제하지 않고 전문 스태프 속성으로 기능을 이관한 뒤 제거한다.

구단 목표: 우승/플레이오프/국제전/잔류/승격/재정안정/육성 등 현재 상황에 맞게 설정.

핵심은 `강도`가 아니라 제한된 훈련 자원을 어디에 배분하는가다.

후보:
- 개인 성장
- 챔피언 숙련
- 팀워크
- 밴픽
- 라인전
- 교전
- 한타
- 운영
- 오브젝트
- 전술
- 조합

훈련 포인트/시간은 희소 자원. 모든 항목 최대치 불가.

독립적인 훈련강도가 단순 `성장↑ 피로↑`만 만든다면 제거/통합한다.

## 11. 스크림

친선전 시스템은 삭제하고 비공식 연습경기를 스크림으로 통합.

스크림:
- 실제 팀 선택→요청→AI 수락/거절→일정→세트→로스터/밴픽/전술/조합 테스트.
- 약팀/균형/강팀 추상 선택 제거.
- 공식 통계와 완전 분리하되 내부 분석/숙련/준비에는 사용.
- AI도 요청 가능.
- 일정/공식전/휴식/상대 의사/관계/수준 등을 고려.

지역 간 스크림:
- 다른 리그 팀과도 가능.
- 평상시는 거리/일정/환경을 고려.
- 국제대회 개최지에 여러 지역 팀이 모이면 해외 스크림 접근성이 크게 증가.
- 해외 메타 학습/조합 준비에 활용.
- 스크림 결과/비장의 조합은 외부에 자동 공개되지 않는다.

기본 스펙(해당되는 값):

패시브/Q/W/E/R을 별도 스킬 데이터로 관리:
- 설명

- 피해 유형

## 13. 챔피언 통계/메타

상세 통계:
- 픽/밴 횟수, 픽률, 밴률, 밴픽률, W/L, 승률, 표본.
- 시즌/Split/대회/국내·국제/리그/패치/기간/포지션 필터.
- 주요 선수/팀/맞대결/최근 추세.

`밴픽률 = (픽 경기 + 밴 경기) / 전체 경기 × 100`

티어는 고정 속성이 아니라 현재 스펙, 패치, 실제 픽밴/승률/표본, 상성, 포지션, 조합/지역 메타에서 파생한다.

초기 메타는 현실 프로씬을 어느 정도 반영하되 시작 이후 게임 내부 데이터로 독립 진화.

지역별 메타 허용:
- 같은 패치에서도 지역별 우선픽/조합이 다를 수 있다.
- 성공적인 비주류 픽/조합은 `등장→성공→분석→확산→카운터 연구`를 통해 다른 팀/지역으로 전파될 수 있다.
- 국제대회에서 지역 메타가 충돌하고 대회 중 메타가 변할 수 있다.

## 14. 신규 챔피언/글로벌 밴

신챔 출시 즉시 프로 공식전 사용 금지.

흐름:
`출시 → 글로벌 프로 밴 → 훈련/스크림 연구 → proEligibleDate → 공식전 해금`

- 글로벌 밴 중 훈련/스크림 사용 가능.
- 공식 데이터가 없으므로 초기 프로 평가에 불확실성 존재.
- 팀별 사전 연습량에 따라 해금 직후 숙련도 차이 발생.
- 글로벌 해금과 특정 대회 사용 가능 여부는 분리.
- 이미 특정 패치/챔피언 풀로 시작된 대회는 해금 후에도 사용 불가할 수 있다.
- 신규 챔피언 출시 빈도는 낮게 유지해 장기 세이브 챔피언 폭증 방지.
- 매우 드문 리워크 지원 가능.

## 15. 패치 엔진

패치 엔진은 실제 누적 데이터를 분석:
- 픽/밴/밴픽률/승률/표본
- 포지션/리그/국제전
- 최근 추세
- 직전 패치
- 상위팀 사용
- 선수/조합 의존
- flex 여부 등.

승률만 보고 패치 금지. 모든 챔피언을 50%로 수렴시키지 않는다.

원인 진단:
`왜 강/약한가 → 관련 스펙은 무엇인가 → 변경 종류/폭 결정`

변경 가능:
- 기본/성장 스탯
- 피해
- AP/AD/HP 계수
- 자원/회복/비용
- 쿨다운
- 회복/보호막
- 이동/CC 등.

고정 ±5 금지. micro/small/medium/large 등의 내부 규모는 가능하나 실제 수치를 변경한다.

동일 방향 연속 패치를 억제하고 충분한 표본을 관찰. 부분 롤백 가능. 패치 결과는 불확실하며 메타 상호작용으로 예상과 다를 수 있다.

연 3회의 주요 메타 패치를 기본으로 하고 소규모 조정은 별도 가능.

패치노트는 정확한 old→new 수치를 표시. 과거 스펙/패치 히스토리 보존.

## 16. 밴픽/조합

AI와 플레이어 모두 단순 챔피언 티어순 픽을 하지 않는다.

픽 판단:
- 현재 패치/메타
- 선수별 실제 숙련도/챔피언 풀
- 이미 고른 아군 챔피언
- 상대 픽
- 라인 상성
- 조합 시너지
- 전술
- flex
- 픽 순서
- 상대 선수 챔피언 풀/최근 데이터.

조합 요소(실제 엔진에 필요한 것만):
- 이니시/받아치기
- 한타/포킹/다이브
- 사이드/스플릿
- 초반 주도권/후반 성장
- 라인 우선권
- 오브젝트
- CC
- AD/AP 구조
- 앞라인
- 캐리 보호
- 사거리/기동성.

모든 5챔 조합을 하드코딩하지 말고 챔피언 속성/스킬/역할 기반으로 동적 시너지 평가.

밴 목적:
- OP 제거
- 상대 핵심 선수 견제
- 우리 조합 카운터 제거
- 챔피언 풀 압박
- 준비 조합 보호
- 상대 예상 조합 차단.

Flex는 상대 AI가 숨은 포지션을 치팅으로 알지 못하게 한다.

픽 순서는 우선픽 확보/정보 숨김/카운터픽/플렉스에 전략적 의미를 가진다.

고정 `블루 선호 80` 같은 수치는 제거. 블루/레드 가치는 패치, 메타, 선수 풀, 상대, 밴픽 전략에서 파생.

## 17. Bo3/Bo5/Fearless

세트 간 정보가 이어진다:
`이전 세트 결과/픽/실패 원인 → 다음 세트 밴픽/전술 조정`

AI는:
- 성공 조합 재사용
- 실패 조합 수정
- 상대 핵심픽 밴
- 카운터 준비
- 선수 상태/진영 변화
등을 고려.

Fearless는 모든 공식 시리즈에 적용되는 고정 경기 시스템으로 취급하며 지역/국제 사무국이 켜고 끄는 정책 토글로 두지 않는다.

Fearless에서는 실제 사용 챔피언 기록과 선수별 챔피언 풀이 후반 세트에 영향을 준다.

## 18. 전술

플레이어는 자기 팀 전술만 수정. 타 팀은 관찰/분석만.

전술은 trade-off:
- 공격성↔안정성
- 초반↔후반
- 교전↔운영
- 자원집중↔분산
- 오브젝트↔라인/사이드 등.

모든 수치 100이 최적해가 되면 안 된다.

`탑/미드/바텀 집중` 같은 단순 독립 버프는 제거. 정글동선, 로밍, 자원배분, 캐리역할, 드래프트 등에서 실제 자원 집중이 파생.

밴픽 조합과 전술이 맞지 않으면 효율 저하, 잘 맞으면 실행력 향상.

## 19. 경기 엔진

금지: `팀 전력 + 랜덤값 → 승패`.

핵심 요인:
- 선수 능력
- 챔피언 숙련
- 챔피언 실제 스펙/현재 패치
- 조합 시너지
- 밴픽
- 상성
- 전술
- 팀워크
- 폼/컨디션
- 현재 경기 상태
- 제한적 변동성.

가능하면 단계형:
`라인전 → 초반 운영/정글개입 → 오브젝트 → 중반 운영/교전 → 한타 → 후반`

앞선 상태가 다음 상태에 영향을 준다.

팀/선수 골드와 격차, 자원집중, 파워스파이크, 오브젝트 등을 엔진 수준에 맞게 모델링.

강팀도 실제 게임 상태가 나쁘면 패배 가능. 작은 초반 우위 하나로 승패 확정도 금지.

선수 실수는 판단/안정성/피로/상황과 연동한 제한적 변동성으로 처리.

경기 후 라인전/밴픽/전술/선수/오브젝트/한타 등 승부 요인을 설명 가능하게 한다.

## 22. AI 원칙

AI도 플레이어와 같은 핵심 시스템 사용:
- 영입/계약/재계약/방출
- 스카우팅
- 1/2군
- 훈련/육성
- 시설
- 스크림
- 밴픽/전술
- 패치 적응
- 재정
- 국제대회 준비.

팀마다 현재 재정/로스터/목표에 따라 즉시전력, 육성, 효율, 비용절감 등 전략이 달라질 수 있다.

AI는 내부 숨은 잠재력, 플레이어의 비공개 스크림 조합 등을 치팅으로 알지 못한다.

항상 최적해를 아는 AI도, 랜덤으로 바보짓하는 AI도 금지. 제한된 정보/분석력 때문에 합리적이지만 틀린 판단은 가능.

AI는 중기 로스터 계획과 대체 후보를 유지하고 매년 무조건 전원 교체하지 않는다.

플레이어를 특별 취급하지 않는다.

### 전 지역 규정 구현 원칙

- 어떤 규정 기능도 LCK 한 지역 전용 구현으로 완료 처리하지 않는다.
- 로스터, 계약, 코칭스태프 등록, 로컬/비로컬 자격, 샐러리, 1/2군, 승강, 국내 대회 포맷, 일정, 라이선스 등 **사무국 소유 규정 기능은 모든 활성 지역 리그가 자기 정책 값을 가질 수 있어야 한다.** Fearless와 First Selection은 사무국 정책이 아니라 고정 경기 시스템이다.
- 실제 규정을 확인한 지역은 해당 지역의 초기 규정/프리셋으로 반영한다. 확인되지 않은 항목은 LCK나 다른 지역 값을 복사하지 않고, 그 지역의 기존 구조와 사무국 정책 엔진이 독립적으로 결정하거나 현 상태를 유지한다.
- 지역별 차이는 데이터/정책으로 표현하고, 핵심 엔진에 `region === KR` 같은 지역명 전용 분기를 최종 해결책으로 남기지 않는다.
- 새 규정 시스템의 완료 조건에는 최소한 **복수 지역에서 서로 다른 규정값으로 정상 동작하는지**, 사용자 구단과 AI 구단이 같은 규정을 따르는지 검증하는 회귀 테스트가 포함된다.
- 사용자 구단과 AI 구단은 같은 등록/계약/이적/스태프/대회 규칙과 같은 상태 전이 절차를 사용한다. 차이는 최종 의사결정자가 사용자냐 각 구단 AI냐뿐이다.
- 각 구단 AI는 완벽한 최적화기가 아니다. 동일한 규칙 아래 제한된 정보, 스카우팅 정확도, 재정, 목표, 구단 철학, 스태프 능력에 따라 합리적이지만 틀린 결정을 내릴 수 있다.
- 국제대회 규정은 지역 사무국 값을 임의 상속하지 않고 국제 사무국이 별도로 결정한다.

담당:
- 참가팀/라이선스
- 프랜차이즈/인증
- 1/2부 및 승강
- 2군 의무
- 로스터 등록/마감
- 외국인 규정
- 샐러리 규정
- 수익 배분/상금
- 국내 일정
- 정규리그/플레이오프 포맷
- 국내 로스터/등록 기간 및 등록 교체 규칙
- 로컬 취득 자격의 지역측 제안/운영
- 사용 패치

## 29A. 게임 시간 진행

세계 전체는 하나의 게임 날짜/시간축을 공유한다.

- `하루 진행`, `다음 주요 일정까지 진행` 등 명확한 진행 기능 제공.
- 진행 시 모든 활성 리그, 계약, 훈련, 스크림, 시설, 대회, AI 의사결정이 함께 처리된다.
- 로스터 마감, 계약 협상, 공식 경기, 중요한 제안 등 플레이어의 필수 결정이 있으면 자동 진행을 중단할 수 있다.
- 시즌은 메뉴 전환으로 초기화되는 구조가 아니라 연속된 세계 시간이다.
- 새 시즌에도 선수 능력/숙련, 팀워크, 재정, 명성, 시설, 계약, 역사 등 지속 데이터는 유지한다. 시즌성 폼 등 필요한 단기 상태만 규칙에 따라 조정한다.

## 29B. 로스터 등록

- 공식 1군 등록은 최소 5명, 최대 10명이며 10명 상한은 계약 보유 인원이 아니라 공식 등록 명단에만 적용한다.
- 공식 등록 명단은 주포지션 5종 보유를 강제하지 않는다. 등록 선수 5명을 TOP/JGL/MID/ADC/SUP 경기 슬롯에 자유롭게 배치할 수 있으며 한 선수의 중복 배치만 금지한다. `p.role`은 전문 역할 표시이지 출전 자격이 아니고 일반 부포지션 자격 시스템은 두지 않는다. 장기 전향은 감독이 제안하고 선수는 수락/거절할 수 있으며, 남발은 하드 제한이 아니라 훈련 기회비용·적응 손실·관계 영향으로 억제한다.
- 한 선수는 같은 시점에 하나의 공식 로스터에만 등록할 수 있다. 임대 선수의 공식 등록은 임대받은 구단만 가질 수 있다.
- 비로컬 최대 2명 제한은 1군 공식 등록 명단에 적용한다.
- 1군/2군 등록, 대회별 엔트리, 등록 마감일을 규정 엔진과 연결한다.
- 국내 공식 등록 가능 기간/마감일은 각 지역 사무국이 정한다. 기간이 열려 있으면 횟수 제한 없이 명단을 변경할 수 있고, 닫히면 일반 변경은 불가능하다.
- 별도의 '등록 교체 횟수' 카운터는 두지 않는다. 시즌 최초 로스터 제출도 교체로 계산하지 않는다.
- 1군↔2군/Academy 내부 승강은 공식 등록과 별도이며, 각 지역 사무국이 공식 등록 기간보다 넓은 내부 이동 가능 기간을 정한다. 이 기간 안에서는 내부 승강 횟수 제한이 없다.
- 등록 기간이 닫혀 있어도 내부 이동 기간이 열려 있으면 소속 이동은 가능하지만, 공식전 출전 자격은 기존 공식 등록 명단을 유지한다.
- 2군/Academy 공식 로스터는 최소 5명이며 주포지션 5종 보유를 등록 요건으로 강제하지 않는다. 경기 때 등록 선수 5명을 다섯 슬롯에 배치한다. 최대 인원과 비로컬 제한은 각 지역 사무국이 별도로 정한다.
- 1군 선수가 2군/Academy 공식전에 출전하려면 내부 이동 기간과 해당 대회의 등록 기간을 모두 충족해야 하며, 재승강 대기기간은 지역 사무국이 정한다.
- 국제대회 진행 중에는 1군↔2군/Academy 내부 승강도 잠근다.
- 국제대회는 시작 전 제출한 최종 명단을 대회 종료까지 고정하고 일반적인 중간 교체/재등록을 허용하지 않는다.
- 긴급 등록/대체는 해당 리그·대회 사무국의 사전 공표 규칙이 허용할 때만 가능하며, 이 예외에서 기존 선수를 빼야 하는지 또는 일시적 10명 초과를 허용할지도 해당 긴급 대체 규칙이 정한다.
- 같은 공식 명단 안의 선발/후보 교체 및 Bo3/Bo5 게임 사이 선수 교체에는 별도 횟수 제한을 두지 않는다. 한 게임이 시작된 뒤에는 선수 교체가 불가능하다. 별도 축소 경기 엔트리는 제출하지 않고 공식 등록 선수 전원을 사용할 수 있다.
- AI 역시 동일한 등록/내부 이동 규칙을 따른다.
- 로컬 자격/이적/FA/등록의 상세 확정 규칙은 `docs/ROSTER_TRANSFER_LOCAL_RULES.md`를 따른다.
- 비출신지역 로컬을 시즌 중 취득해도 활성화는 다음 시즌부터 가능하다.
- 계약 중 구단 간 이동은 시즌 단위 최대 2회이며 임대 출발도 1회로 계산한다. 임대 복귀와 FA 계약은 이 횟수에 포함하지 않는다.

## 35A. 동일 규칙/데이터 구조 원칙

AI와 플레이어는 계산 표시 방식만 다를 수 있으며 핵심 규칙은 동일해야 한다.

모든 활성 지역 리그에도 동일한 원칙을 적용한다. 한 지역에서 추가된 규정 기능은 다른 지역에서 비활성/다른 값/다른 구조를 선택할 수는 있어도, 규정 엔진 자체가 특정 지역만 지원해서는 안 된다.

AI가 다음을 우회하지 못하게 한다:
- 예산/현금/연봉/샐러리 규정
- 계약/이적 조건
- 로스터 등록
- 1군/2군 이동 규정
- 시설 투자비/운영비
- 훈련/숙련도 획득
- 선수 성장/노화
- 챔피언 글로벌 밴/대회 사용 제한.

팀, 선수, 챔피언 스펙, 리그, 대회, 패치/규정 등 변경 가능성이 높은 게임 데이터는 가능한 한 코드 로직과 분리된 데이터/config 구조로 관리한다. 새 가상 리그/팀/대회 추가나 규정 변경 때문에 핵심 엔진을 뜯어고치지 않도록 한다.

## 35B. 감독 세이브 지속성

구단에서 해임되는 기능을 구현하더라도 그것만으로 세이브를 강제 종료하지 않는 구조를 전제로 한다. 향후 다른 구단 취임/구직 등 감독 커리어 시스템으로 확장할 수 있도록 플레이어 감독과 구단을 영구적으로 동일 엔티티에 묶지 않는다. 세부 감독 커리어 기능은 핵심 게임 루프 이후 확장 가능하다.

## 36. 장기 밸런스/자동 검증

## 39. 최종 게임 루프

`신인 생성/2부 → 스카우팅 → 영입 → 시설/훈련/스크림 → 성장 → 1군 → 패치/메타 연구 → 조합/밴픽/전술 → 공식 경기 → 실제 통계 → 국내 성적 → 국제대회 → 명성/가치/재정 → 계약/이적/투자 → 다음 시즌`

동시에:

`챔피언 스펙 → 경기 → 픽밴/승률 데이터 → 패치 엔진 → 수치 변경 → 지역별 메타 변화 → 팀별 연구/스크림 → 새로운 조합 → 다음 경기`

그리고:

`팀 성적 → 명성/수익 → 선수·시설·2군 투자 → 로스터/육성 변화 → 전력 변화 → 다음 성적`

이 세 순환이 하나의 세계에서 연결되어야 한다.

작업량이 많다는 이유로 핵심 시스템을 임의 삭제하지 않는다. 한 번에 안전하지 않으면 의존성 순서로 단계 구현하되 본 문서를 최종 목표로 유지한다.
2026-10-04 추가 확인: 통합 1부/국가별 2부 연결에서 승강제 규칙은 리그 사무국이
결정한다. 개발자는 참가 자격·승강 인원·선발전·시행 시점의 데이터와 실제 다음 시즌
편성을 연결하며 임의의 고정 승강 규칙을 대신 확정하지 않는다. 소유 2군은
모구단과 같은 1부로 승격할 수 없다. 국가별 하부 편성과 이 사무국 연결은 후속 10.2 범위다.

구단 연고국과 2군 육성/운영 거점은 별도 선택 값이다. 2군을 모구단 연고국 밖에서
키우는 것을 허용하되, 실제 국가별 하부 리그 참가 자격은 사무국이 심사한다.
훈련장/운영국 변경만으로 선수 국적·출신지역·로컬 자격을 바꾸지 않는다.
이는 후속 10.2의 확정 범위이며 현 버전의 지역 코드만으로 구현 완료를 주장하지 않는다.

국제대회 공식 경기 중계는 전세계 공통 편성에서 서로 겹치지 않아야 한다. 같은
국내 리그의 공식 경기 중계도 동시 진행하지 않는다. 다른 국내 리그끼리는 병행
가능하며, 대회 개최 기간 전체를 분리할 필요는 없다. Eastern Cup과 Western Cup은
동일 위상의 대회로 병행 개최할 수 있다. 개시 시각만 분리하는 것으로는 부족하며
예정 중계 시간과 실제 경기 초과 시간에 따른 순연까지 연결한다(후속 10.3).

국내 기본 공식 명칭은 스플릿 1·스플릿 2·스플릿 3이고 리그 사무국이 이름을
설정하면 해당 지역의 `splitNames`를 사용한다. 이미 저장된 과거 명칭은 보존한다.

## 아마추어 배경과 이야기의 범위

아마추어 생태계는 별도 경기/리그 시뮬레이션 없이 선수 출신·동료·재도전 배경과 사건으로 표현한다. 필요한 인물의 가상 배경과 실제 운영 이력을 보존하고 스카우팅·테스트·영입 경로에 연결한다. 선수 프로필에서 선택적으로 읽고 중요 사건만 짧게 알린다. 가상 배경을 실제 대회 데이터나 계산된 경기 통계로 가장하지 않고 숨은 능력·타 팀 비공개 정보를 공개하지 않는다. 기존 직접 운영, 계약/등록/사무국 권한, 저장/역사 호환성을 유지한다. [개발 작업 3.1](DEVELOPMENT.md#31-아마추어-배경과-선수-이야기--승인된-구현-예정-범위)이 구현/검증 기준이다.
