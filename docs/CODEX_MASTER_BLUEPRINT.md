## 1. 제품/플레이 철학 및 실제 핵심 게임 루프

**플레이어 역할:** 사용자는 구단의 실제 감독(manager)이다. 구단 자체의 소유권·이사회·AI 경제 의사결정과 감독의 경기/계약/선발/전술 권한을 구분한다. 플레이어 외 구단도 같은 시간·정보·대회·계약/예산/선수 가용 규칙에서 운영한다.

**목표 경험:** 모바일에서 짧게 접속해 '오늘 필요한 결정'을 확인하고, 영입·훈련/스크림·공식경기·커리어/구단 운영을 진행하여 스스로 진화하는 세계에서 여러 시즌을 이어가는 싱글플레이. 결정을 '딸깍' 했을 때 실제 게임의 자원·시간·상태가 변하고, 결과의 이유가 나중에 복기 가능해야 한다.

### 1.1 한 시즌의 정식 사용자 여정

1. **새 경력/로드:** 저장 슬롯 선택(현행 소스 10개), 구단/지역/리그·디비전/기본 설정·역할 선택 → 합법 초기 FA 공급/기초 세계 날짜. 미설정/손상/구버전 슬롯을 명확히 구분.
2. **시즌 준비:** 구단 목표/재정·계약 만료/선수단·로컬 자격/의료/2군·스태프/시설/스카우팅 보고서 확인 → 관심 후보와 실제 조건/비용 평가.
3. **이적/협상:** 선수·구단·에이전트에게 정당한 제안, 실제 세계 시간 경과와 AI 경쟁·역제안/거절·마감, 합의 뒤 감독의 명시적 최종 확정 → 실제 정산·소속/등록 및 알림/과거 기록.
4. **육성/스크림:** 제한된 훈련 시간·시설·스태프·파트너 가용과 실제 달력 충돌을 바탕으로 훈련/스크림·휴식·의료 관리. 연습 결과는 공식 순위·상금·경기 공식 기록과 분리.
5. **공식 경기 준비:** 확정된 일정/대회 패치·공개 상대 분석/팀 전술/선발/선수 피로/출전 가능·자격, First Selection 및 Fearless, 감독 수동 결정이 승인 규칙대로 경기 입력을 결정.
6. **경기/세트 진행:** 실제 경기 엔진이 자원/행동·교전/오브젝트·넥서스 판정을 수행하고, 빠른 진행·실황·결과/분석실이 **하나의 공식 사실**을 사용. 시리즈 중 중단/재개/세트별 밴픽/스케줄 점유.
7. **정산/회복:** 경기 승패·대회 포인트/순위·상금/급여, 팀/선수 개별 공식 통계와 경험·피로·부상, 보상/기록/뉴스·패치 적응·다음 일정 연결.
8. **오프시즌/장기 세계:** 이적·계약 종료/재계약·신인 공급/은퇴·승강/라이선스/대회 슬롯·구단 투자/해체, 과거 선수/구단·패치/로스터·우승 기록 불변, 새로운 시즌 준비.
9. **저장/앱 종료/복원:** 어느 이벤트 경계에서나 마지막 **완료 커밋된** 세계를 안전하게 복원. 감독 미결정/시장 대기/중단된 Bo·저장 슬롯/정보 권한의 연속성을 잃지 않음.

각 단계의 모바일 화면은 `현재 상태`, `선택 가능한 행동`, `조건·비용·마감`, `수행 결과/이유`, `다음 할 일`을 같은 단어/실제 사실로 연결한다. 홈 한 화면이 모든 상세 수치를 보여줄 필요는 없지만 사용자가 별도 코드를 알지 않고도 다음 필수 결정에 접근해야 한다.

### 1.2 가장 중요한 실패 여정

- 선수가 합의했지만 최종 서명 직전 예산/시장 마감/로스터 자격/경쟁팀 계약으로 실패: 소속·현금·채무/등록이 반쯤 변경되지 않음. 합의 기록·실패 이유 보존.
- 공식 Bo 진행 중 앱 전환/저장/시리즈 세트 재개: 완료 세트·Fearless 사용/첫 선택권·실제 일정 점유·상금/통계가 두 번 처리되지 않음.
- 스크림 Bo1을 열어본 뒤 결과 화면을 다시 열기: 최초 실제 1회 시뮬레이션의 동일 결과·단 한 번의 훈련 소비·피로/선수 이력 유지.
- 저장 슬롯 A가 느리게 쓰는 동안 B를 열거나 새 세계를 생성: A의 오래된 연산/화면/UI가 B의 게임 데이터·최근 슬롯 메타를 덮지 않음.
- 선수 이적/은퇴·구단 해체/사명 변경/리그 개편 뒤 10시즌 전 경기 열람: 당시 팀·선수·패치/상금·로스터로 저장된 공식 역사를 표시, 현재 상태로 재생해 덮어쓰지 않음.
- 타 구단 비공개 의료·실능력/잠재력·비공식 스크림·미래 계약을 사용자/AI가 합법 관측 전부터 참조하지 않음.

## 2. 전역 아키텍처 계약 — 한 세계, 한 사실, 여러 화면

현재 실제 소스는 `scripts/artifact-modules.mjs`가 나열한 **엔진 102 + UI 70 = 총 172**개의 dependency-free JavaScript 모듈과 standalone HTML 빌드. 파일 목록이 있다는 것이 전체 C안 구현 완료의 증거는 아니다.

### 2.2 모든 명령의 구현 인터페이스

새로운 도메인 명령을 구현할 때 기존 command/state-transaction 패턴에 적합한 방법으로 다음 의미를 반드시 충족한다. **별도 새로운 공용 프레임워크를 무조건 만들지 말 것.**

1. **입력:** actor ID(감독·AI·시스템), 소유 팀/선수·경기·협상 ID, 예상 세계 버전/시각, 사용자 명령/확정 범위.
2. **권한/적법성:** 관리 팀의 직접/위임 권한, 계약·선수/로컬/대회 등록, 의료 가용성, 합법 관측·시장·재정 조건, 작업 중단 조건.
3. **예약과 원가:** 세계 시간/자원/스태프/훈련·게임 내 골드/재정 비용이 실제로 발생하는 순간과 선지급/계약 채무를 분리.
4. **전환:** `state-transaction.js`/`state-rollback.js` 등 기존 원자성·배타성 방법을 재사용. 동일 명령 ID/시간 이벤트 이중 실행 방지·다른 정상 구단 상태 보존.
5. **출력:** 성공/거절/미결/오류의 의미와 적용된 변동 범위·적법 거절 이유·사용자가 할 수 있는 다음 행동. 결과를 화면에서 새로 추정하지 않는다.
6. **증거:** 사건 시각/당시 선수·팀·패치/계약/밴픽, 관련 계산 근거·공개/내부 관측, 시드/엔진 버전(필요 시)을 가용성에 맞게 보존.
7. **확인:** 각 consumer의 실제 효과·UI가 결과를 재읽는지, save/load/취소·rollback·중복/경쟁 입력 후 동일 상태인지 집중 시험.

## 4. 게임 전 분야 16개 상세 작업 묶음

### D01. 새 게임·튜토리얼·첫 경기
- 필수: 구단/지역·감독 역할, 새 세계/기존10 슬롯·초기 FA·1/2군/의료·합법 등록, 첫 선발·대회/스크림 가능 상태 표시.
- 원인/결과: 초기 팀 생성·지역 로컬/선수 수/예산 → 초기 계약·선발 → 현재 세계 날짜/첫 공식 경기 예약.
- UX: 지금 할 일·왜 출전 불가능한지·결정 전 예상 비용/외국인 슬롯을 탭/카드로 읽기.
- 반례: 빈 후보·감독 무직/해임·동명이인·구형 슬롯/손상 파일·0명 팀·이름/계약/FA 생성 충돌.
- 완료: 최초 설치→합법 경기→저장→같은 상태 재개를 320px UI로 확인. 소유 코드/테스트 [A1](CODEX_DOMAIN_A_CLUB.md), [C1](CODEX_DOMAIN_C_UI_QA.md).

### D02. 선수·육성·훈련·코칭/의료·선발
- 필수: 역할/챔피언 숙련·선수간 호흡·개별 성장 기회, 피로/부상/재활·실제 역할 약속과 선수 만족도/계약·관계/경력.
- 원인/결과: 활동 시간/코치·시설·선수 심리/출전 → 세부 능력·피로/결장·전술 적응 → 경기 개별 행동/평가/역사.
- UX: 관측 추정/실제 팀 내부 정보 구분, 주전·후보/2군·의료·훈련 부담과 실행 가능 일자/비용.
- 반례: 같은 시각 공식 경기+스크림/훈련, 결장 선수 선택, 의료 tick 중복, 2군 이동 뒤 기존 코치 자동 조작, 닉네임 충돌/동일 ID 분리.
- 완료: 선수별 세부 결과를 실제 경기/연습 소비자가 읽고 장기 저장 복원 후에도 연결. [A2–A4/A10](CODEX_DOMAIN_A_CLUB.md).

### D03. FA·이적시장·계약·대표자
- 필수: 관심→조사→제안/조건→응답 대기·역제안/경쟁·철회·가계약/합의→최종 감독 확인→실제 소속/지급/등록/경력 변경.
- 원인/결과: 시장/응답 시간·각 당사자 의향/정보·재정·선수 역할 조건→현재 합법 서명, AI도 같은 자금/시간 제약.
- UX: 하단 시트/전체화면 상세와 여러 협상 상태, 다음 연락 예정시각·현재 결정권자/다음 행동·실패 이유/예산·선수 등록 가능성.
- 반례: 마감 직전 합의, 선수가 타 구단 최종 서명, 구단 파산·선수 부상, 선수/구단 대표자가 답변 순서 변경, 중복 제출/시간 스킵·저장/복원.
- 완료: 기본 2–8h/경쟁 24–72h·조건부 즉시 응답과 감독 직접 서명 규칙을 실제 세계 시계/계약/돈·UI에서 동시에 입증. [A6](CODEX_DOMAIN_A_CLUB.md), #224·#225·#234.

### D04. 임대·1/2군·로컬/등록
- 필수: 임대 원소속/실사용 소속·급여 분담/수수료·리콜/매입 의무와 옵션/출전 약속, 로컬/외국인·대회 등록·1군/2군 지도·국가별 2부 경계.
- 원인/결과: 선수 이동 사건→양 구단의 합법 권한/예산·출전/성장·다음 등록에 실제 반영.
- UX: 본 구단/임대 구단과 옵션 조건·만료·동작할 버튼/재등록 가능 여부 명시.
- 반례: 월말 AI 검토 주기 %7·동시 옵션 행사·임대 종료 직후 5인 미달·모구단/2군 동일 선수 이중 선발.
- 완료: 실제 날짜/양 구단 정산·당시 계약 기록/세이브 일치. #245, [A7–A8](CODEX_DOMAIN_A_CLUB.md).

### D05. 스카우팅·정보/분석실
- 필수: 실 능력/잠재력(엔진 내부) vs 공식 공개 기록 vs 구단 관측/평가·보고서 불확실성 vs AI·UI의 합법 정보.
- 원인/결과: 스카우트 조사 비용/시간·전문성·대상 표본/패치/출전 수준 → 보고서 정확도/노후화 → 합법 영입·전술/분석 자료.
- UX: 표본·시점/담당·추정 범위·관측한 경기/정보 부족과 '이 선수가 약하다'를 명확히 분리.
- 반례: 상대 정확 실 OVR가 range 하한을 직접 제한하는 코드·상대 의료 남은 일수/스태프 내부 자료 노출·감독 이직 시 이전 구단 보고서 접근·AI 미래 결과 선취.
- 완료: 숨은 속성만 바꾼 paired-state에서 비공개 정보 미관측 사용자/AI 출력의 불법 변화 없음. #248, [A5](CODEX_DOMAIN_A_CLUB.md).

### D06. 스크림·훈련 시간/결과
- 필수: 실제 상대 섭외/가용성·훈련 자원/Bo·Fearless·팀 비공개 연습 데이터와 공식 경기 통계 분리.
- 원인/결과: 상대/시각/선발·챔피언/준비 → **실제 한 시리즈** → 연습 효과/선수 피로·내부 보고서·한 번의 결과 화면/저장.
- UX: Bo1도 실제 경기 상세/시간/선수 통계·연습 효과를 잃지 않고 보여주되 새 경기 실행 금지.
- 반례: `ui-match.js`에서 기록용 `simulateSeries`와 단판 화면용 `simulateMatch` 이중 실행; 경기 일정 겹침/AI 수락 중복·페이지 재진입.
- 완료: #243의 동일 시드/경기 기록/훈련 일회 적용과 저장 parity. [A10](CODEX_DOMAIN_A_CLUB.md), [B6](CODEX_DOMAIN_B_MATCH_WORLD.md).

### D07. 챔피언 원본·패치/시스템
- 필수: 실제 패시브/Q/W/E/R·아이템/룬/소환사/웨이브·정글/타워/오브젝트의 검증된 당시 데이터와 프로 출전 제한.
- 원인/결과: 패치 예정→확정/락→프로 자격·선수 사전 연구→실제 밴픽/경기 소비→당시 경기/메타/시즌 보존.
- UX: 현재/다음 패치의 예정/확정·대회 적용 버전/전술 영향과 실제 공개 자료.
- 반례: 진행 중 경기 핫픽스·미시작 세트 임시 프로 밴/버전 혼합, 미증명 스킬 계수 만들기, `patch-content.js` RNG 정렬.
- 완료: 수치 old→new가 실제 사용 스킬·아이템/밴픽·경기 결과에서 설명 가능한 효과. #232·#246, [B1/B5](CODEX_DOMAIN_B_MATCH_WORLD.md).

## 6. 기능별 QA 방법 — 재현 증거를 남기는 법

### 6.1 단위/인접/통합 세 층

- **L1 원인 단위:** 정확한 seed/세계 시간·선수/팀 ID와 재현 가능한 최소 세계 구성으로 한 사건을 실행해 예상/실제 결과 diff 저장. 이 단계에서 신규 수치/사람 이름·시나리오 확정 값은 실제 사양/테스트 fixture에서 가져올 것.
- **L2 인접 엔진:** 예를 들어 임대는 `월드 시간 ↔ 임대 계약 ↔ 재정 ↔ 등록`; 스크림은 `밴픽 ↔ 시리즈 실제 한 실행 ↔ 훈련 소비 ↔ 화면/저장`; 선수 의료는 `훈련/시간 ↔ 의료 ↔ 출전자격/대체·비용`; 패치는 `예정/세계 날짜 ↔ 메타/밴픽/경기 ↔ 당시 역사`를 동시에 확인.
- **L3 사용자 여정:** 신규게임→영입→훈련/스크림→공식 Bo→경기 복기/재정→오프시즌→저장/복원을 실제 주요 버튼·화면 전환/모바일로 확인. 필요 시 2부·무직 감독·구단 해체·타 지역·국제전 경로를 넣는다.

### 6.2 공통 테스트 매트릭스 (의도적 위험/조건)

| 축 | 포함할 입력 | 결과에 요구되는 것 |
| --- | --- | --- |
| 권한 | 관리팀/AI팀/타팀/무직 감독/퇴사 스태프 | 불법 조회·변경 거절, 합법 공개 기록 유지 |
| 시간 | 같은 틱 두 명령, 월말·연말/타임존/DST, 중계 초과/시장 마감 | 사건 순서 결정론, 일정/재정 소비 이중 처리 없음 |
| 경제 | 비용 딱 맞음/1 부족, 분할금·파산/후원 권리 충돌 | 실제 승인 가능 여부와 잔액/채무 원자성 |
| 선수 | 의료 결장/0가용/2군/임대·재활, 중복 역할/동명이인 | 합법 등록·성장/출전/역사 ID 정합 |
| 경기 | Bo1/3/5, Fearless·선픽, 장기 경기, 가짜 timeout 승리 금지 | 단일 실제 세트/넥서스·공식 판정/기록 |
| 정보 | 무관측/작은 표본/오래된 보고서, 상대 숨은 값만 변경 | AI/사용자 불법 정보 선취 없음 |
| 저장 | 중단·복원/슬롯 교체, 느린 DB/쿼터·손상/구버전 | 마지막 정상 스냅샷, 공식 결과·대기 결정 그대로 |
| 화면 | 320/360/390px, 빈/대량 데이터·연속 클릭/뒤로·키보드 | 가독성·실제 조작·문맥/오류 표시 |
| RNG | 고정/변경 seed, 독립 실행/브라우저, RNG stream 분리 | 동일 입력의 의도된 재현성·다른 스트림 교란 없음 |
| 장기성 | 시즌1·5·20+ 기록·구단 개편/선수 은퇴 | 당시 ID/공식 역사·조회/저장 크기 보전 |

### 6.3 시나리오 단위의 입력·기대·테스트 요구

- 테스트에 실제 도메인 기능이 없다면 성공할 것으로 가정한 고정 assertion을 새로 만들지 않는다. 어떤 사양이 아직 미구현인지 상태를 명시하고, 기존 안정 기능에 맞춰 작은 수직 slice를 완성한다.
- 오류가 **재현 가능한 위험**인지 경로만 **논리적으로 의심**되는 위험인지 별도 기록. 재현 전 성능 개선 폭/데이터 손실/정보 누출 발생률을 단정하지 않는다.
- 우선 실제 파일에 있는 `scripts/*-acceptance.mjs` 중 관련 것을 실행한다. `package.json`의 정확한 검증 스크립트/최종 CI를 조회하며, 존재하지 않는 스크립트 이름을 임의 생성해 PASS 처리하지 않는다.
- 변경한 코드가 실제 엔진/화면의 실행 경로에 포함됐는지 빌드 산출물/호출 추적으로 확인. 테스트가 해당 분기를 한 번도 호출하지 않는다면 커버리지가 있다는 주장은 불가능.

## 8. 기여·빌드·검증·게시 정확성

- 구현 소스: `src/artifact/`. 조립/실행 모듈 순서: `scripts/artifact-modules.mjs`; **index.html 및 dist/index.html 직접 수동 편집 금지**. `npm run build`로 산출.
- `package.json`에 있는 집중 수용 스크립트와 `npm run check`/정적/Regression·CI 분리; 의료 core·4 seed shards·2 aggregate를 포함하는 승인 필수 검사 강도 약화 금지.
- 실 코드 변경 후 PR을 올릴 때 시작 main SHA, 기존 진행 PR 충돌, 재현 입력·시드/로그, 변경 파일/라인, 집중·인접/종합 검사(pass/fail/skipped), 완료하지 못한 항목, PR/commit/CI ID를 함께 기록. **테스트를 실행하지 않았다면 PASS로 쓰지 않음.**
- CI만 통과했다고 출시 성공 주장하지 말 것. 최신 PR head 병합, 결과 main head의 standalone/Pages 후속 검증, 실제 모바일 브라우저/Android/실기기/장기 수용을 나눈다.
- 사용자 게임 테스트→문제 수정→최종 장기100시즌·실기기/TalkBack·Android 리릴스의 **후순위**를 변경하지 않는다. 장기 성능 문제를 예방할 소형 계측은 조기 수행 가능.

## 10. 개발 금지사항 / 감사 후 유지해야 할 것

1. 근거 없이 엔진 전체 재작성, 새로운 독립 세계 시간/경제·의료/스카우팅 writer/저장 구조 중복 신설.
2. 화면을 보기 좋게 만드는 과정에서 수동 감독 권한·기존 주요 기능 버튼·아이템 장부·의료/2군/AI 규칙 삭제.
3. 임의 능력/피해/챔피언 효과·패치/대회 정책·승률·영입 수락 확률·선수 가치·실제 외부 데이터 숫자 창작.
4. 서버/웹 연결 없으면 핵심 싱글플레이가 작동하지 않는 설계, 장기 모바일 메모리 무제한 기록 증식, 새 유료 runner/서명/API 비밀 추가.
5. 감독/직원 **별도 인수인계** 기능의 재도입(사용자 최신 제외), 공식 세트/중계 중간 핫픽스, Fearless 위반, 상대 AI에 숨은 능력/비공개 계약 열람.
6. 스크림·경기 결과 화면을 위한 두 번째 경기 실행, 일반 스크림 공식 기록/상금 편입, 과거 기록 현재 상태로 재계산.
7. `source risk`를 재현된 결함으로, 문서 등록을 코드 구현으로, 빌드 통과를 기기/배포 완료로 허위 변경.
8. 기존 실패 로그·시드/검증 증거를 삭제하거나 테스트 기대값/도메인 법칙을 약화해 오류를 감추기.
