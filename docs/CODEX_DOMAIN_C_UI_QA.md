## C5. 저장 슬롯 · 세계 직렬화 · 중단/복원 · 데이터 버전

- **담당:** **P0 #244**, #239·#240·#241.
- **코드:** `app.js`, `save.js`, `save-migration.js`, `ui-save-library.js`, `ui-startup-storage.js`, `ui-state.js`, `state-transaction.js`, `state-rollback.js`.
- **확정 현재 구조:** `app.js:SAVE_SLOTS`은 **1–10 총 10개 슬롯** (과거 루트 README의 세 슬롯 표기는 2026-10-17 수정). 세계 schema v15, 저장 압축 format 2, IndexedDB+localStorage fallback/저장 슬롯별 큐가 존재; 안전한 장치 강제 종료 입증과는 다름.
- **P0 위험 조사:** `app.js:idb/idbGet/idbSet`에서 고정 **800ms timeout**, `saveDB`의 **150ms delay**. IDB transaction 성공/실패·타임아웃 결과/늦게 성공한 쓰기·큐 병행·스토리지 부족/권한/차단·fallback 실패, 페이지 `visibilitychange/pagehide`·화면 잠금·OS kill/홈 화면 이동/장시간 무응답 시 최후 성공 checkpoint와 사용자 UI 저장 표시를 엄격히 분리.
- **원자성:** 슬롯A 저장 중 슬롯B 선택/새 게임/현재 감독 변경, 느린 오래된 promise가 새로운 DB·화면/알림·최근 슬롯 메타를 덮지 않음. 저장 중 강제 종료는 *원자적으로 완결된 마지막 정상 데이터*로 돌아올 수 있어야 하며 반쯤 직렬화된 중간 세계를 유효 세이브로 표시 금지.
- **호환:** 10개 슬롯, 새 게임/자동 저장/수동 백업 내보내기·가져오기/오래된 v15 인코딩·파손/알 수 없는 앞선 버전 구분/원본 유지. migration에서 ID/계약/세계 시각/지불/공식 경기 원본/기록·관측을 다시 계산하지 않음.
- **반례:** 동시에 두 save, 800ms 뒤 DB 성공/실패, quota full·IDB unavailable/fallback readonly, JSON corrupt/절반 읽기·schema mismatch, 비정상 중지 도중 Bo 공식 경기/협상 응답/마감·내 팀 변경, 화면상 '저장됨' 표시와 실제 마지막 성공 저장 불일치.
- **완료:** 로그 및 주입 지연 실험·원본 전후 diff, 중단 후 재접속·정상 슬롯/백업 복원/복원 시 중복 tick·계약/전투 결과 없음. **실기기 forced-kill/Android release 결과는 구현 후 별도 추가**.

- **#247 소스상 문제:** `ui-club-recruitment.js`의 `JSON.stringify(db)` stamp, `JSON.parse(JSON.stringify(db))` 임시 세계 및 `ui-player.js`/`ui-club-finance.js`도 조회/미리보기에서 반복 깊은 복사가 발생할 수 있음. **실제 최적화 효과는 미계측**. 읽기전용 projection/유효범위 캐시·버전/권한/패치/선수 소속/슬롯 무효화가 정확히 작동하도록 작은 수정을 선호.
- **시뮬레이션:** 이벤트가 없는 구간은 올바르게 skip할 수 있으나 의료/시설/훈련/이적시장/패치/미래 계약/AI 반응·실제 세계 시각의 효과를 누락하면 안 됨. 단계별 빠른 진행과 상세 진행은 같은 원인/시드/승패/미래 세계 상태를 만들어야 함.
- **UI:** 데이터 정렬/필터·관전 타이머/중복 listener·비가시 탭 반복 그리기와 memory leak을 검사. 웹 Worker/작업 분할은 실제 파일 빌드/offline HTML/호환성과 기존 로직이 허락하는 경우에만 적용.
- **긴 세계:** 개인 선수 사건 최근120/뉴스250/재정 연간 최근10·해외 compactSeason 등 제한은 영구 이력과 구별하고 **무한 배열 추가/긴 JSON stringify 폭발** 없이 조회·중요 역사 보존과 성능 양립.
- **완료:** 최적화 전후 wall-time/메모리·장치/환경/seed·시즌/조회 데이터 규모 표 + 의도하지 않은 결과/시드·예산/관측/저장 차이 0. 개선 숫자는 측정치가 있는 경우에만 보고. 최종 100시즌·실기기/발열은 구현/사용자 시험 후.

## C7. 정보보호 · 내부 권한 · 액션 원자성 · 반복 실행

- **담당:** **상시 #241**, #242·#248·#244.
- **코드:** `state-transaction.js`, `state-rollback.js`, `state-player-actions.js`, `registration-match.js`, `contract-agreement.js`, `ui-state.js`, `scouting.js`.
- **정당한 actor:** 현재 감독, 위임 권한이 있는 AI/실제 클럽 스태프, 시스템이 수행할 수 있는 작업의 종류와 소유 구단/로스터/재정/자료 scope를 명확히. 오브젝트 id만 변경해 다른 구단 선수 계약/스카우트 내부 보고서/경기 밴픽을 변경할 수 없어야 함.
- **순수 미리보기:** preview는 사용자/AI 행동을 **실제 상태로 commit하지 않아야** 하며 해당 세계 버전/시각·예산·선수·자격이 바뀌면 늦은 확정은 다시 검증/거절. 읽기/추정 계산을 위해 전체 세계/관측 자료를 무단 변경하지 않음.
- **실패 복원:** 성공하면 관련 비용·소속·권한·등록·역사·알림이 한 번씩 일관되게 기록되고, 실패하면 해당 행위의 부분 변화만 원자적으로 회수하며 **이전에 확정된 과거 공식 결과/타 클럽 정상 작업은 보존**.
- **반례:** 더블 탭/서버 지연 유사 중복 이벤트, 같은 시각 두 FA 최종 서명/같은 이적료 청구, 시장 마감과 대기 서명 경합, 세이브 슬롯 전환 중 늦은 UI callback, 같은 날 의료/훈련 tick 두 번, 다른 감독의 내부 평가 열람.
- **완료:** 네 가지 시점(행동 전/미리보기/확정 후/복원 후)의 deep deterministic diff, 고의 오류 주입, 정상 다른 actor/다른 슬롯/기록 영향 없는지 검사.

## C8. 빌드·정적 검사·CI·배포의 실제 게이트

- **구현 소유:** `src/artifact/`의 **102개 엔진 + 70개 UI**; 조립 순서 `scripts/artifact-modules.mjs`. `scripts/build.mjs`이 `index.html`, `dist/index.html` standalone 산출물을 만듦. HTML 자동 산출물은 직접 수작업 편집하지 않음.
- **개발:** Node.js 20+; `npm run dev` / `npm run build`. 가장 작은 수정은 소유 도메인의 focused acceptance부터. 실행 명령이 실제 package/scripts에 존재하는지 확인.
- **기본 검사:** `npm run check`는 긴 직렬 전체 체크; `npm run regression`, `npm run career:acceptance`, `npm run perf`는 용도에 맞게 필요 시. `check` 통과를 실제 브라우저/장기 100시즌/안드로이드 검증과 혼동 금지.
- **필수 CI:** 현재 정확한 PR head의 required checks, 의료 core+**4개 seed shard + 2개 aggregate**, 원본 13/14 점검·stale run/취소/실패 구분 및 CI 원문 보존 정책은 `docs/DEVELOPMENT.md`/`docs/CI_RESULTS.md`를 기준으로. 순차 병합 후 최신 main의 빌드·standalone-sync·Pages 실행과 결과를 따로 증명.
- **증거:** source 경로·커밋 SHA, 단계별 테스트 명령과 pass/fail/skipped, 시작/종료 시간·seed/브라우저, 필수 CI 실행 ID·상태, PR·merge main/head·Pages 게시 evidence, 모르는 항목을 임의로 '완료' 표기 금지.
- **원본 보호:** 과거 CI·회귀 실패, 경쟁 자료, 선수 로스터/의료/계약/전술 수치, historical proof를 버리거나 테스트 단언 수/시드 수를 줄여 녹색으로 만들지 않는다. 유료 runner/과금 변경을 우회 수단으로 사용하지 않는다.
