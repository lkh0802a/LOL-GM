**최소 읽기 순서:** AGENTS.md → 현재 선택한 이슈 본문·관련 댓글 → 현재 main·관련 코드/테스트. 상세 설명이 필요한 경우에만 이 문서의 해당 작업 절 → 마스터의 관련 INV/D → 해당 분야 A/B/C 절을 추가로 조회한다. 첫 실제 구현 **#243** 및 다음 **#244** 순서는 변하지 않는다. 문서만 더 작성하거나 다시 전수조사만 반복해서 구현 완료라고 주장하지 말 것.



## 1. 코덱스에게 주는 직접 실행 명령

**코덱스 단독 개발 지시:** 다음 작업을 이 순서대로 수행하라. 다른 모델/에이전트와 업무를 분담하는 계획을 세우지 않는다. 단순 분석·계획·이슈 재등록에 그치지 말고 실제 수정이 요청된 Codex 작업에서는 코드와 테스트 결과를 남겨라. 모델 변경을 절약 수단으로 전제하지 않는다.

1. 저장소 최신 `main`, 현재 브랜치, 열린 PR, 실행중/완료 이슈, 원본 테스트를 확인한다. 최신 상태가 이 문서와 다르면 *먼저 차이와 증거를 확인하고* 작업 중복/충돌을 방지한다.
2. 가장 앞선 아직 완료되지 않은 **실제 구현 이슈**를 선택한다. 전체 인덱스 #242는 tracker, #241은 모든 PR의 상시 품질 게이트이므로 처음 두 이슈를 '개발 완료'로 취급하지 않는다. 기본 첫 작업은 **#243**이다.
3. 버그/위험을 작은 fixture·시드·UI 상태로 재현한다. 소스상 위험이 실제 사용자 피해로 입증되지 않았을 때는 **'위험 / 재현 전'**으로 기록한다. 재현 실패가 기능 완료 또는 문제없음의 증거가 되는 것은 아니다.
4. 원인과 변경 경계를 확정하고 **기존 source writer/consumer를 재사용하는 최소 PR**로 수정한다. 사용자와 AI, 실전과 연습, 화면과 게임 기록, 소속·시각·재정·세이브를 서로 다른 규칙으로 계산하지 않는다.
5. 해당 집중 테스트와 인접 도메인 통합 검사, 정적/빌드, 정확 최종 head 필수 CI를 차례로 검증한다. 기존 실패 단언·가정·테스트 강도를 약화하거나 임의 스탯/확률로 실패를 덮지 않는다.
6. 이슈에 **원인/변경 파일/사용한 명령/통과·실패·미실행/PR·커밋/미완 사항**을 남긴다. 완료 기준을 충족한 작업만 Close. 다음 우선순위 작업으로 이동한다. 외부 동의가 필요한 규칙 변경/새 사양은 임의 처리하지 말고 구체적으로 알린다.

## 3. 첫 PR 상세 작업 계약 — #243

### 3.1 현재 코드에서 확인된 원인

- `src/artifact/ui-match.js`, `bindMatch()`: 스크림 시작 시 **한 번** `simulateSeries(DB, blue, red, bo, seed, {fearless:true,firstChoice:'coin',replay:true,practice:true})` 호출.
- 이어 `recordScrimPractice(DB, series.rec, series.lines)`로 **첫 번째 실행 결과**를 기록/훈련 효과에 사용하고 저장.
- **Bo1 전용 분기**에서 다시 `simulateMatch(DB, blue, red, seed)`를 호출해 `LAST`와 `renderResult(LAST)`를 채움. 두 번째 `simulateMatch`는 첫 실행과 동일한 실제 게임이라고 보장할 수 없음.
- `src/artifact/series.js`: `seriesGameSetup`의 첫 세트 시드는 `seed+'/g1'`; `playSeriesSessionGame`는 팀 진영·선픽·Fearless/챔피언 사용, `publicMatchRecord`와 `seriesResultLines`을 **실제 한 세트의 출력**으로 산출한다.
- `simulateSeries`의 `opt.capture`는 별도로 `simulateMatch`를 다시 실행하면서 조기 반환하므로, **지금 구현 그대로 사용해서 두 번 돌리는 우회 수정은 금지**.

### 3.2 개발 목표

**스크림 1회 사용자 명령 = 실제 1회 시리즈 실행.** Bo1/Bo3/Bo5 모두 이 실행에서 생성된 승패·진영·밴픽·시드·라인 통계·연습 효과·공개 기록이 단일 사실의 원본이어야 한다.

가능한 최소 방향:
- Bo1 결과 화면을 이미 생성한 `series.rec.games[0]`와 공개 경기/연습 기록으로 직접 렌더링하거나,
- 기존 Bo1 `renderResult`/관전·로그를 유지하려면 **이미 실행된 `playSeriesSessionGame`의 `r`을 읽기 전용 화면 객체로 반환하는 명시적 옵션**을 마련하고, 저장 형식/별도 시뮬레이션/연습 효과를 늘리지 않는다.

**금지:** Bo1에서 `simulateMatch` 또는 `simulateSeries`를 화면용으로 또 호출, 결과를 맞추려고 패치/시드·밴픽을 임의 수정, 화면으로만 두 개 결과 중 하나를 숨기기, 연습 효과/기존 로그·세부 정보 기능을 무심코 제거, 전체 경기 엔진 재작성.

### 3.3 #243 필수 수용 테스트

1. 고정 시드 Bo1 1세트를 두 방식으로 비교: `series.rec.games[0]`, `series.lines`, 화면 상세/요약, `recordScrimPractice`, 저장/복원 결과의 승패·선수·진영·밴픽·공개 스탯이 정확히 한 실행에서 유래.
2. 훈련 자원·피로·숙련·경기 기록이 **스크림 1회당 한 번**만 갱신. UI 새로 렌더링·다른 탭 이동·결과 다시 열기 후에도 중복 적용 금지.
3. Bo1과 Bo3/Bo5의 일반·Fearless·First Selection, 시드/라인업·상대/매니저 변경, 선수 교체/부상, 과거 기록 저장·복원 집중 회귀.
4. 세트 출력이 실제 동일하다는 것을 검증할 **재현 테스트를 추가**. 소스 코드 문자열만 보고 성공 판정하지 않는다.

## 5. 모든 후속 PR 공통 규칙

### 기능·정책 보존

- 모든 C안 10개와 Stage 1–13/경기 38+추가 감사 8은 **계속 개발 목표**. 이미 있는 의료·임대·스태프·스카우팅/세계 하루 시계·시리즈·공개 기록·상태 transaction/rollback을 무효화하거나 복제하지 말 것.

- **별도 직원/감독 인수인계 화면·엔진은 승인 제외.** 기본 상태/계약/기록 소유권만 유지.
