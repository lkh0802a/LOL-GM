# LOL-GM 제품 UI·UX 및 저장·정보 표시 요구사항 (세계관 정본 밖)

> 사용자 승인 기능을 별도 보존한 제품 명세다. 게임 세계 내부/외부의 규정 제정권을 가지지 않으며 대회·계약·선수·재정의 효력을 변경할 수 없다. 세계관 권한·금지의 실제 근거는 [공식 세계 규정집](../rulebook/README.md)을 우선한다.

### UI-001 · 모바일 우선 정보·행동 분리
LOL-GM의 주된 사용 환경은 **모바일**이며 화면에서 **목록 탐색 → 상세 비교·판단 → 실제 감독 행동**을 구분한다. 승인된 계약·선수·출전·재정 옵션을 단순화 명목으로 제거하지 않고, 합법적인 세계 명령을 재사용한다. [근거 #225](https://github.com/lkh0802a/LOL-GM/issues/225), [모바일 동선 사용자 승인](https://github.com/lkh0802a/LOL-GM/issues/225#issuecomment-6392612529), [#240](https://github.com/lkh0802a/LOL-GM/issues/240)

새 게임에서 선수단이 비어 있을 때 첫 영입 안내는 **선택형**으로 제공한다. 실제 자유계약 선수와 직원이 합법적으로 관측한 근거에 따른 추천, 직접 검색과 선수 비교를 제공하되, 안내 이행이나 영입을 강제하지 않고 실재하지 않는 선수단이나 임의 계약을 만들지 않는다. 알림은 감독의 결정이 필요한 중요한 사건과 오류를 중심으로 제공하며 모든 미세 이벤트의 알림을 강제하지 않는다. 실제 계약의 최종 서명권은 감독에게 남는다. [#251 M107C·M145B·M148B 사용자 선택](https://github.com/lkh0802a/LOL-GM/issues/251#issuecomment-6312021889), [#225 첫 영입 및 관측 범위](https://github.com/lkh0802a/LOL-GM/issues/225#issuecomment-6312087208)

받은편지함은 실제 중요도, 법적·계약상 응답 기한과 감독의 필수 의사결정 여부를 구분한다. 중요한 의무를 분류 과정에서 누락하지 않고 매일 미세 알림을 강제하지 않는다. **주간 타임라인은 실제 공식 경기·스크림·이동·휴식·시차·선수 개인 활동 및 직원 일정**을 함께 비교하되, 독립된 세계 시계와 팀·선수의 실제 시간 점유를 한 번만 반영한다. 확정된 공식 일정을 화면에서 임의 변경하거나 선수의 개인 랭크를 팀 전체의 강제 일정으로 표시하지 않는다. [#251 R3-114B 승인](https://github.com/lkh0802a/LOL-GM/issues/251#issuecomment-6245258798) [#251 M203C 사용자 선택](https://github.com/lkh0802a/LOL-GM/issues/251#issuecomment-6312524720)

**상단 탭의 전체 순서**는 사용자가 직접 재정렬할 수 있어야 한다. 드래그 또는 동등한 모바일 접근성 조작을 제공하고, 가로 스크롤·좁은 화면(320px 포함)·다른 브레이크포인트와 저장·복원 후에도 이용자가 설정한 순서를 안정적으로 유지한다. 새 기능·탭이 추가되더라도 이전 사용자의 설정을 안전하게 이전하고 기존 모든 필수 메뉴·권한·세계 기록의 접근성을 유지한다. 탭 재배치는 게임 안의 계약·선수·대회 상태를 변경하는 명령이 아니다. [#251 195C 사용자 승인](https://github.com/lkh0802a/LOL-GM/issues/251#issuecomment-6246141985), [#251 M147C 요약·상세/개인화](https://github.com/lkh0802a/LOL-GM/issues/251#issuecomment-6312021889)

### UI-002 · 저장 슬롯의 선택적 안전 삭제
저장 슬롯은 시작·게임 내 목록에서 **불러오기와 구별된 명시적 삭제**가 가능해야 한다. 삭제 전 대상 슬롯/팀/시즌 확인·취소를 제공하며, 확정된 삭제가 이전 비동기 저장으로 복구되거나 **다른 슬롯을 삭제하는 일은 없어야 한다**. 삭제·읽기·내보내기/복구를 혼동하지 않는다. [근거 #273](https://github.com/lkh0802a/LOL-GM/issues/273), [현재 V2 포함 사용자 승인](https://github.com/lkh0802a/LOL-GM/issues/273#issuecomment-6392612110)

### UI-003 · 실제 계약·영입 미리보기는 읽기 전용
선수 이적 관심도·수락 가능성·로스터 합류 후 배치·급여/바이아웃·지급 일정을 **관측 근거에 따른 미리보기**로 보여준다. 실제 영입 제안/수락/이적료·로스터 변경은 **명시적 제출·확정 전에는 일어나지 않는다**. 예측치와 실제 선수의 법적 동의를 구별한다. [근거 #225](https://github.com/lkh0802a/LOL-GM/issues/225), [영입 비교·계약 약속 확인](https://github.com/lkh0802a/LOL-GM/issues/280#issuecomment-6465606954), [#322](https://github.com/lkh0802a/LOL-GM/issues/322)

### UI-004 · 협상 과정과 약속·기한 표시
선수의 실제 요구, 명확한 거절/역제안·기한, 경쟁 구단의 합법적 공개 정보, **체결된 계약 약속의 이행/미이행 상태**를 동일한 사건 기록에서 추적한다. 즉시 거절 사유를 알림으로 확인할 수 있으나, 존재하지 않는 제안·경쟁 구단·계약 체결 사실을 허위로 생성하지 않는다. [근거 #225](https://github.com/lkh0802a/LOL-GM/issues/225), [계약 UX 승인](https://github.com/lkh0802a/LOL-GM/issues/225#issuecomment-6392612529), [실제 약속·알림 연계](https://github.com/lkh0802a/LOL-GM/issues/280#issuecomment-6465606954)

### UI-005 · 스카우팅은 필요한 시점의 수요 기반 추천
실제 로스터 공석·계약 만료·전력 부족 등에 따른 **보강 후보**는 관련 화면에서 참고할 수 있다. 현재 공백뿐 아니라 실제 계약 만료 전망·장기 선수단 계획·노화 등 합리적으로 입증된 미래 수요도 고려할 수 있으나, 인위적인 수요를 만들지 않는다. 과거에 제안되었던 **매주 유망주 보고·특별 발견 알림·반복 수집 배지**의 도입 결정은 철회되었다. 후보 열람·무시 자체에는 비용이나 벌칙이 없으며 유료 조사·영입은 감독의 명시적 선택이다. [#251 이슈 본문 최종 스카우팅 철회](https://github.com/lkh0802a/LOL-GM/issues/251), [#251 후속 미래 보강 수요 승인 ⑪](https://github.com/lkh0802a/LOL-GM/issues/251#issuecomment-6337287799)

### UI-006 · 실제 경기·계약·여론 정보의 출처 구분
게임 뉴스·대회 분석·시즌 평가·언론 보도에는 **그 시점에 존재한 실제 세계 사건/관측 근거**가 있어야 한다. 확인된 사실, 관측에 근거한 추론, 미확인 루머, 실제 계약 완료를 구분하며 미래 결과·타 구단 비공개 입찰·허위 경기/영입을 사실처럼 발표하지 않는다. [근거 #280](https://github.com/lkh0802a/LOL-GM/issues/280), [시장 루머·실제 원본 연계](https://github.com/lkh0802a/LOL-GM/issues/225#issuecomment-6467723176), [#322](https://github.com/lkh0802a/LOL-GM/issues/322)

### UI-007 · 과거 경기 복기와 결과 설명
전술·밴픽·선수 기량에 관한 해설/복기·사후 피드백은 **실제 실행된 경기/당시 관측 로그와 불확실성**에 근거해야 한다. 후속 패치·현재 로스터를 적용해 과거 경기를 재시뮬레이션하여 확정된 승패를 변경하거나, 결과에 맞추어 존재하지 않았던 원인을 사후적으로 구성하지 않는다. 당시에 보존한 선수·패치·전술·사건·난수·버전 등 **완전한 재현에 필요한 근거가 부족한 경우에는 재현의 한계를 명시**하고, 저장된 공식 판정과 역사를 우선 보존한다. [근거 #280](https://github.com/lkh0802a/LOL-GM/issues/280), [#239](https://github.com/lkh0802a/LOL-GM/issues/239), [#239 당시 경기 이력 보존 승인](https://github.com/lkh0802a/LOL-GM/issues/239#issuecomment-6227432963)

경기 결과는 기본적으로 간결한 요약을 제공하고 상세 보기는 선택할 수 있다. 상세 보기는 같은 실제 경기와 기록을 표시하며 이를 열람하기 위해 두 번째 경기를 생성하지 않는다. [#251 M60C·M65B 사용자 선택](https://github.com/lkh0802a/LOL-GM/issues/251#issuecomment-6312021889)

과거 경기에서 다른 선택을 검토할 때는 당시 관측 가능한 장단점과 불확실성을 별도로 설명한다. 가상의 대안에 대한 승패를 이미 확정된 공식 결과나 역사에 혼입하지 않는다. **다른 구단과 AI 구단의 실제 공개 공식 경기**도 적법한 관측 범위에서 관전·복기할 수 있으며 비공개 전술·의료·숨은 AI 판단을 공개 경기 기록처럼 보여주지 않는다. [#251 82B 승인](https://github.com/lkh0802a/LOL-GM/issues/251#issuecomment-6244712136) [#251 M182B 사용자 선택](https://github.com/lkh0802a/LOL-GM/issues/251#issuecomment-6312524720)

**텍스트 중계·관전의 재생 속도와 시각효과 표시**는 사용자가 설정할 수 있다. 속도 변경·효과 축소·빠른 결과 보기·자세한 관전은 **같은 실제 경기의 단일 확정 결과와 난수·세트 기록**을 사용해야 하며, 설정 변경이나 시각효과 생략으로 경기 시뮬레이션·선수 컨디션·승패·세계 일정이 다시 생성되거나 변하지 않는다. 이는 접근성과 표시 속도 선택이지 경기 세계의 새로운 배속 권한이 아니다. [#251 85B 사용자 승인](https://github.com/lkh0802a/LOL-GM/issues/251#issuecomment-6244712136)

### UI-008 · 현재 감독의 권한과 저장/화면 문맥
조회·스크롤·미리보기/목록 복귀는 세계 시간·AI 결정·계약·자금 원장을 수정하지 않는다. 오래된 세이브나 이전 관리 구단·선수를 대상으로 잔존하는 UI 콜백이 무단 계약/이적·저장을 실행하지 않아야 한다. [근거 #225](https://github.com/lkh0802a/LOL-GM/issues/225), [검토 재검증·화면 문맥](https://github.com/lkh0802a/LOL-GM/issues/225#issuecomment-6392612529), [#240](https://github.com/lkh0802a/LOL-GM/issues/240)

감독은 합법적으로 선택 가능한 자동 진행 정지 조건을 조정할 수 있다. 정지 조건 설정이 계약의 최종 서명이나 실제 권한 담당자의 필수 결정을 건너뛰는 권한을 부여하지 않는다. [#251 M201C 사용자 선택](https://github.com/lkh0802a/LOL-GM/issues/251#issuecomment-6312524720)

### UI-009 · 게임 화면과 개발·설계 기록의 표현 분리
게임 플레이어에게 제공하는 대회·일정·경기·뉴스·알림·도움말 등은 **게임 세계에서 성립하는 규정과 실제 관측 사건**을 기준으로 서술한다. 개발 중 논의한 선택지, 사용자 승인 과정, 구형 엔진과의 비교, 미구현 여부 등 **게임 세계 밖의 개발·설계 메타 설명**을 게임 속 사실 또는 안내 문구로 노출해서는 안 된다. 이 원칙은 실제 대회 형식과 참가 조건의 정확한 표시를 제한하지 않으며, 사용자의 조치가 필요한 실제 저장·제출 오류를 숨기는 근거도 아니다. GitHub 이슈·개발 명세·테스트 진단에는 적용하지 않는다. [사용자 추가 확정](https://github.com/lkh0802a/LOL-GM/issues/280#issuecomment-6393197631)

### UI-010 · 미제출 협상 초안의 안전한 복구
감독이 **아직 제출하지 않은 계약·이적 제안의 입력값과 탐색 문맥**은 취소·화면 이탈·재진입 후 적법한 범위에서 복구할 수 있다. 다만 복구된 초안을 실제 제출하기 전에는 관리 구단·저장 슬롯·대상 선수·세계 시각·제안 기한·예산·시장 및 계약 권한을 다시 검증해야 한다. **이미 제출된 유효 제안, 실제 당사자 합의, 최종 서명, 확정된 지급 및 경과한 세계 시간**은 초안 복구나 화면 취소로 철회·소급 변경하지 않는다. [#145B 사용자 승인](https://github.com/lkh0802a/LOL-GM/issues/225#issuecomment-6245281026), [후속 실제 UI 동선 승인](https://github.com/lkh0802a/LOL-GM/issues/225#issuecomment-6392612529)
