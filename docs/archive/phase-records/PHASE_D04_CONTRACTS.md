# D04 — 계약 기간·보장·냉각·우선협상 심화

> 출처: `docs/RETROACTIVE_DEPTH_AUDIT_1_11.md`의 D04/P0.
> 선행 완료: D01~D03. 기존 `player.sign` 트랜잭션과 저장/롤백 경로를 재사용하며 별도 계약 원장을 만들지 않는다.

## D04-B1 — 계약 기간 정책 정합화와 상황별 선호

### 규칙 충돌 정리

`RULE_SWEEP_2026_09_28_A.md`의 “고정 범위 대신 상황별 자유 협상”과 `PLAYER_RELATION_CONTRACT_RULES.md`의 “최대 3년” 및 `REGRESSION_BASELINE.md`의 3년 상한 보호가 문구상 충돌했다.

B1에서는 구체 계약 규칙과 기존 회귀 보호를 기준으로 다음처럼 해석을 고정한다.

- 법적/엔진 계약기간 범위는 **1~3년**이다.
- “자유 협상”은 모든 선수가 똑같이 2년 계약을 받는다는 의미가 아니라, 1/2/3년 중 선수의 현재 상황에 따라 선호와 협상 결과가 달라진다는 뜻이다.
- 3년 초과 계약은 별도 확정 규칙 변경 없이 추가하지 않는다.
- 의료·시장·계약 금액 밸런스 상수는 B1에서 변경하지 않는다.

### 엔진 규칙

`contracts.js::contractDurationPolicy`를 계약기간 단일 정책으로 추가한다.

- 최소 1년, 최대 3년, UI/정규화용 선택지 `[1,2,3]`.
- 29세 이상은 유연성을 위해 1년 선호.
- 21세 이하이면서 성장 목표인 선수는 장기 성장 안정성을 위해 3년 선호.
- 커리어 목표가 안정성인 선수는 3년 선호.
- 23세 이상이며 야망 수치가 높은 선수는 재시장 진입 유연성을 위해 1년 선호.
- 그 외는 2년 선호.
- 이 분류는 계약 가능 범위를 제한하지 않고 **선수 효용/요구기간의 선호**만 바꾼다.

기존 `offerUtility`의 기간 보정 계수는 새 숫자를 추가하지 않고 이전의 연당 `.055` 규모를 그대로 사용한다. B1은 “무조건 장기가 좋다”였던 방향만 선수 선호기간과의 거리로 바꾼다.

### 동일 경로 연결

- `normalizeContractTerms`: 모든 계약을 중앙 기간 정책으로 정규화.
- `contractYearsForPlayer`: 기존 나이/명성/의료 위험 기반 AI 기간 생성은 유지하되 중앙 1~3년 경계 안에서만 반환.
- `negotiationDemand`: 선수 측 초기 요구기간이 중앙 정책의 `preferred`를 사용.
- `negotiationCounter`: 기존 역제안 알고리즘은 정규화 단계에서 동일 기간 경계를 사용.
- 관리 구단 협상 UI: 하드코딩된 `[1,2,3,4]`를 제거하고 `contractDurationPolicy(...).choices`를 사용.
- 실제 계약 확정은 기존 `player.sign → signContract` 트랜잭션을 그대로 사용한다.

### B1 acceptance

`scripts/contract-duration-acceptance.mjs`에서 다음을 검증한다.

- 중앙 정책이 1~3년 범위와 선택지를 유지한다.
- 안정성 선호 선수는 3년 계약 효용이 1년보다 높고, 야망 높은 전성기 선수는 1년 계약 효용이 3년보다 높다.
- 선수 측 협상 요구기간도 각각 3년/1년으로 나온다.
- AI 자동 기간 생성이 중앙 법적 범위를 벗어나지 않는다.
- 4년 입력은 기존 회귀 규칙대로 3년으로 정규화되고, 0년 숫자 입력은 최소 1년으로 정규화된다.
- 미지정 기간은 해당 선수 선호기간을 기본값으로 사용한다.
- 3년 계약을 실제 체결한 뒤 종료연도와 save/restore가 일치한다.
- 협상 UI가 엔진 기간 정책을 사용하며 4년 하드코딩 선택지를 노출하지 않는다.

## B1 이후 남은 D04

B1은 D04 전체 완료가 아니다. 다음 독립 단위는 **재계약 거절 후 냉각기간과 완전 결렬 재개 조건**이다. 이후 시즌 최종 국제대회 종료 후 14일 원소속 독점 우선협상, 가계약 실효일, 계약 보장액/방출·파산 정산, 선수 동의와 에이전트/약속 상태를 단계적으로 기존 트랜잭션에 연결한다.


## B1 검증 결과

최종 PR 코드 CI에서 `D04_CONTRACT_DURATION_ACCEPTANCE`와 UI acceptance가 통과했다. 중앙 범위는 `[1,3]`으로 유지됐고, 안정성 커리어 선수는 3년을 선호하며 동일 조건에서 1년/3년 효용이 약 `2.006 → 2.226`으로 증가했다. 야망 높은 전성기 선수는 1년을 선호했고, 기존 AI 기간 생성은 여러 시드에서 1·2·3년을 모두 만들되 중앙 범위를 벗어나지 않았다. 협상 UI는 엔진 `contractDurationPolicy`의 선택지를 사용하며 기존 4년 하드코딩 선택지가 제거됐다.

기존 regression의 3년 계약 보호, 실제 체결 종료연도, save format 2 왕복도 통과했다. D03 stale-report 시장 acceptance와 전체 regression/smoke/2시즌 career 186경기도 함께 통과했다.

D02 다지역 실제 달력 검증도 628일·948 공식 경기·78,514 선수·일을 완주했다. 기간 효용 변화가 오프시즌 계약/옵션 선택을 통해 이후 세계 궤적에 영향을 주어 실제 스크림 블록 등 일부 관측치는 이전 run과 달라졌지만 acceptance 불변식은 모두 통과했으며 의료 확률·훈련 확률·의료 밸런스 상수는 변경하지 않았다.

따라서 B1은 완료로 기록하되 D04 전체는 아직 완료가 아니다. 다음 가장 앞선 단위는 재계약 거절 후 냉각기간과 완전 결렬 협상의 재개 조건이다.


## D04-B2 — 재계약 거절 냉각과 완전 결렬 재개 조건

### B2 상태 분류

기존 `submitNegotiationOffer`가 사용하던 실패 조건을 새 임계치 없이 두 종류로 구분한다.

- **일반 거절(`rejected`)**: 협상 최대 라운드를 모두 사용했지만 기존 patience 소진이나 기존 severe-gap 조건(`utility < threshold - .62`)에는 도달하지 않은 경우.
- **완전 결렬(`breakdown`)**: 기존 patience가 0 이하가 되거나 기존 severe-gap 조건에 도달한 경우.

관리 구단이 직접 `cancelNegotiation`으로 종료한 것은 선수의 거절이 아니므로 냉각/결렬 잠금을 만들지 않는다. 경쟁 구단 선택, 시장 마감 등 기존 별도 종료 상태도 B2의 재계약 거절 잠금으로 바꾸지 않는다.

### 냉각기간

확정 규칙 문서는 “재계약 거절 뒤 냉각기간”을 요구하지만 고정 일수를 지정하지 않는다. B2에서는 새 밸런스 숫자를 만들지 않고 **해당 선수의 기존 `negotiationRoundLimit`(= 그 협상의 `maxRounds`)을 날짜 수로 재사용**한다.

재계약이 거절/결렬되면 `cooldownUntil = addDays(closedDate, maxRounds)`를 저장한다. 이 날짜 전에는 동일 선수·동일 구단 재계약 협상을 다시 시작할 수 없다. 냉각 종료일에는 일반 거절 협상을 다시 시작할 수 있다.

AI 오프시즌 재계약은 현재 한 번의 제안 뒤 거절되면 선수를 FA로 전환하므로 같은 소속팀이 즉시 반복 재제안하는 우회 경로가 없다. 이후 B3의 14일 원소속 독점 협상 창을 형식화할 때 동일 재개 검사 경로를 재사용한다.

### 완전 결렬의 의미 있는 변화

완전 결렬은 냉각기간이 끝났다는 이유만으로 재개할 수 없다. 결렬 시 `situationAtClose`를 저장하고 다음 실제 상태 중 하나가 바뀌었는지 비교한다.

- 소속 선수/협상 구단
- `wantsOut` 및 사유
- 커리어 목표
- 현재 로스터 역할
- 기존 만족도 라벨
- 기존 재계약 공식에서 쓰는 신뢰 임계 구간(55/65), 관계 임계 구간(45)
- 만족도 이슈 코드 집합
- 누적 국제전 출전 또는 우승 이력
- 현재 계약 종료연도

위 항목은 이미 선수 만족도/재계약 효용/커리어 기록에서 사용되는 상태다. 현재 능력치나 새 확률을 추가하지 않는다.

### 시도 이력과 저장

같은 협상을 재개할 때 기존 stable negotiation ID를 유지하면서 이전 시도 요약을 `previousAttempts`에 보존한다. 각 요약에는 상태, 실패 유형, 종료일, 냉각 종료일, 결렬 시 상황 스냅샷이 남는다. 새 시도에는 `attempt` 번호와 `reopenedChanges`를 기록한다. 기존 `world.negotiations` 저장 경로를 그대로 사용하고 별도 협상 원장을 만들지 않는다.

### B2 acceptance

`scripts/contract-negotiation-state-acceptance.mjs`에서 다음을 검증한다.

- 기존 acceptance threshold보다 조금 낮지만 patience를 깎지 않는 제안을 최대 라운드까지 반복하면 `rejected`로 종료된다.
- 냉각 종료일은 기존 `maxRounds` 일수와 정확히 일치하고, 당일/종료 전 재시작이 차단된다.
- save/restore 후에도 냉각 상태가 유지되고, 경계일에 재개되면 이전 시도 감사 정보가 보존된다.
- 기존 severe-gap 조건을 만족하는 합법 제안은 `breakdown`으로 종료된다.
- 완전 결렬은 냉각 종료일 이후에도 상태 변화가 없으면 재개되지 않는다.
- `wantsOut`/사유처럼 실제 재계약 효용에 쓰이는 선수 상황이 바뀌면 재개되며 변경 사유가 기록된다.
- 재개 시도와 이전 실패 유형은 save/restore 뒤에도 보존된다.
- 관리 구단의 자발적 협상 취소는 즉시 재시작 가능해 기존 취소 동작을 보존한다.

## B2 이후 남은 D04

다음 독립 단위는 **월즈 종료 후 14일 원소속 독점 재계약과 월즈+14일 계약 만료, 구단의 선수별 조기 접촉권 포기, 15일째 정식 FA 개방**이다. 선수는 합리적 제안을 거절해 한 시즌을 통째로 쉬는 경력 손실도 고려하되 명백한 저평가는 거절한다. 이후 보장액/방출·파산 정산, 선수 동의, 에이전트/구두 약속을 단계적으로 연결한다.


### B2 검증 결과

최종 코드 CI의 `D04_CONTRACT_NEGOTIATION_STATE_ACCEPTANCE`에서 실제 정상 거절은 2027-06-01의 3라운드 종료로 분류됐고 냉각 종료일은 정확히 2027-06-04였다. 동일일과 하루 전 재시도는 save/restore 후에도 차단됐으며 종료일에만 재개됐다.

재개된 두 번째 협상에서 기존 severe-gap 기준보다 효용이 **0.767 낮은** 합법 제안은 `breakdown`으로 판정됐다. 냉각 종료일 2027-06-07에도 시간 경과만으로는 재개되지 않았으며, 선수의 실제 `wantsOut` 및 사유가 바뀐 뒤에만 세 번째 시도가 허용됐다. 감사 기록은 시도 1의 `rejected`, 시도 2의 `breakdown`과 재개 변경 항목을 모두 보존했고 save format 2 저장/복원도 통과했다. 관리 구단 자발적 취소는 선수 거절로 오인되지 않아 즉시 재시작 가능했다.

초기 검증 fixture가 계약금과 보너스를 고정한 채 연봉만 조절해 중간 효용 구간에 도달하지 못했으나, 엔진 임계치/인내 값을 조정하지 않고 합법 계약 조건 조합을 탐색하도록 테스트만 수정했다. 최종 코드 리뷰에서는 첫 협상의 RNG 시드를 B2 이전과 정확히 동일하게 유지하고, 실제 재개 시도에만 attempt suffix를 부여해 기존 창단/협상 분포의 불필요한 변동을 막았다.

같은 최종 CI에서 B1 계약기간, D03 전체 스카우팅, D02 다지역 628일·948 공식 경기·15,644 실제 스크림 블록·78,514 선수·일, regression, world smoke, 2시즌 career 186경기, performance probe, production build가 모두 통과했다. 의료/계약 시장 밸런스 확률이나 기존 회귀 상수는 변경하지 않았다.

**B2만 완료**로 기록한다. D04 전체 완료에는 14일 원소속 독점/15일째 타팀 접촉과 가계약 실효일, 보장액·파산/방출 정산, 선수 동의·에이전트/약속의 후속 독립 작업이 필요하다.


## D04-B3 — 월즈+14일 계약 만료와 원소속 독점/조기 접촉

### 확정 날짜 규칙

- 기준일은 그 해의 **World Championship 최종 경기일**이다. 월즈가 없는 커스텀 월드는 최종 국제대회, 그것도 없으면 최종 일정일을 fallback으로 사용한다.
- 기준일 다음 날부터 14일째까지 기존 시즌 만료 계약은 계속 유효하다.
- **14일째가 기존 계약의 실제 만료일**이고, 이 기간 전체가 원소속 구단의 독점 재계약 기간이다.
- **15일째부터 미재계약 선수는 FA**가 되어 모든 구단과 정식 계약할 수 있다.
- 과거 초안의 “연말 12/31 만료 → 1/1 가계약 발효” 모델은 사용하지 않는다.

### 원소속 구단의 조기 접촉 허용

재계약 계획이 없는 구단은 만료 예정 선수별로 `grantEarlyContact`를 통해 독점 접촉권을 포기할 수 있다.

- 접촉권 포기는 즉시 방출이 아니며, 선수의 현재 팀·기존 연봉·출전권은 계약 만료일까지 유지된다.
- 다음 시즌 팀/선수 옵션이 남은 계약은 옵션 결정 전에 접촉권을 포기할 수 없다.
- 접촉권이 포기된 선수만 타 구단이 독점기간 안에 `early_fa` 협상을 시작할 수 있다.
- 합의가 나도 다음 계약은 15일째에만 발효된다.
- AI 구단도 재계약 필요성이 낮은 선수를 같은 권한/상태 저장 경로로 조기 공개하며, AI 영입 구단도 동일한 관찰·예산·계약 효용 규칙을 사용한다.

### 선수의 무계약 경력 위험

선수는 단순히 요구조건을 못 맞췄다는 이유만으로 현실성 없이 한 시즌을 쉬는 선택을 반복하지 않는다.

- 기존 `offerAcceptanceThreshold`에 오프시즌 무계약의 경력 기회비용을 반영한다.
- 별도의 임의 desperation 상수는 만들지 않고 B1의 기존 기간 효용 단위 `.055`와 B2의 기존 의미 있는 저제안 경계 `.22`를 재사용한다.
- FA 경력이 이미 누적됐거나 전성기 연령대라면 무계약 위험을 더 크게 본다.
- 반대로 `contractOfferReasonable`은 기존 AI 시장이 실제로 쓰던 최저 연봉 배수 `.95 × (1 - medicalRisk × .4)`를 보장급 하단으로 재사용한다. 이 하단보다 낮은 명백한 저평가는 무계약 위험이 있어도 수락하지 않는다.
- 팀 전력, 역할, 시설, 목표, 기간, 관계 등은 기존 `offerUtility`가 계속 판단한다.

### 회계/저장 불변식

월즈+14일에 선수 이동이 발생해도 지난 시즌의 연봉·SFR 결산이 새 로스터로 재계산되면 안 된다. 계약창을 열 때 월즈 종료 시점의 팀별 payroll/regulatory payroll을 스냅샷하고 지난 시즌 재정 결산은 그 값을 사용한다.

접촉권 포기, 미래 계약 합의, 만료일, 발효일, 협상 이력은 기존 `world` 저장 경로를 통과한다. 다음 계약 발효는 기존 원자적 `player.sign`/만료 `player.release` 트랜잭션을 재사용한다.

## D04-B4a — 방출 보상 채무의 계약 근거와 결산 이력

첫 독립 단위는 기존 방출 보상 규칙의 금액을 바꾸지 않고 실제 채무를
선수별로 추적하는 것이다. `contractReleaseSettlement`가 방출 시점의 선수,
날짜, 연봉, 종료연도, 잔여 연수, 기존 50% 보상률과 면제 여부를 계산한다.
관리자와 AI 모두 기존 `player.release` 트랜잭션을 통해 같은 정산을 사용한다.

`finance.buyout`은 계속 미결제 합계의 source of truth다. 선수별 근거는
`finance.releaseObligations`에 저장하고 현금은 방출 때 중복 차감하지 않는다.
연간 결산은 그 합계를 한 번 비용 처리하고, 선수별 근거를 기존 10년 제한
재정 이력의 `releaseSettlement`에 남긴 뒤 미결제 목록을 비운다. 구버전
저장의 합계는 그대로 유지하며 상세 미기록 금액으로 표시한다. 가상의
선수나 계약 내용을 만들어 채우지 않는다.

재정 화면에서 현재 미결제 내역과 직전 결산 내역을 세로 카드와 터치 가능한
접이식 목록으로 확인할 수 있다. 이 단계는 HTML 버전에 반영된다.
`contract-release-liability-acceptance.mjs`가 순수 preview, 관리자/AI 동일
근거, 실패 후 원자적 rollback, 미결제/결산 save 복원, 기존 합계 보존 및
다음 해 중복 청구 방지를 검증한다.

**B4 전체 완료가 아니다.** 보장 조건의 실제 협상, 상호 해지, 구단 지급불능
정산은 후속 독립 단위다. 의료 대체 계약과 창단/만료 면제는 유지한다.

## D04-B4b — 협상 가능한 방출 보장률

방출 보장을 실제 개인 계약 조건 `releaseGuaranteeRate`로 저장한다. 첫 구현의
선택지는 **50%·75%·100%**다. 기존 규칙의 50%를 하단과 생략 기본값으로 유지하며,
중간/전액 보호를 추가한다. 이는 구현 정책이며 새로운 실존 리그 규정이 아니다.
구버전 계약과 진행 중 협상에서 필드가 없어도 보호율을 소급 변경하지 않는다.

선수의 기존 커리어 목표가 안정이면 전액, 성장이면 75%, 나머지는 50%를
초기 요구한다. 역제안은 요구율과 구단 제안 중 높은 비율을 유지한다. 보장률은
수락 효용에도 반영되므로 요구가 강제 최저 조건은 아니다. 기존 기간 효용 단위
`.055`를 한 보호 단계에 재사용하고 안정/성장 외 목표는 절반 가중한다.
50% 제안의 기존 효용은 그대로다. RNG 소비와 협상 임계치를 바꾸지 않는다.

관리자 협상, 경쟁 구단, 창단/재계약/조기 접촉/FA 영입/필수 로스터 충원 AI가
같은 정책을 사용한다. 보장 조건은 서명된 계약·계약 이벤트·옵션 연장·미래
계약 합의/발효·저장에 남는다. 협상 화면은 엔진 선택지를 사용한 선택 상자를
제공하고 선수 상세는 서명된 비율을 표시한다. 유효하지 않은 비율은 협상 라운드,
계약 합의 또는 트랜잭션을 진행하기 전에 거부한다.

보장률은 구단 방출 때 **연봉 × 잔여 연수 × 서명한 비율**에 적용된다.
정상 계약 만료·창단 방출·의료 대체 계약의 기존 면제를 유지한다. 의료 계약의
일급 보장과 혼동하지 않는다. 활성 계약의 조건부 비용을 미결제 채무로 미리
잡지 않고 실제 방출에서만 B4a 채무를 발생시켜 기존 결산에서 한 번 지급한다.

`contract-guarantee-acceptance.mjs`는 실제 협상 수락과 UI 제출, 선수 효용,
관리자/AI 방출 비용, 옵션 보존, 구버전 기본값, 면제, 실패 rollback 및 계약/
협상/채무 저장 복원을 검증한다. 기존 `contract-window-acceptance.mjs`는 서로
다른 보장률의 재계약/조기 계약을 저장한 뒤 정확한 날짜에 발효하여 같은
보장률이 실제 계약에 남는지 검증한다. 전체 검증은 Actions에서 수행한다.

**B4 및 D04는 진행 중이다.** 다음 독립 작업은 상호 해지와 지급불능 정산이다.

## D04-B4c — 오프시즌 상호 해지

상호 해지는 `offseason`/`market` 단계에서만 가능하다. 선수의 이적 희망,
중립 만족도 50 미만의 불만, 또는 후보/경쟁 역할에서 주전을 원하는 커리어
목표가 있어야 동의 의향을 가진다. 현재 계약을 유지하려는 선수는 합의금을
제시해도 거절한다. 의료 대체 계약·이미 만료된 계약·합의한 미래 계약은
이 절차로 우회할 수 없다.

첫 구현의 선수 요구액은 현재 계약 방출 보장액 기준이다. 이적 희망은 50%,
주전 기회 탐색은 75%, 그 외 불만은 전액을 요구한다. B4b 보호 단계의 비율을
재사용한 구현 정책이며 임의의 실제 리그 규정이 아니다. 금액은 0.1억 단위로
올림하되 원래 보장액을 넘지 않는다. 제안은 요구액 이상, 원래 보장액 이하여야
한다. 선수 판단은 RNG나 실제 상태 변경 없이 계산한다.

관리자는 계약창/이적 시장의 접이식 상호 해지 화면에서 금액을 제안하고 결과를
확인한다. AI는 시장 로스터 정리 시 같은 선수 동의와 요구액을 적용하며,
동의가 없으면 기존 일방 방출 규칙을 따른다. `player.release`의 `mutual` 모드가
preview·권한·현재 동의 재검증·rollback을 모두 재사용한다. 선수는 즉시 FA가
되고 계약과 옵션이 종료된다. 근거와 합의금은 기존 채무에 발생하고 결산에서
한 번 지급된다. `mutual_termination` 커리어 이벤트와 재정 정산 근거가 저장된다.

`contract-mutual-termination-acceptance.mjs`는 선수 거절/저제안, 시즌 중 차단,
의료/미래 계약 보호, 순수 preview, 동의 변경/변조 차단, 실제 UI 제안/취소,
관리자/AI 동일 처리, 실제 AI 시장 로스터 정리, 늦은 실패 rollback, 저장 복원과
결산 중복 방지를 검증한다. 반복 전체 검증은 Actions에서 수행한다.

**D04는 아직 완료가 아니다.** 다음은 지급불능 시 채무 정산이며, 선수 동의가
필요한 이적·에이전트/약속은 이후 독립 작업이다. 기본 월드 독립 2부 시작,
남은 Items 1–23/D 기능, 모바일 HTML 및 Android 검증도 계속 남아 있다.


## D04-B4d1 — 구단 해체와 현금 한도 정산

사무국의 foldTeam은 system 전용 club.close 트랜잭션을 사용한다. 모구단
해체는 소유 2군을 함께 종료하고, 2군만 종료할 때에는 모구단을 유지한다.
선수의 계약·옵션과 로스터를 정리하고 FA로 전환한다. 폐쇄 구단이 구매자인
미래 계약과 관련 열린 협상은 취소하지만, 다른 구단과 이미 합의한 선수의
다음 계약은 보존한다. 관리 구단 해체는 기존 새 구단 선택 흐름을 사용한다.

각 구단의 양수 현금 범위에서 기존 방출 채무와 계약상 종료 보상 채무를
비례 지급한다. 원래 청구액·지급액·미지급액을 별도 해체 정산에 보존한다.
현금이 없거나 음수이면 현금을 만들어 지급하지 않으며 미지급액을 삭제하지
않는다. 상세 없는 기존 채무도 보존한다. 의료 대체 계약의 선지급 금액을
추가 보상으로 다시 청구하지 않는다. 비활성 구단은 다음 시즌 결산 대상이
아니므로 해체 지급을 연간 비용으로 중복 청구하지 않는다.

현실성 참고: Riot의 [SolaFide 공식 제재](https://lolesports.com/en-US/news/competitive-ruling-solafide-esports)는
급여·상금 미지급과 소유주 제재, 소유권 변경 조건을 확인한다. 이는 미지급을
정상적인 무상 채무 삭제로 처리하지 않기 위한 참고이며, 게임의 보장률이나
비례 청산을 Riot 공식 규정으로 증명하는 자료가 아니다. 가상 리그 규칙은
우선 유지한다. 현재 범위는 선수 종료 보상과 개별 구단 현금 풀이다.
모구단의 공동 채무 보증, 자산 매각, 외부 채권자 우선순위, 미지급 임금·상금,
스태프 채무, 소유주 제재·구제금융은 구현되지 않았다. 소유 2군과 모구단의
자금 지원 관계는 후속 B4d에서 연결해야 한다. 해체와 파산을 동일한 사유로
간주하지 않으며 이 단계를 완전한 지급불능 시스템으로 표시하지 않는다.

club-closure-acceptance.mjs는 순수 preview, 권한, 모구단/2군 범위, 잘못된
채무 거절, 현금·계약 변경 시 stale 거절, 전체 적용 후 실패 rollback,
기존 합계 채무, 지급과 미지급 보존, 협상·미래 계약 처리, 안전한 UI,
저장 복원, 중복 지급 차단 및 새 계약 체결을 검증한다.

CI 첫 실행은 기존 smoke가 폐쇄 2군의 FA에게 살아 있는 계약을 유지하도록 기대하여 실패했다. 해당 검증을 계약 종료·커리어 이력·지급/미지급 합계 보존으로 바꿨다. 선수의 FA 전환 요구는 유지하며 채무 검증을 추가했다.


## D04-B4d2 — 소유 2군 종료 시 실제 모구단 지원

기존 연간 결산의 모구단→소유 2군 지원 관계를 종료 정산에도 연결한다.
2군 자체 양수 현금으로 지급할 수 없는 선수 종료 보상에 대해, 활성 모구단의
현금에서 모구단 자체 종료/방출 채무를 먼저 보호한 나머지를 지원한다.
여러 소유 2군이 함께 닫히면 부족 청구액 비율로 지원금을 배분한다. 모구단이
함께 닫히는 경우에도 모구단 자체 청구액 보호 후 남는 현금만 사용할 수 있다.
음수 잔고·부족한 자금은 임의 증자하거나 자동 탕감하지 않는다.

finance의 한 경로에서 모구단 현금 감소와 2군 현금 증가를 함께 기록한다.
그 후 선수 채무를 지급한다. 폐쇄 구단의 정산에는 원래 현금·지원 수령/제공
및 이전 근거가 남는다. 계속 운영하는 모구단은 최근 20건의 별도 지원 기록을
보존하고 재정 화면에서 확인할 수 있다. 이는 이미 발생한 내부 현금 이전이며
다음 연간 결산에서 운영 비용으로 재차 청구하지 않는다. 기존 B4d1 저장은
지원 필드가 없어도 계속 표시된다. 지원 구단 전체 finance도 stale snapshot과
rollback 범위에 들어가 늦은 실패 시 현금과 지원 이력이 함께 복구된다.

이것은 게임의 기존 소유 2군 재정 지원 모델을 일관되게 확장한 정책이다.
공식 Riot 공동 채무 보증/청산 우선순위 규정이라고 주장하지 않는다. 역방향
2군 잔여 현금 회수, 자산 매각, 임금·상금·스태프 등 다른 채무, 폐쇄 이후의
채권 회수와 새 소유주 구제는 아직 남았다. D04 전체 완료가 아니다.

Focused acceptance는 충분/부족/0/음수 모구단 현금, 모구단 채무 보호,
전체 조직/2군 단독 종료, 순수 preview와 부모 현금 stale 차단, 늦은 실패
rollback, 전체 현금 보존, 양쪽 저장 복원, 실제 재정 UI와 다음 결산 중복
차감 방지를 검증한다. 전체 회귀·장기 시뮬레이션은 Actions에서 검증한다.


## D04-B4d3 — 종료 2군 잔여 현금 회수와 음수 잔고 지원

소유 2군의 종료 보상 청구액을 보호한 뒤 남는 양수 현금을 모구단으로
반환한다. 반환은 모구단이 계속 운영하거나 함께 종료되는 경우 모두 적용한다.
전체 조직 종료에서는 먼저 2군 잔여 현금을 회수한 뒤 모구단 자체 청구액을
보호하고, 나머지를 다른 종료 2군의 부족 자금에 지원한다. 선수에게 지급할
돈이 있는데도 비활성 2군에 현금이 묶이는 기존 경로를 제거한다.

종료 2군의 현금이 음수이면 선수 채무를 지급하기 전에 음수 잔고도 해소해야
한다. 선수 청구가 있는 2군의 지원 필요액은 청구액에서 현재 현금을 뺀 유동성
부족액이다. 모구단 지원이 부족하면 음수 현금과 선수 미지급을 각각 보존한다.
선수 청구가 없는 2군의 음수 잔고를 이 기능으로 무조건 구제하지 않는다.
현금 이전과 실제 선수 지급 합계가 원래 조직 현금을 보존하는지 검증한다.

finance의 기존 양쪽 현금 이전 경로를 재사용하며 kind로 지원과 회수를
구분한다. 계속 운영하는 모구단은 최근 20건의 회수 기록을 저장하고, 종료
구단 정산은 반환/회수/지원 근거를 보존한다. 재정 화면에서 각각 표시하며
연간 결산의 추가 수입/지출로 다시 잡지 않는다. 새 필드는 선택적이므로
기존 지원 기록과 B4d1 저장도 계속 읽을 수 있다. 기존 action journal로
회수 이후 늦은 실패의 양쪽 현금·이력·선수·구단 상태를 전부 복구한다.

이는 게임의 모구단/소유 2군 내부 재정 정책이다. 실제 Riot 청산 법규로
주장하지 않는다. 독립 구단의 잔여 자산, 시설 매각, 다른 채권자, 미지급
임금/상금·스태프 채무, 해체 이후의 회수와 외부 구제는 여전히 미완료다.
D04 전체 완료로 표시하지 않는다.

추가 focused acceptance: 채무 보호 후 잔여 현금 반환, 적자 모구단으로 반환,
늦은 실패 rollback, 전체 조직의 회수→자체 채무→다른 2군 지원 순서,
음수 2군 잔고의 충분/부족 지원, 순수 preview, 실제 양쪽 UI, 저장 복원,
다음 결산의 중복 수입 방지. 전체 회귀/장기 시뮬레이션/빌드는 Actions가 맡는다.


## D04-B4e1 — 모든 완전이적의 선수 개인 조건 동의

구단 간 합의만으로 선수를 이동시키던 player.transfer 경로에 선수 동의를
추가한다. 기존 계약을 유지하는 이동과 새 계약 조건을 맺는 player.sign의
transfer 모두 같은 contractTransferConsent 정책으로 검증한다. manager,
ai, system 모두 거절을 우회할 수 없다. 같은 조직의 1·2군 이동은 별도
내부 배치 규칙을 유지한다. 의료 대체 계약과 이미 합의한 다음 계약은 이
경로로 우회할 수 없다.

선수는 기존 협상과 같은 offerUtility / offerAcceptanceThreshold로 연봉,
역할, 계약 기간, 구단 전력·시설·스태프·국제전 가능성, 커리어 목표를 판단한다.
새 개인 조건은 기존 합리적 급여 하단도 적용한다. 기존 계약 유지 이적은
잔여 연수와 이미 합의한 조건을 평가하지만, 이전 구단에서 지급한 계약금을
다시 받는 새 계약금으로 계산하지 않는다. 이 단계는 실제 LoL의 비공개 계약
관행을 추정한 새 보상 공식이 아니라 게임의 기존 선수 협상 정책을 모든
완전이적에 일관되게 적용하는 작업이다.

조회는 선수·대상 팀·파생 시장 캐시를 분리한 결정 뷰에서 실행하여 원본의
만족도, 레거시 시설/스태프, depthChart 및 캐시를 변경하지 않는다. RNG를
사용하지 않는다. 동의 당시 효용·기준·개인 조건은 canonical preview에
포함되고 적용 직전에 재평가한다. 커리어 목표나 구단 조건이 달라져도 이전
동의로 적용할 수 없다. 이적 이벤트에 동의 근거를 저장하며 저장 복원 뒤
커리어 이력에서도 선수 동의를 표시한다. 과거 이력에 동의를 소급 생성하지 않는다.

AI 시장은 구매 후보와 자동 교환 후보 모두의 실제 동의를 확인한다. 교환을
거절하면 기존 선수를 상대 구단으로 자동 이전하지 않고 기존 로스터 관리
흐름을 따른다. 관리자 저제안 협상도 급여 하단을 정상 역제안/거절 판단에
연결한다. AI의 새 개인 조건 협상 확장, 에이전트/약속, 임대/조건부 이적과
전체 지급불능 범위는 후속 작업으로 남는다. D04 전체 완료가 아니다.

transfer-consent-acceptance는 순수 조회/preview, 모든 actor의 거절 보호,
기존·새 조건, 이미 지급한 계약금 제외, 선호 변경 stale 거절, 늦은 실패
rollback, 동의 이력 저장 복원, 의료/미래 계약 보호와 실제 AI 시장의 거절
선수 강제 영입 방지를 검증한다. 반복 전체 회귀/장기 진행은 Actions에서 수행한다.


## D04-B4e2 — AI 완전이적 개인 조건 제안

AI는 감당 가능한 기존 계약을 선수가 수락하면 그대로 유지한다. 기존 조건을
거절하거나 해당 연봉을 감당할 수 없으면 선수의 현재 희망 기간, 대상 구단의
역할 및 보장률 선호로 새 계약을 제안한다. 연봉은 기존 만료 후 시장 제안의
1/1.05/1.15배 탐색을 재사용하며, 기존 공정 급여·효용·선수 동의 정책을 따른다.
별도 AI 전용 수락 공식이나 무작위 강제 동의는 추가하지 않는다.

영입 가능 연봉은 현재 계약 급여 전체와 제안 이적료 지급 후 현금으로 계산한다.
자동 교환은 상대 선수의 동의가 필요하므로, 아직 확정되지 않은 교환 선수의
연봉을 미리 빼서 영입 예산으로 사용하지 않는다. 감당 가능한 동의 조건이 없으면
후보를 넘기며, 현금·소속·계약을 변경하지 않는다. 새 조건은 player.sign의
transfer 트랜잭션으로 이적료와 새 계약을 함께 적용하며 저장된 동의 근거와
실제 계약 조건을 유지한다. 이미 수락한 기존 조건은 player.transfer를 유지한다.

AI 이적 제안·시장 실행은 contract-transfer-market.js로 분리한다. 기존 계약
정책과 원자적 트랜잭션은 재사용하며 모듈 크기 제한을 늘려 우회하지 않는다.
transfer-consent acceptance는 순수 조회, 예산 없음, 기존 계약 우선, 이적료
지급 후 예산, 실제 AI 시장의 새 계약 및 저장 복원을 검증한다. 에이전트·구두
약속, 이적료 분할/추가금, 임대와 지급불능 잔여 범위는 아직 미완료다.


## D04-B4f1 — 계약 역할 약속의 실제 이행

계약 promisedRole과 구단이 편집하는 rosterRole을 분리한다. 현재 역할을 후보로
내려도 계약에서 합의한 주전 약속은 사라지지 않는다. 역할 하향은 약속 불이행
불만으로 표시하고, 공식 출전 부족은 계약 역할을 기준으로 기존 관찰 게임 수와
기대 출전·심각도 정책을 적용한다. 기존 만족도·감독 신뢰·재계약 의향 계산에
같은 원인을 전달한다. 새로운 보편적 강제 이적이나 수락 공식은 추가하지 않는다.

실제 계약 체결과 완전이적 시 현재 사용량을 기준점으로 저장한다. 이전 계약·
구단의 출전 부족을 새 합의에 청구하지 않으며, 시즌이 바뀌면 새 시즌 기록을
사용한다. 같은 조직의 1·2군 배치는 재협상이 아니므로 기준점을 초기화하지
않는다. 의료 결장 상태이고 실제 출전도 없는 공식 게임은 출전 가능 기회에서
제외한다. 시리즈 후 부상을 입었더라도 실제 출전 게임은 계속 인정한다.

선수 상세 화면은 현재 역할과 계약 약속을 따로 보여주며 계약 이후 기용 기록을
표시한다. 기준점과 의료 결장 사용량은 선택적 필드이다. 구버전 저장은 기존
시즌 사용량과 저장된 계약 역할을 읽으며, 알 수 없는 과거 계약 날짜/출전
기준점을 생성하지 않는다. 조회 자체는 상태를 변경하지 않는다.

수락 검증: 실제 공식 사용량 갱신, 하향 편집 우회 차단, 지킨 약속, 부상 결장,
만족도/신뢰와 재계약 의향, 새 합의·완전이적 기준점, 저장/구버전·순수 조회.
에이전트와 구두 약속, 약속의 전체 이력/재협상 UI, 지급불능 잔여 범위와 임대는
후속 작업이며 D04 전체 완료가 아니다.


## D04-B4f2/B4g1 — 구두 약속·에이전트·확인 화면 묶음

구두 역할 약속은 계약 조건과 별도인 추가 기회 약속이다. 현재 역할과 계약보다
높은 역할만 제안하며, 이미 진행 중인 약속을 반복해서 관찰 기록을 지울 수 없다.
계약/구두 약속 중 더 높은 기대를 기존 실제 기용·의료 결장 기준에 적용하여
만족도·신뢰·재계약과 연결한다. 새 계약/완전이적/방출은 기존 구두 약속을 종료하고
커리어 근거를 남긴다. 내부 1·2군 이동은 약속 종료나 초기화가 아니다.

player.promise는 기존 원자적 명령 경로에서 본인 담당 선수 권한, 순수 preview,
사용량 stale, 늦은 실패 rollback을 처리한다. 소유 2군 감독은 자기 선수에 대한
스포츠 약속을 할 수 있으며 경제적 계약 권한은 계속 모구단에 있다. AI는 실제
선발 승격 때 같은 명령으로 약속하고, 관리자 구단의 선택을 강제로 확정하지 않는다.
화면은 담당자와 진행 중 약속을 표시하고 내용을 확인·취소·확정한 뒤 저장한다.

기존 계약 요구의 고명성 기준 82 이상 선수에게만 실체 담당 에이전트를 부여한다.
선수에 포함된 엔티티는 안정 ID·고객 ID·이름·독립 협상 성향·커리어 중점을 저장한다.
협상 성향은 기존 선수 성향 분포를 별도 안정 RNG 스트림에서 생성한다. 새 수락
공식이나 월드 RNG 소비는 없으며 기존 요구 급여/옵션/바이아웃과 라운드 인내에
담당자 성향을 적용한다. 최종 효용과 수락 여부는 계속 선수 자신의 정책이다.
저명하지 않은 선수는 자기 성향으로 직접 협상한다. 구버전 저장에 담당자가 없어도
직접 협상하며 새 실제 협상/계약 때 필요한 담당자를 생성한다.

수락 검증은 실제 요구와 라운드 변화, 고객 성향 보호, 담당자 저장, 구두 약속
권한·순수 조회·stale·rollback·반복 보호, 실제 AI 역할 조정, 신뢰와 저장 복원,
실제 UI 취소/확정/저장을 묶어서 확인한다. 여러 고객을 둔 에이전시 시장, 수수료,
담당자 변경, 하향 약속 상호 재협상 및 지급불능/이적료 분할·임대는 미완료다.


## D04-B4g2 — AI 계약·이적 개인조건의 대표자 협상 위치

AI 재계약, 자율 FA 영입, 조기 FA 제안 및 완전이적 개인조건은 기존 `negotiationDemand`,
`negotiationCounter`, `negotiationRoundLimit`를 재사용한다. 제안된 계약이 기존
선수 효용/합리적 보장급 정책을 충족하지 않으면 담당자 프로필 또는 선수 자신의
개인 협상 성향으로 요구·역제안을 만들고, 기존 구단 급여 예산/현금 범위와 해당
협상 라운드 한도 안에서만 다음 조건을 판단한다. AI는 새 수락 공식이나 추가
무작위 추첨을 사용하지 않는다. 성공 여부는 기존 `offerUtility`, 합리성 및
완전이적 선수 동의 검증으로 최종 결정된다.

수동 구단이 시장에 제출한 FA 제안은 같은 자동 역제안 확장으로 바꾸지 않는다.
기존 제안 조건이 선수 정책을 통과하면 기존 플레이어 제안을 그대로 적용하며,
통과하지 못하면 관리자가 공식 협상 UI에서 직접 협상해야 한다. 협상 역제안은
계약 조항일 뿐 에이전트 권한이나 수수료가 아니다. 이적료는 기존 구단 간 합의
절차에서만 정한다.

`agent-negotiation-parity-acceptance.mjs`는 실제 AI 재계약 결정, 자율 FA 시장,
조기 FA 합의 경로, AI 완전이적 개인조건 헬퍼, 실제 수동 이적 협상 카드의 담당자 표시와 취소를
검증한다. 또한 save/restore 시 구버전 담당자 부재, 잘못된 고객 ID의 직접 협상
fallback, 순수 조회, 제안 실패 시 현금/계약 미변경, 수동 제안 자동 수정 금지를
확인한다. 이 수락은 대표자가 독립 수락 권한을 갖거나 에이전시 시장·수수료·
담당자 변경 기능을 갖췄다는 뜻이 아니다. 기존 D04 지급불능의 추가 채무/자산,
임대/조건부 이적의 나머지 범위도 계속 열려 있다.
