# D04 — 계약 기간·보장·냉각·우선협상 심화

> 출처: `docs/RETROACTIVE_DEPTH_AUDIT_1_11.md`의 D04/P0.
> 선행 완료: D01~D03. 기존 `player.sign` 트랜잭션과 저장/롤백 경로를 재사용하며 별도 계약 원장을 만들지 않는다.

## D04-B1 — 계약 기간 정책 정합화와 상황별 선호

### 규칙 충돌 정리

`RULE_SWEEP_2026_09_28_A.md`의 “고정 범위 대신 상황별 자유 협상”과 `PLAYER_RELATION_CONTRACT_RULES.md`의 “최대 3년” 및 `REGRESSION_BASELINE.md`의 3년 상한 보호가 문구상 충돌했다.

B1에서는 구체 계약 규칙과 기존 회귀 보호를 기준으로 다음처럼 해석을 고정한다.

- 법적/엔진 계약기간 범위는 **1~3년**이다.
- “자유 협상”은 모든 선수가 똑같이 2년 계약을 받는다는 의미가 아니라, 1/2/3년 중 선수의 현재 상황에 따라 선호와 협상 결과가 달라진다는 뜻이다.
- 3년 초과 계약은 별도 확정 규칙 변경 없이 추가하지 않는다.
- 의료·시장·계약 금액 밸런스 상수는 B1에서 변경하지 않는다.

### 엔진 규칙

`contracts.js::contractDurationPolicy`를 계약기간 단일 정책으로 추가한다.

- 최소 1년, 최대 3년, UI/정규화용 선택지 `[1,2,3]`.
- 29세 이상은 유연성을 위해 1년 선호.
- 21세 이하이면서 성장 목표인 선수는 장기 성장 안정성을 위해 3년 선호.
- 커리어 목표가 안정성인 선수는 3년 선호.
- 23세 이상이며 야망 수치가 높은 선수는 재시장 진입 유연성을 위해 1년 선호.
- 그 외는 2년 선호.
- 이 분류는 계약 가능 범위를 제한하지 않고 **선수 효용/요구기간의 선호**만 바꾼다.

기존 `offerUtility`의 기간 보정 계수는 새 숫자를 추가하지 않고 이전의 연당 `.055` 규모를 그대로 사용한다. B1은 “무조건 장기가 좋다”였던 방향만 선수 선호기간과의 거리로 바꾼다.

### 동일 경로 연결

- `normalizeContractTerms`: 모든 계약을 중앙 기간 정책으로 정규화.
- `contractYearsForPlayer`: 기존 나이/명성/의료 위험 기반 AI 기간 생성은 유지하되 중앙 1~3년 경계 안에서만 반환.
- `negotiationDemand`: 선수 측 초기 요구기간이 중앙 정책의 `preferred`를 사용.
- `negotiationCounter`: 기존 역제안 알고리즘은 정규화 단계에서 동일 기간 경계를 사용.
- 관리 구단 협상 UI: 하드코딩된 `[1,2,3,4]`를 제거하고 `contractDurationPolicy(...).choices`를 사용.
- 실제 계약 확정은 기존 `player.sign → signContract` 트랜잭션을 그대로 사용한다.

### B1 acceptance

`scripts/contract-duration-acceptance.mjs`에서 다음을 검증한다.

- 중앙 정책이 1~3년 범위와 선택지를 유지한다.
- 안정성 선호 선수는 3년 계약 효용이 1년보다 높고, 야망 높은 전성기 선수는 1년 계약 효용이 3년보다 높다.
- 선수 측 협상 요구기간도 각각 3년/1년으로 나온다.
- AI 자동 기간 생성이 중앙 법적 범위를 벗어나지 않는다.
- 4년 입력은 기존 회귀 규칙대로 3년으로 정규화되고, 0년 숫자 입력은 최소 1년으로 정규화된다.
- 미지정 기간은 해당 선수 선호기간을 기본값으로 사용한다.
- 3년 계약을 실제 체결한 뒤 종료연도와 save/restore가 일치한다.
- 협상 UI가 엔진 기간 정책을 사용하며 4년 하드코딩 선택지를 노출하지 않는다.

## B1 이후 남은 D04

B1은 D04 전체 완료가 아니다. 다음 독립 단위는 **재계약 거절 후 냉각기간과 완전 결렬 재개 조건**이다. 이후 시즌 최종 국제대회 종료 후 14일 원소속 독점 우선협상, 가계약 실효일, 계약 보장액/방출·파산 정산, 선수 동의와 에이전트/약속 상태를 단계적으로 기존 트랜잭션에 연결한다.


## B1 검증 결과

최종 PR 코드 CI에서 `D04_CONTRACT_DURATION_ACCEPTANCE`와 UI acceptance가 통과했다. 중앙 범위는 `[1,3]`으로 유지됐고, 안정성 커리어 선수는 3년을 선호하며 동일 조건에서 1년/3년 효용이 약 `2.006 → 2.226`으로 증가했다. 야망 높은 전성기 선수는 1년을 선호했고, 기존 AI 기간 생성은 여러 시드에서 1·2·3년을 모두 만들되 중앙 범위를 벗어나지 않았다. 협상 UI는 엔진 `contractDurationPolicy`의 선택지를 사용하며 기존 4년 하드코딩 선택지가 제거됐다.

기존 regression의 3년 계약 보호, 실제 체결 종료연도, save format 2 왕복도 통과했다. D03 stale-report 시장 acceptance와 전체 regression/smoke/2시즌 career 186경기도 함께 통과했다.

D02 다지역 실제 달력 검증도 628일·948 공식 경기·78,514 선수·일을 완주했다. 기간 효용 변화가 오프시즌 계약/옵션 선택을 통해 이후 세계 궤적에 영향을 주어 실제 스크림 블록 등 일부 관측치는 이전 run과 달라졌지만 acceptance 불변식은 모두 통과했으며 의료 확률·훈련 확률·의료 밸런스 상수는 변경하지 않았다.

따라서 B1은 완료로 기록하되 D04 전체는 아직 완료가 아니다. 다음 가장 앞선 단위는 재계약 거절 후 냉각기간과 완전 결렬 협상의 재개 조건이다.


## D04-B2 — 재계약 거절 냉각과 완전 결렬 재개 조건

### B2 상태 분류

기존 `submitNegotiationOffer`가 사용하던 실패 조건을 새 임계치 없이 두 종류로 구분한다.

- **일반 거절(`rejected`)**: 협상 최대 라운드를 모두 사용했지만 기존 patience 소진이나 기존 severe-gap 조건(`utility < threshold - .62`)에는 도달하지 않은 경우.
- **완전 결렬(`breakdown`)**: 기존 patience가 0 이하가 되거나 기존 severe-gap 조건에 도달한 경우.

관리 구단이 직접 `cancelNegotiation`으로 종료한 것은 선수의 거절이 아니므로 냉각/결렬 잠금을 만들지 않는다. 경쟁 구단 선택, 시장 마감 등 기존 별도 종료 상태도 B2의 재계약 거절 잠금으로 바꾸지 않는다.

### 냉각기간

확정 규칙 문서는 “재계약 거절 뒤 냉각기간”을 요구하지만 고정 일수를 지정하지 않는다. B2에서는 새 밸런스 숫자를 만들지 않고 **해당 선수의 기존 `negotiationRoundLimit`(= 그 협상의 `maxRounds`)을 날짜 수로 재사용**한다.

재계약이 거절/결렬되면 `cooldownUntil = addDays(closedDate, maxRounds)`를 저장한다. 이 날짜 전에는 동일 선수·동일 구단 재계약 협상을 다시 시작할 수 없다. 냉각 종료일에는 일반 거절 협상을 다시 시작할 수 있다.

AI 오프시즌 재계약은 현재 한 번의 제안 뒤 거절되면 선수를 FA로 전환하므로 같은 소속팀이 즉시 반복 재제안하는 우회 경로가 없다. 이후 B3의 14일 원소속 독점 협상 창을 형식화할 때 동일 재개 검사 경로를 재사용한다.

### 완전 결렬의 의미 있는 변화

완전 결렬은 냉각기간이 끝났다는 이유만으로 재개할 수 없다. 결렬 시 `situationAtClose`를 저장하고 다음 실제 상태 중 하나가 바뀌었는지 비교한다.

- 소속 선수/협상 구단
- `wantsOut` 및 사유
- 커리어 목표
- 현재 로스터 역할
- 기존 만족도 라벨
- 기존 재계약 공식에서 쓰는 신뢰 임계 구간(55/65), 관계 임계 구간(45)
- 만족도 이슈 코드 집합
- 누적 국제전 출전 또는 우승 이력
- 현재 계약 종료연도

위 항목은 이미 선수 만족도/재계약 효용/커리어 기록에서 사용되는 상태다. 현재 능력치나 새 확률을 추가하지 않는다.

### 시도 이력과 저장

같은 협상을 재개할 때 기존 stable negotiation ID를 유지하면서 이전 시도 요약을 `previousAttempts`에 보존한다. 각 요약에는 상태, 실패 유형, 종료일, 냉각 종료일, 결렬 시 상황 스냅샷이 남는다. 새 시도에는 `attempt` 번호와 `reopenedChanges`를 기록한다. 기존 `world.negotiations` 저장 경로를 그대로 사용하고 별도 협상 원장을 만들지 않는다.

### B2 acceptance

`scripts/contract-negotiation-state-acceptance.mjs`에서 다음을 검증한다.

- 기존 acceptance threshold보다 조금 낮지만 patience를 깎지 않는 제안을 최대 라운드까지 반복하면 `rejected`로 종료된다.
- 냉각 종료일은 기존 `maxRounds` 일수와 정확히 일치하고, 당일/종료 전 재시작이 차단된다.
- save/restore 후에도 냉각 상태가 유지되고, 경계일에 재개되면 이전 시도 감사 정보가 보존된다.
- 기존 severe-gap 조건을 만족하는 합법 제안은 `breakdown`으로 종료된다.
- 완전 결렬은 냉각 종료일 이후에도 상태 변화가 없으면 재개되지 않는다.
- `wantsOut`/사유처럼 실제 재계약 효용에 쓰이는 선수 상황이 바뀌면 재개되며 변경 사유가 기록된다.
- 재개 시도와 이전 실패 유형은 save/restore 뒤에도 보존된다.
- 관리 구단의 자발적 협상 취소는 즉시 재시작 가능해 기존 취소 동작을 보존한다.

## B2 이후 남은 D04

다음 독립 단위는 **월즈 종료 후 14일 원소속 독점 재계약과 월즈+14일 계약 만료, 구단의 선수별 조기 접촉권 포기, 15일째 정식 FA 개방**이다. 선수는 합리적 제안을 거절해 한 시즌을 통째로 쉬는 경력 손실도 고려하되 명백한 저평가는 거절한다. 이후 보장액/방출·파산 정산, 선수 동의, 에이전트/구두 약속을 단계적으로 연결한다.


### B2 검증 결과

최종 코드 CI의 `D04_CONTRACT_NEGOTIATION_STATE_ACCEPTANCE`에서 실제 정상 거절은 2027-06-01의 3라운드 종료로 분류됐고 냉각 종료일은 정확히 2027-06-04였다. 동일일과 하루 전 재시도는 save/restore 후에도 차단됐으며 종료일에만 재개됐다.

재개된 두 번째 협상에서 기존 severe-gap 기준보다 효용이 **0.767 낮은** 합법 제안은 `breakdown`으로 판정됐다. 냉각 종료일 2027-06-07에도 시간 경과만으로는 재개되지 않았으며, 선수의 실제 `wantsOut` 및 사유가 바뀐 뒤에만 세 번째 시도가 허용됐다. 감사 기록은 시도 1의 `rejected`, 시도 2의 `breakdown`과 재개 변경 항목을 모두 보존했고 save format 2 저장/복원도 통과했다. 관리 구단 자발적 취소는 선수 거절로 오인되지 않아 즉시 재시작 가능했다.

초기 검증 fixture가 계약금과 보너스를 고정한 채 연봉만 조절해 중간 효용 구간에 도달하지 못했으나, 엔진 임계치/인내 값을 조정하지 않고 합법 계약 조건 조합을 탐색하도록 테스트만 수정했다. 최종 코드 리뷰에서는 첫 협상의 RNG 시드를 B2 이전과 정확히 동일하게 유지하고, 실제 재개 시도에만 attempt suffix를 부여해 기존 창단/협상 분포의 불필요한 변동을 막았다.

같은 최종 CI에서 B1 계약기간, D03 전체 스카우팅, D02 다지역 628일·948 공식 경기·15,644 실제 스크림 블록·78,514 선수·일, regression, world smoke, 2시즌 career 186경기, performance probe, production build가 모두 통과했다. 의료/계약 시장 밸런스 확률이나 기존 회귀 상수는 변경하지 않았다.

**B2만 완료**로 기록한다. D04 전체 완료에는 14일 원소속 독점/15일째 타팀 접촉과 가계약 실효일, 보장액·파산/방출 정산, 선수 동의·에이전트/약속의 후속 독립 작업이 필요하다.


## D04-B3 — 월즈+14일 계약 만료와 원소속 독점/조기 접촉

### 확정 날짜 규칙

- 기준일은 그 해의 **World Championship 최종 경기일**이다. 월즈가 없는 커스텀 월드는 최종 국제대회, 그것도 없으면 최종 일정일을 fallback으로 사용한다.
- 기준일 다음 날부터 14일째까지 기존 시즌 만료 계약은 계속 유효하다.
- **14일째가 기존 계약의 실제 만료일**이고, 이 기간 전체가 원소속 구단의 독점 재계약 기간이다.
- **15일째부터 미재계약 선수는 FA**가 되어 모든 구단과 정식 계약할 수 있다.
- 과거 초안의 “연말 12/31 만료 → 1/1 가계약 발효” 모델은 사용하지 않는다.

### 원소속 구단의 조기 접촉 허용

재계약 계획이 없는 구단은 만료 예정 선수별로 `grantEarlyContact`를 통해 독점 접촉권을 포기할 수 있다.

- 접촉권 포기는 즉시 방출이 아니며, 선수의 현재 팀·기존 연봉·출전권은 계약 만료일까지 유지된다.
- 다음 시즌 팀/선수 옵션이 남은 계약은 옵션 결정 전에 접촉권을 포기할 수 없다.
- 접촉권이 포기된 선수만 타 구단이 독점기간 안에 `early_fa` 협상을 시작할 수 있다.
- 합의가 나도 다음 계약은 15일째에만 발효된다.
- AI 구단도 재계약 필요성이 낮은 선수를 같은 권한/상태 저장 경로로 조기 공개하며, AI 영입 구단도 동일한 관찰·예산·계약 효용 규칙을 사용한다.

### 선수의 무계약 경력 위험

선수는 단순히 요구조건을 못 맞췄다는 이유만으로 현실성 없이 한 시즌을 쉬는 선택을 반복하지 않는다.

- 기존 `offerAcceptanceThreshold`에 오프시즌 무계약의 경력 기회비용을 반영한다.
- 별도의 임의 desperation 상수는 만들지 않고 B1의 기존 기간 효용 단위 `.055`와 B2의 기존 의미 있는 저제안 경계 `.22`를 재사용한다.
- FA 경력이 이미 누적됐거나 전성기 연령대라면 무계약 위험을 더 크게 본다.
- 반대로 `contractOfferReasonable`은 기존 AI 시장이 실제로 쓰던 최저 연봉 배수 `.95 × (1 - medicalRisk × .4)`를 보장급 하단으로 재사용한다. 이 하단보다 낮은 명백한 저평가는 무계약 위험이 있어도 수락하지 않는다.
- 팀 전력, 역할, 시설, 목표, 기간, 관계 등은 기존 `offerUtility`가 계속 판단한다.

### 회계/저장 불변식

월즈+14일에 선수 이동이 발생해도 지난 시즌의 연봉·SFR 결산이 새 로스터로 재계산되면 안 된다. 계약창을 열 때 월즈 종료 시점의 팀별 payroll/regulatory payroll을 스냅샷하고 지난 시즌 재정 결산은 그 값을 사용한다.

접촉권 포기, 미래 계약 합의, 만료일, 발효일, 협상 이력은 기존 `world` 저장 경로를 통과한다. 다음 계약 발효는 기존 원자적 `player.sign`/만료 `player.release` 트랜잭션을 재사용한다.
