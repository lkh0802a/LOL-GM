## 세계 외부 헌장과 세계 내부 규정의 두 층

**이 디렉터리의 규범 조항은 세계 외부에서 승인하는 상위 헌장**이다. 국제·지역사무국, 독립 개최사 등 세계 안의 주체가 유효하게 제정·공표하는 지역/대회별 규정은 해당 세계에 존재하는 **내부 시행 규정**이다. CORE-011·CORE-012는 그 권한과 효력의 관계를 정하며, 내부 기관의 개별 처분·계약·실제 경기 결과는 규정의 제정과 구별한다.

외부 정본에 규정된 초기 세계 상태와 장래 개정 가능한 내용은 동일하지 않다. 예를 들어 지역별 공식 리그의 적법한 형식 변경권은 세계 안에서 행사할 수 있으나, 세계 공통 시장 28일·구단 대회 경기 금지·Worlds 구단 공식 피날레 등은 내부 기관의 임의 개정으로 바꿀 수 없다.

**국가대표 대회는 별도 참가 주체에 따른 정규 체계**로서 NAT-001~010에 따른다. 국가당 복수 대표팀 구성·국가대표 경기의 스토브리그 개최는 허용하되, 국가대표 운영기관/국적/강제 차출·참가 정원·보상액 등 승인되지 않은 세부 권한은 미정으로 둔다.

**UI·UX는 세계 외부 헌장도 내부 시행 규정도 아니다.** 종전 10개 UI 승인 요건은 [제품 명세](../interface-spec/USER_EXPERIENCE_REQUIREMENTS.md)에 전부 보존하고, [80-EXPERIENCE.md](80-EXPERIENCE.md)는 이전 문서 경로를 위한 안내문만 남겼다. UI 조작이 세계 내부의 계약·권한·기록을 새로 제정하지 않는다.

**조항 수는 완성 기준이 아니다.** 현 세계관 조항 116개(기존 103개 + CORE 2개, NAT 10개, PLAYER 1개)와 별도 UI 요구 10개의 문서 연결은 편집 검증치일 뿐이다. 남은 국가대표 제정권·선수 자격·훈련·분쟁·승인 원문 효력의 완결성은 별도 확인이 필요하다. [2026-11-08 신규 13개 조항 추적 대장](../rulebook-audit/CANON_2026_11_08_ADDENDUM.md)은 [2026-11-01 기존 113조 이력](../rulebook-audit/CLAUSE_DECISION_MATRIX_2026_11_01.md)을 소급 덮어쓰지 않는다.

**AI·Codex 작업 안내:** [AI_RULEBOOK_GUIDE.md](../AI_RULEBOOK_GUIDE.md)는 룰북 내용과 별개의 비규범적 탐색·검증 절차다. 규칙 정의는 복제하지 않는다.

**1단계 원문 판정 추가:** [#251 R01~R21 선택 21건](../rulebook-audit/STEP1_R01_R21_SOURCE_ADJUDICATION_2026_11_01.md) 및 [#234 일정·보호 라이선스 후속 효력 16사슬](../rulebook-audit/STEP1_CALENDAR_LICENSE_SUPERSESSION_2026_11_01.md)을 별도 대조하였다. 원문 선택 기록은 기존 380행에 R계열 21행을 더해 **401행**이나, 승인 유효 정책 수 또는 전수조사 완료율이 아니다. 신규 정책 규정의 소급 추가 없이 기확정 COMP-020~021과 직접 승인 원문을 일치 확인했다.

**1단계 전수 수집 현황:** [전체 39개 이슈·612개 댓글·290개 PR·401개 원본 선택 설명 및 승인 효력 종합 대장](../rulebook-audit/STEP1_SOURCE_COMPLETENESS_AND_DECISION_GATE_2026_11_01.md). **원문 색인·당시 개별 선택 내용은 모두 수집·매핑했으나 최신 효력 100% 인증은 미완료.** 실제 사용자 승인에 따른 최종 철회·대체 관계를 모든 출처에 대해 검증할 때까지 정본 최종 발행 금지.

**발행 전 1단계 승인 효력 전수조사:** [승인·철회·미이관 원문 대조표](../rulebook-audit/STEP1_APPROVAL_EFFECT_AUDIT_2026_11_01.md)에서 실제 확인한 선택의 현재 효력과 후속 철회, 누락된 하위 운영 규칙을 추적한다. **113개 상위 조항의 관련 원문 부분대조는 기존 이슈 댓글 610개 및 PR 289건의 선택별 전수 최종 판정을 뜻하지 않는다.** 1단계와 규정 우선순위(2단계), 내부 충돌(3단계), 승인 누락 편입(4단계), 구형 문서 충돌 교정(5단계)이 끝나기 전에는 최종 정본으로 확정하지 않는다.

**발행 전 충돌 검증:** [문서·규정 충돌 대조표](../rulebook-audit/CROSS_DOCUMENT_CONFLICT_AUDIT_2026_11_01.md)에 교정 완료와 잔여 충돌·미확정 적용 범위를 구분한다. 이는 규범 조항이 아닌 감사 기록이며, 검증 완료 전 본 Draft의 정본 확정을 유보한다.

**범위:** 현행 상위·주요 분야별 확정 규칙의 개정 편찬본이다. 이전 GitHub 이슈·댓글의 세부 승인 전체를 전수 이관한 완성본이라고 주장하지 않는다. 해당 도메인 미수록 세부사항은 **사용자가 승인한 원본**에서 확인한다.

## 규정집의 문체와 표현 원칙

규정 본문은 **문어체의 평서형·규정형(‘한다’, ‘할 수 있다’, ‘해서는 안 된다’, ‘적용한다’)**으로 작성한다. 구어적 약칭·비유·감정적 표현 대신 정확한 주체, 객체, 적용 단계, 예외 및 효력 범위를 명시한다. 게임·개발 분야의 표준 전문용어(Fearless Draft, First Selection, MMR 등)는 의미를 유지한다. **문장 교정은 사용자가 승인한 규칙의 의무·권한·금지·예외를 강화하거나 완화하는 근거가 아니다.** 과거 승인 원문과 과거 버전의 변경 이력은 삭제하거나 현재 규정으로 오인하지 않도록 구분한다.

## 게임성과 현실성을 함께 유지하는 규정 편찬 원칙

**실제 세계의 결과는 보존하고, 반복 조작·중복 계산·근거 없는 우발 사건만 제거한다.** 계약·재정·선수·스태프·대회에서 통상적이고 합법적인 일상 업무는 담당 AI/시스템이 자동 처리하되, **자금 부족·권리 충돌·적격성 위반·선수 동의 및 감독에게 위임되지 않은 중대한 선택**은 해당 세계의 실제 제약과 결정권에 따라 처리한다. 자동 집행은 계약상 의무·세계 시간·지급/자원 원장·정보권한을 생략하는 수단이 아니다.

사용자에게는 매번 같은 일을 확인하도록 강제하지 않고 **의미 있는 선택과 필요한 예외만** 제시한다. 간소화로 새로운 무료 자원·승률 보정·허위 사건·자동 성과를 만들어내거나, 유효 계약·당시 기록·선수 권리를 소급 삭제해서는 안 된다. 상세 비용·확률·의사결정 UI는 하위 운영 규정·구현 명세로 관리하고, 상위 룰북에는 영구적인 권한·효력·금지 원칙을 우선 기재한다. 상위 기준은 **CORE-010**, 재정상 적용은 **BIZ-004**에 각각 규정한다. 이 편찬 기준은 2026-11-01 사용자 대화의 간소화 및 게임성·현실성 병행 승인에 근거하며, 다른 기존 승인 조항의 의무를 자동 철회하는 의미가 아니다.

## 수정하더라도 복잡해지지 않는 관리 방법

1. **한 규칙의 정의는 해당 분야 파일 한 곳에만 둔다.** 다른 장은 고유 규칙 ID를 참조하고 동일 문장을 복사하지 않는다.
2. **고유 ID는 영구 유지한다.** 예: `TRANS-001`. 개정하더라도 ID를 재번호 부여하거나 과거 출처를 지우지 않는다. 한 조항의 뜻이 서로 다른 둘로 나뉘는 경우에만 새로운 ID를 추가하고 관계를 남긴다.
3. **실제 변경이 승인된 경우에만** 해당 분야 파일과 [CHANGELOG.md](CHANGELOG.md)를 함께 고친다. 로그에는 변경 조항, 이전/새 버전, **사용자 확정 근거**, 적용 대상·시즌·효력 시점을 적는다. 단순 오탈자/링크 정정은 의미 변경과 구별한다.
4. 이전 결정·원본 계약·대회 역사·당시 규정 버전은 삭제하지 않는다. **게임 내부 사무국의 적법한 차기 시즌 규정 개정**은 해당 저장 세계의 `rulesVersion` / `effectiveSeasonId` 이력에 기록한다. **이러한 개정이 발생할 때마다 본 규정집을 수정하지 않는다.** 이 규정집은 사무국이 따르는 상위 규칙과 정당한 개정 권한을 정한다.
5. 과거 문서·PR/이슈의 제안·개발 TODO·미확정 계수·구현 진행률은 **규정집에 복사하지 않는다**. 출처끼리 충돌하면 후속으로 명시적 승인을 받은 동일 쟁점의 결정을 따르며, 판단 근거가 충분하지 않은 경우에는 **임의 확정해 기재하지 않는다**.
6. `main`에 병합되지 않은 편찬 PR은 **공식 반영 완료로 표시하지 않는다**. 문서 편찬·코드 구현·테스트 합격·실제 게임 적용은 서로 별개다.
