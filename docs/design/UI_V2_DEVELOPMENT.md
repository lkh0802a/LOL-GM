# 새 화면 개발 실행 — 2026-10-15

개발 범위와 승인·출시 기준은 [단일 개발 지침](../DEVELOPMENT.md)의 원래 단계1–13을 따른다. 이 문서는 로컬 개발 명령 설명이다.

`npm run dev:ui-v2`는 `http://127.0.0.1:4174`에서 새 화면만 제공한다. 기존 운영 주소와 별개인 로컬 개발 주소다. `src/ui-v2` 또는 기존 엔진 소스 변경을 감시해 자동으로 다시 조립한다. 브라우저 새로고침은 직접 한다. 작성 중인 조건을 강제로 지우는 자동 새로고침은 하지 않는다. 조립 중이거나 실패한 경우 이전 결과를 최신 결과처럼 제공하지 않고 오류 응답을 낸다. 개발 서버는 원래 게임 서버나 게시 설정을 변경하지 않는다. 종료는 Ctrl+C다.

`npm run check:ui-v2`는 현재 소스로 새 화면을 조립하고 금액·기존 화면 미포함·권한/비서 조회, 선수단 준비/직원, 산하 선수단 선택/검색 복귀, 공식 경기 선택권·밴픽/종료를 차례로 검사한다. 기존 세 검사 파일과 단언을 유지하고 공식 경기/공통 작업 창 검사를 추가했다. 각 검사는 독립 VM에서 실행하고 읽기 전용 엔진 소스와 컴파일 결과만 공유한다. 첫 실패 시 명령은 실패로 끝난다. 원래 `npm run check`·원격 필수 검사·의료7·게시 검사를 대체하지 않는다.

연속 세 검사에서 기존의 별도 실행은 엔진102개를 각 프로세스가 읽고 컴파일하지만 새 실행은102개 읽기·컴파일1회·독립 문맥3개였으며 공식 경기 추가 뒤에는4개다. 실제 결과 기록 전체가 동일한 세 쌍만 비교한다. 개발 검사 준비 시간 측정이며 실제 게임 진행 성능 개선이나 장기 경력 수용이 아니다. 시간은 실행 환경에 따라 달라진다.

현재 환경에서 기존 검사기 `ci-run.test.mjs`는 격리 실행의 자식 프로세스 출력 누락으로2개 단언이 실패했다. 일반 로컬 실행에서는 원래4개가 정상 통과했다. 원래 검사기나 단언은 바꾸지 않았다. 두 실행의 원문/제한을 구분하며 전체 검사 성공으로 소급 치환하지 않는다. 원격은 기존 Node22 설정을 유지한다.

조립 스크립트와 화면 모듈 목록 변경도 감시해 최신 조립 함수를 다시 불러온다. 일반 화면/엔진 소스도 감시해 재조립한다. 개발 서버 스크립트 자체를 수정했을 때만 서버를 재시작한다. 산출물은 임시 파일의 원자적 이름 변경으로 교체해 부분 작성된 HTML이 열리지 않게 한다.

공통 작업 창은 src/ui-v2/dialog.js이며 협상 상세와 검토/비서/직원·준비·밴픽의 단일 창을 연결한다. 목록/상세는 URL로 구분하고 초안·목록 위치·현재 권한을 유지한다. 기능 연결 정적 조사는 `node scripts/audit-feature-connections.mjs /tmp/LOL-GM-connections.json`으로 재현하며 문자열 참조를 기능 완료로 판정하지 않는다.


## 2026-10-22 현재 main 연결과 단일 사이트 교체

사용자 최신 요청으로 PR231 디자인을 우선한다. 최신 main00554b1 엔진을 보존하고 `npm run build`가 새 화면을 기존 index.html/dist/index.html로 조립한다. 기존 Pages의 play.html/LOL-GM.html은 같은 검증 산출물을 사용하며 별도 공개 미리보기를 만들지 않는다. 이 변경 자체는 병합·게시 성공이 아니다.

새 화면은 퇴역한 포인트 배분·독립 강도를 제공하지 않는다. 의료의 정상/제한 활동은 기존 다섯 계획과 실제 작성자/소비자를 유지한다. 엔진 퇴역 작업 PR253의 실패와 미완료는 별도 보존한다. 스크림은 실제 request/cancel·상대 독립 판단·수동 검토와 최종 적용을 사용한다. 예약은 실제 참가나 자원 소비가 아니다.

운영 게임과 동일한 열 슬롯·IndexedDB/localStorage fallback·이전 정상 복구 지점을 사용한다. `ui-v2-browser-storage.mjs`가 기존 app.js/ui-save-library.js의 저장 전용 함수 원문을 조립하므로 별도 저장 writer나 기존 화면 렌더러를 만들지 않는다. 손상/읽기 실패 위치는 새 게임에 쓰지 않으며 이전 UI 시험용 저장도 삭제하지 않는다. 파일 내보내기/가져오기는 기존 복원 검사를 유지한다.

새 화면 집중 검사는 기존14개에 실제 운영 슬롯/실패/순차 쓰기와 스크림 수동 연결 검사를 추가한다. CI의 기존 필수 게이트에 새 화면 workflow를 연결해 단독 중복 실행 없이 verify와 게시 전에 통과해야 한다. 현재 구현/검증 중이며 정확 최종 HEAD 전체·CI·의료7·결과 main·게시 결과는 실제 종료 이후 기록한다. APK/실기기/TalkBack/전체 세계 시즌 수용 주장은 아니다.
