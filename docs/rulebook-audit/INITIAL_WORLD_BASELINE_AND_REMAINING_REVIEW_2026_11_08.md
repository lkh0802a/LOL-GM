# 초기 세계 기준 및 후속 누락·규정 개선 감사 — 2026-11-08

> **비규범적 감사 자료.** 이 문서는 새 조항·시행 규정·실제 게임 데이터를 제정하지 않는다. 권위 있는 세계규칙은 `docs/rulebook/`에, 구현 수용 기준은 `docs/GAME_IMPLEMENTATION_ENTRYPOINT.md`에 있다. 확정된 사용자 선택, 실제 문서 반영, 데이터 준비와 엔진 구현을 구별한다.

## 이번에 확정해 정본에 반영한 원칙

- 첫 시즌에 사무국 AI가 규정을 매번 즉흥·무작위로 만드는 방식이 아니라, **사전에 설계하고 교차 검증한 초기 세계·지역별 운영 체계**를 사용한다. 모든 지역의 제도를 똑같이 할 필요는 없다.
- 처음 설정한 지역별 규정 후보는 실제 세계의 기관이 적법하게 제정·공표·발효해야 한다. 해당 법적 사건이 없이 초깃값을 이미 유효한 법으로 간주하지 않는다.
- 운영 성과·경제 여건·실제 참가 기반이 달라지면 이후 시즌에 권한 있는 기관이 적법하게 개정할 수 있다. 초기값의 존재만으로 영구 고정하거나, 매년 의무적으로 규칙을 개정하지 않는다.
- 기존 저장의 유효 계약·선수 정보·선수 등록·경기 결과·재정 기록은 신규 시작 프리셋으로 소급 덮어쓰지 않는다.
- 실제 본칙은 CORE-012⑦, 구현 계약은 `docs/GAME_IMPLEMENTATION_ENTRYPOINT.md` 제13절, 정본 정적 회귀검사는 `scripts/rulebook-guard.mjs`와 테스트에 분리했다.

'우선 1'은 검토 순서이지 현행 규정의 무효·철회 판정이 아니다. '처리됨 (규범)'은 사용자 선택을 정본 조문에 반영했다는 뜻이며 코드 실행·시행 규정 인스턴스·장기 시뮬레이션의 완료를 뜻하지 않는다. '처리됨'은 기존 조항의 표현·법적 효과 사이의 충돌을 바로잡았다는 뜻이지 새로운 예외·수치·이적권을 승인했다는 뜻이 아니다. '기술 검증'은 법규 개정 보류가 아니라 승인된 규칙을 실제 달력·세계 시간에 구현하는 데 필요한 안전성 시험이다. '출처 대조·수용 검증'과 '명료화'는 확인한 규칙을 유지하거나 중복 계수 위험을 제거한 상태이며, 임의로 정책 값을 변경했다는 뜻이 아니다. 위 후보의 실제 수정 여부는 선행 사용자 승인과 후속 변경의 최신 효력 및 해당 영역의 수용 사례를 대조해 결정한다. 아직 승인되지 않은 새 숫자·예외·판정법을 정본에 삽입하지 않는다.

## 확인할 회귀 사례

1. 같은 초기 설정·시드로 만든 두 세계는 초기 유효 대회·지역 규정과 계약·원장 상태가 동일해야 한다.
2. 서로 다른 두 지역이 다른 리그 포맷을 가지더라도 세계 선수시장·국제대회·단일 시각과 등록이 충돌하지 않아야 한다.
3. 초기 시행 규정이 미공표라면 `NEEDS_RULE`, 선수의 실제 국적이 미확인이라면 `NEEDS_FACTS`, 장래 규정이 아직 미발효라면 `NOT_EFFECTIVE`로 처리한다.
4. 기존 저장을 불러온 경우 새 초기 프리셋이 그 세계의 유효 계약·경기 역사·재정 원장을 다시 만들지 않아야 한다.
5. 정당한 운영 성과 변화 뒤의 다음 시즌 개정은 권한·공표·시행 시각을 검증하고, 초기 시즌의 결과에는 소급하지 않아야 한다.

## 검증 경계

이번 편찬·검사기 수정은 **문서/정적 회귀검사 변경**이다. 실제 초기 세계 데이터 인스턴스 생성, Rust 엔진 입력, 100시즌 장기 자동 운영, 기존 저장 파일 마이그레이션, 정확 HEAD 전체 CI 및 최종 main 병합은 각각 별도 검증 대상이다. 기존 401개 선택·원본 댓글/PR 전체의 최신 승인 효력 인증도 아직 완료로 처리하지 않는다.
