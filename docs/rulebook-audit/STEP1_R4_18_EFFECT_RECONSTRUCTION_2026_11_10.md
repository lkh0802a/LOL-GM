## 직접 후속 교정과 구분해야 할 사건

1. **R4-190 3단계 정정:** 190B는 사용자 추가 의견으로 당시 보류 → 뒤이어 190A '모든 참가자 실명+닉네임 공개'라고 기록됐지만 → **직접 사용자 재정정이 이전 해석을 철회**. 최종 PLAYER-006은 **세계 인물 한 명당 랭크 계정 하나, 닉네임 변경 불가, 계정 주인 식별 가능**이며 별도 '현실 본명/실명' 필드 생성·병렬 노출·익명 신원해금은 금지. 비공개 실제 능력·내부 MMR/의료/타 구단 정보는 보호.
2. **R4-149 공식 개최와 R4-155 리그 재편:** 공식 기관 간 공동 주관 대표가 필요하다면 적법한 책임 주체의 최종 권한을 보존하며, 독립 개최사가 공인받았다는 이유로 공식 사무국을 대체하지 않는다. 재편 이후에도 구단은 새 자격을 실제 심사받지만 기존 계약/역사/선수 ID와 정당한 전환 책임이 자동 삭제되는 것은 아니다.
3. **R4-171·172·174 랭크 수학:** 승패를 핵심으로 팀 MMR/파티 불균형을 **중복 보정하지 않고**, 직전 팀원 매칭의 특별 선호·회피는 두지 않으며, 동점 RP 선수는 공동 세계 공식 순위를 갖는다. PLAYER-003·004에서 구분. 챔피언/팀워크·후속 공식 경기 능력에는 근거 없는 고정 RP→실력 즉시 보너스 부여하지 않는다.
4. **R4-177·178·180 계약 원자성:** 선수 맞교환·추가 이적료/분할금/옵션은 해당 계약의 실제 당사자와 지급/등록/시간을 합법적으로 확인해 한 번만 확정한다. 대리인 변경 시 **아직 서명되지 않은 제안**과 이미 확정된 계약의 효력을 구별한다. 대리인 변경을 소급 금전 채무 삭제/무제한 제안 부활로 사용 금지.
5. **R4-185/187/188/195/199/202/204/218은 실제 지급·UI/제품 수용:** 현실 시간 카운트다운을 강요하지 않되 게임 세계 내 밴픽 시계·서명권·Fearless/First Selection은 유효. 재정 전망 1·3·6·12개월은 미래 확정 현금으로 전환하는 권한이 아님. 실명 없는 당대 닉네임 역사·명예 기록과 선택형 기념 콘텐츠를 보존한다.
6. **R4-185 취소 표현의 후속 효력:** 185D는 과거 취소 환불 채무의 지급기한을 다루며 기술·방송 사고로 취소 사건을 만들지 않는다고 명시했다. 후속 확정 회차 운영은 COMP-010의 사전 자원 확보와 확정 후 운영을 따른다. 제공하지 않은 계약상 급부 등에 대해 실제 발생한 적법 환불·채무까지 없애지는 않는다. 후속 직접 대화 원문 독립 열람은 `UNKNOWN`이며 정본 완결 판정은 보류한다.

## R4-155 구현·검증 추적

- [승인 원문 155A](https://github.com/lkh0802a/LOL-GM/issues/251#issuecomment-6246141985)과 `docs/rulebook/70-GOVERNANCE.md`의 GOV-008은 재심사와 기존 권리·역사 보존을 함께 요구한다. 예를 들어 통합 대상 구단이 기존 구단이라는 이유만으로 새 자격을 자동 취득하거나, 재심사 실패를 이유로 과거 우승·유효 계약을 소급 삭제하는 결과는 각각 이 요구에 어긋난다. 기존 승강·산하 2군 처리는 리그 통합 자체와 구별한다.
- 기존 `src/artifact/office-international.js`의 `regional-merger` 분기는 대상 구단을 이동시키고 지역 승계·삭제를 기록한다. `src/artifact/region-continuity.js`의 이동 함수는 기존 구단·산하팀의 지역과 이력을 바꾸고 `syncClubLicense`를 호출한다. `src/artifact/club-license.js`의 `clubLicenseState`는 활성 구단의 상태를 `approved`로 산출하며 목적지 유형을 기록한다. 이 경로에서 심사 결과나 불승인 분기는 확인되지 않는다. 예를 들어 목적지 자격 미충족인 활성 구단을 입력하더라도, 별도 호출 경로가 차단하지 않으면 유형 동기화만으로 승인 상태가 될 수 있다. 미충족 구단 실실행 반례와 전체 호출 경로 검증은 `NOT_RUN`이므로 전체 정합성 판정은 `UNKNOWN`이다.
- `node scripts/region-license-observation.mjs`: 합성 세계의 활성 구단에 가상의 `rejected` 상태를 직접 넣고 직렬화·복원한 다음 이동 함수를 호출한 관찰에서 `before=rejected`, `afterLoad=rejected`, `afterMove=approved`, `destination=EU`, `reason=regional-merger`가 출력됐다. 합성 입력은 복원되지만 이 상태가 실제 게임에서 적법하게 생성 가능한지, 실제 목적지 자격이 불충족인지, 별도 상위 경로에서 차단되는지는 확인하지 않았다. 특정 자격 요건이나 진단 결과를 새 세계법으로 확정하지 않는다. 실제 사용자 저장이나 이관의 검증 결과가 아니다.
- `scripts/region-continuity-acceptance.mjs`는 합성 세계에서 실제 재편 함수를 호출하여 산하팀·계약·재정·역사 스냅샷, 승계 이력 및 합성 저장 재로드를 확인한다. `scripts/club-license-acceptance.mjs`는 이동 후 목적지 유형과 라이선스 이력을 확인한다. 두 스크립트를 직렬 실행해 각각 PASS했지만, 자격 미충족 구단의 심사·불승인 여부나 실제 사용자 저장은 검증하지 않는다.
- `scripts/rulebook-guard.mjs`는 GOV-008 문구를 정적으로 보호한다. `scripts/rulebook-guard.test.mjs`의 변형 반례는 재심사와 완료 경기·우승 역사 보호 문구의 삭제를 검출한다. 이는 문서 검사이며 재편 엔진의 심사·실제 저장 원자성에 대한 실행 증거가 아니다. 리빌드 구현 전 부적격 구단·실제 계약·기록을 포함한 검증과 사용자 저장 원본 보존이 필요하다.

## R4-190 초기 이름 입력 경계

- [#251 최종 정정](https://github.com/lkh0802a/LOL-GM/issues/251#issuecomment-6246200434)은 1인 1계정·불변의 고유 닉네임·안정 인물 연결을 요구하며, 실명 병기 의무는 철회한다. [#250](https://github.com/lkh0802a/LOL-GM/issues/250)의 무검사 난수 fallback은 별도로 이미 알려진 미수정 문제다.
- `src/artifact/player.js`의 `genPlayer`는 이름이 직접 제공되면 `uniqNick`을 호출하지 않고 사용한다. `src/artifact/world.js`의 초기 선수 데이터 로딩이 이 직접 이름 경로를 사용한다. 초기 데이터가 실제로 중복됐다는 뜻은 아니다.
- `node scripts/seeded-nickname-observation.mjs`의 기본 합성 세계는 1,846명 중 중복 닉네임 0건이었다. 별도 복사본에 기존 이름을 직접 지정하여 선수를 추가하자 서로 다른 ID 2개가 같은 이름을 가졌고 합성 저장 복원 후에도 2개가 남았다. 원본 합성 바이트는 불변이었다. 이는 강제 입력 반례이며 실제 사용자 데이터·다른 초기 설정·장기 세대의 충돌 빈도는 `UNKNOWN`, 게임 수정·실제 저장 이관은 `NOT_RUN`이다. 기존 이름과 역사를 임의로 바꾸지 않는다.
