### R03 기존 구현 관찰 — 닫힌 이적창과 의무매입

- [TRANS-008](../rulebook/30-TRANSFERS.md)은 매입 의무 발생과 완전이전·등록 효력을 구분하고, 유효한 시장·지역 창·명시적 예외가 없으면 의무를 기록하면서 이전을 보류한다. 임대 종료부터 합법 이전까지의 급여·의료·활동 책임은 실제 계약/관할 규정으로 판단해야 하는 R03의 미확정 경계이며 여기서 임의 확정하지 않는다.
- 기존 `src/artifact/loan-purchase.js`의 `validateLoanPurchase`는 만료·당사자·재정 등을 검사하지만 `permanentTransferWindowError`를 호출하지 않는다. `scripts/loan-closed-window-observation.mjs`는 합성 지역의 공표 창을 1월 7~31일로 설정하고 2027-07-01 만료 의무매입을 관찰한다. 같은 합성 상태에서 이적창 함수는 닫힘을 반환했지만 시스템 매입 명령과 `processLoanDaily`는 각각 임대를 종료하고 이적료 2를 정산했다. 명령 경로의 새 급여 30·매입 이력과 합성 원본 불변을 확인했다.
- **만기 자금 부족의 독립 경계:** 같은 진단은 임대 계약 당시 1000이었던 매입 구단 현금을 만기 합성 복사본에서만 0.5로 낮춰 이적료 2의 의무매입을 실행한다. 닫힌 창에서 명령은 성공했고 지급 구단 현금은 -1.5, 수령 구단은 1000→1002, 임대는 종료되고 새 급여는 30이었다. 합성 저장 복원 후에도 이 값이 유지됐다. 별도 복사본에서 창만 7월 1~14일로 바꾼 대조군도 창 검사는 통과하고 현금은 -1.5가 됐다. 현금 변경은 통제된 입력이지 실제 지출·사용자 자금의 증거가 아니다. 관측값을 정상 수용 결과로 고정하지 않는다.
- 코드 연결: `validateLoanPurchaseTerms`는 의무매입 약정 **시점**의 자금을 확인하지만 `validateLoanPurchase`의 만기 현금 검사는 선택권에만 적용된다. 매입 `apply` → `settleTransferSigningFee` → `payFinancePrepaid`는 부족액을 별도 청구 원장으로 분리하지 않고 선지급액을 현금에서 차감한다. 반면 기존 분할 청구의 `validateTransferPayment`는 실제 현금 한도로 지급액을 정한다. [BIZ-004](../rulebook/60-BUSINESS.md)의 확정 의무·부족분 미지급·무근거 당좌대월 금지와 대조가 필요한 구형 경로다. 계약서상 지급일·담보/예약 재원·상계·유효한 대출 및 금전·소속 효력의 관계는 이 합성 fixture에서 제공하지 않았으므로 법적 결과와 실제 손실은 **UNKNOWN**이다. 계약 및 유효 재원/기한을 가진 별도 fixture로 충분·부족·분할 지급, 중복 처리, 저장 복원과 창/등록 경계를 독립 검증해야 한다.
- **합성 중복 실행과 복원:** 위 닫힌 창 의무매입 진단에서 이미 이행된 합성 건에 동일 `player.loan-purchase` 명령을 다시 적용하자 매입 합의 없음으로 거부됐고 전체 `packDB` 바이트는 불변이었다. 이행 직후 저장을 복원한 복사본에 같은 명령을 재실행해도 동일하게 거부되고 복원 전후 바이트는 유지됐다. 일일 처리 경로도 첫 처리 후 같은 상태에 다시 적용했을 때 바뀌지 않았다. 자금 부족으로 합성 현금이 음수가 된 별도 사례도 저장 복원 후 중복 명령은 거부되고 상태가 유지됐다. 이 사례는 중복 차감 방지의 제한된 관찰이며, 첫 이행이 닫힌 창에서도 발생한 위 충돌을 정당화하지 않고 실제 계약·동시 실행·중단 중 복구·모든 의무매입의 수용을 증명하지 않는다.
- **기존 확정액과 신규 약정의 별도 관찰:** `node scripts/loan-commitment-observation.mjs`는 합성 임대 의무매입 2가 이미 있는 구단의 현금을 3으로 설정한다. `financeCommittedTransferCash`는 기존 2를 표시하지만 `validateLoanPurchaseTerms`는 신규 의무매입 2를 수락했고, 실제 `player.loan` 명령도 성공하여 총 약정액 4가 됐다. 합성 저장 복원 뒤에도 4였으며 원본 복사 전 저장은 불변이었다. 대조군은 현금 1.5에서 신규 약정을 거부했다. 각 계약의 지급기한·재원·다른 수입과 적법한 신용은 주어지지 않았으므로 **총 약정액이 현금보다 크다는 사실만으로 위법·실제 손실 또는 예약 현금 존재를 단정하지 않는다**. 이는 기존 validator가 신규 약정을 개별 현금과 비교하는 경로와 기존 확정액 표시의 차이를 보여 주는 합성 관찰이다. 만기별 실제 현금흐름·계약상의 재원 확보·지급 우선순위·부족분 원장은 별도 `NOT_RUN`이다.
- **분할 약정의 선지급·만기 지급 대조:** `scripts/loan-closed-window-observation.mjs`에 동일 합성 임대의 별도 분할 약정(총 2, 전환 시 1, 8월 1일 1)을 추가했다. 계약 당시 현금 1000을 만기 복사본에서 0.5로 직접 낮추고 닫힌 창의 의무매입을 실행하면 전환이 성공하고 현금은 -0.5가 되며 나머지 1은 pending 청구로 기록됐다. 이후 날짜를 직접 8월 1일로, 현금을 0.4로 각각 설정한 뒤 `processTransferPayments`를 호출하면 0.4만 지급되고 현금 0, 청구는 `earned`·기지급 0.4였다. 저장 복원 후 같은 날짜의 재처리는 불변이었다. 즉 이 입력의 선지급과 분할 청구 지급은 서로 다른 현금 부족 처리 경로를 가진다. 합성 현금 투입은 실제 수입·대출이나 계약상 담보를 재현하지 않으며, 실제 일별 진행·연체 해결·사용자 저장은 NOT_RUN이다. 법적 지급 순서나 계약 효력을 이 관찰에서 새로 확정하지 않는다.
- **잔여 청구의 합성 회수와 복원:** 위 0.4 부분 지급 저장을 별도 복원하고 날짜를 9월 1일로 이동시킨 다음 구매 구단 현금을 시험용으로 0.6으로 직접 설정해 같은 정산 함수를 실행했다. 잔여 0.6 지급 후 구매 구단 현금 0, 판매 구단 현금 1001.4→1002, 양쪽 같은 청구 행의 기지급 1·`paid`가 관찰됐다. 다시 저장·복원하여 같은 날짜에 처리해도 저장 바이트는 변하지 않았고 원 합성 저장도 불변이었다. 후속 자금은 외부에서 주입한 통제 입력이며 실제 수익·계약의 지급 우선순위·연체 이자·다른 채무와의 경합 또는 실제 회수를 증명하지 않는다. 최초 전환 시 -0.5가 발생한 구형 경로도 해결하지 않는다.
- **정본 문구 보호:** `scripts/rulebook-guard.mjs`는 TRANS-008의 닫힌 창에서 성립한 금전·이행 책임을 기록하면서 이전·등록을 보류하는 문구와 BIZ-004의 무근거 자동 당좌대월·제3자 대납 금지를 각각 검사한다. `scripts/rulebook-guard.test.mjs`는 이 두 문구를 반대로 바꾼 변형을 거부한다. **정적 문서 검사만 추가한 것이며 위 구형 매입 동작은 수정하거나 정본에 적합하다고 판정하지 않았다.**
- 인접 `scripts/loan-calendar-acceptance.mjs`는 기존 임대 만료·매입 처리의 회귀를 검증하지만 이 반례가 정본에 적합하다는 뜻은 아니다. 사용자 저장·실제 계약·실제 예외의 존재, 계약의 브리지 책임 및 Rust 이관은 `NOT_RUN`/`NEEDS_FACTS`다. 해당 합성 결과를 정상 규칙으로 고정하거나 사용자 저장을 수정하지 않는다.

### R05 기존 상금 계획의 근거 경계

- [COMP-019](../rulebook/10-COMPETITIONS.md)은 Worlds 공동 정규순위의 미확정 차등 상금에 사전 공표 기준이 없으면 해당 차등분을 보류하면서 이미 확정된 채무는 보호한다. 어떤 분배 비율이나 실제 채무가 존재하는지는 대회별 규정·계약의 사실 확인이 필요하다.
- 기존 `src/artifact/finance-closeout.js`의 `financeCloseoutPrizes`는 완료 대회마다 대회 종류/지역에 따른 재원과 `elimReach` 가중치로 계획을 계산한다. `node scripts/prize-plan-observation.mjs`에서 상금 조건을 별도로 넣지 않은 합성 지역 2팀 대회를 실제 한 경기로 완료한 뒤 계획을 조회하면 두 구단에 양수 금액이 계산됐고 조회 전후 합성 세계는 동일했다. 이 진단은 `closeFinances`를 호출하거나 현금을 지급하지 않는다.
- **합성 결산·복원 추가 관측:** `node scripts/prize-settlement-observation.mjs`는 같은 합성 지역 2팀·실제 한 경기 완료 상태를 복사하고, 비교본에서만 해당 시즌을 제거한 뒤 동일 결산 시드로 `closeFinances`를 각각 호출했다. 상금 조건을 넣지 않은 대회가 있는 쪽의 두 계획은 약 3.0130·3.9170, 원장 상금과 비교본 대비 현금 차이는 반올림된 3.0·3.9였으며 비교본의 상금 항목은 0이었다. 동일 연도 중복 결산은 상태를 바꾸지 않았고 합성 원본 불변 및 합성 저장 복원 뒤 원장 상금 보존을 확인했다. 다른 수입·비용과 합성 정산의 차이를 통제한 관찰이며, 대회 주최자의 확정 채무·재원이나 실제 사용자 자산의 존재를 의미하지 않는다.
- **합성 동률 성적 추가 관측:** `node scripts/prize-tie-observation.mjs`는 2팀·2경기·BO1의 *간소화된 지역 관측 전용 대회*를 최대 20개 결정적 대회 시드로 실행해 양 팀이 실제 1승 1패·세트 1승 1패·상대전적 0인 사례(`prize-tie-1`)를 얻었다. 기존 `league-aggregation.js:rrTable`은 남은 동률에 시드 해시를 사용하며 대회 종료 경로는 그 순서로 우승/준우승을 기록한다. `financeCloseoutPrizes`·`closeFinances`는 상금 조건을 제공하지 않은 합성 사례에 각각 원장 상금 3.0·3.9를 기록했고, 복사 전 합성 원본과 중복 결산은 불변, 합성 저장 복원 뒤 원장은 같았다. **이 관측은 현행 정본에 적법한 지역 포맷·결정 규정이 존재한다는 주장도, Worlds의 다섯 지표·경계전·확정 채무를 재현한 실험도 아니다.** 형식상 축소한 대회와 기존 우승자 자동 판정을 현행 수용 기준으로 고정하지 않는다.
- **종료 대회의 현재 참가 목록 변경 관측:** `node scripts/prize-history-observation.mjs`는 합성 2팀 대회의 실제 한 경기를 완료한 뒤 동일 원본에서 두 복사본을 만들고, 한 복사본의 *현재* 대회 참가 목록에서 당시 참가 `NS`만 미참가 `NMT`로 교체했다. 당시 `formatSnapshot.teams`는 양쪽에서 그대로다. 기존 `financeCloseoutPrizes`는 당시 스냅샷 대신 `db.competitions[season.comp].teams`를 읽어, 변경 전 `NS` 계획 약 3.917·`NMT` 없음에서 변경 후 `NS` 없음·`NMT` 0.63으로 계획을 바꿨고, 결산 원장에는 각각 3.9→0·0→0.6이 기록됐다. 합성 저장 복원 후 과거 스냅샷과 결과 원장, 합성 원본 불변을 확인했다. **실제 팀 교체·이미 확정된 상금 채무·Worlds 공동순위의 발생 증거가 아니다.** 당시 참가 기록/기확정 채무 보존이라는 CORE-002·COMP-019와의 정합성 확인을 위한 반례이며, 현재 목록 변경을 자동 상금 권리 이전으로 확정해서는 안 된다. 관측 스크립트는 이 차이가 존재해야만 통과하도록 고정하지 않는다.
- **구형 오프시즌 호출 순서 관측:** `runOffseason`은 기존 `promotionRelegation` 뒤 `closeFinances`를 호출한다. `node scripts/prize-offseason-observation.mjs`는 이 두 함수를 같은 순서로 **합성 복사본에서 직접 호출**했다. 축소된 2팀·실제 한 경기의 `split=3` 합성 대회와 2부 없는 강등형 지역에서, 별도 승강 결정전 없이 구형 경로가 패배 구단 `VXG`를 비활성화했다. 과거 참가 스냅샷은 그 구단을 유지하고, 상금 계획은 처리 전후 약 3.013이었으나 `closeFinances`의 `activeTeams` 결산 뒤 그 구단의 해당 연간 이력 건수는 0→0이었다. 합성 저장 복원에서 비활성 상태·이력 건수와 합성 원본 불변을 확인했다. `runOffseason` 전체·승강 결정전·실제 대회 규정·상금 계약/확정 채무·청산 정산 및 사용자 저장은 실행하지 않았다. 특히 **별도 실경기 없는 승강/해체는 현행 COMP-016의 합법 경로로 승인한 것이 아니며**, 이 구형 현상을 정상 수용 규칙으로 고정하거나 확정 채권 손실로 단정하지 않는다.
- **실제 함수의 스플릿 전환 경로 관측:** `node scripts/prize-split-transition-observation.mjs`는 축소된 합성 첫 스플릿의 실제 한 경기 종료 후 복사본에서 `foldTeam`으로 참가 `NS`를 종료하고 `advanceStep`을 호출했다. 실제 전환 함수가 같은 대회 ID를 새 `leagueComp`로 교체해 현재 목록이 `VXG,NMT,YFD`가 됐지만, 완료된 첫 스플릿 스냅샷은 `VXG,NS`를 유지했다. 기존 상금 계획은 전환 전 `NS` 약 3.013에서 전환 후 `NMT,YFD` 각 약 0.462로 바뀌었고, **두 번째 스플릿이 진행 중인 합성 상태에서 `closeFinances`를 직접 호출**하자 첫 스플릿 미참가 `NMT`의 원장 상금은 0.5, 종료 `NS`의 신규 결산 원장은 없었다. 합성 원본 불변, 합성 저장 복원 후 과거 참가 스냅샷·NMT 상금 값 보존을 확인했다. **정상 연간 결산의 실행 순서·전체 시즌, 합법적 구단 종료, 확정 상금 채무·Worlds 공동순위·실제 저장은 재현하지 않았다.** 현행 규칙 위반이나 사용자 손실을 확정하지 않으며 이 수치를 규칙으로 고정하지 않는다.
- **기존 연간 결산 전체 호출 관측:** `node scripts/prize-annual-close-observation.mjs`는 합성 4팀·단일 라운드 BO1 대회의 실제 6경기를 모두 실행한 뒤 같은 합성 저장을 두 번 복원했다. 각 복사본을 오프시즌 상태로 둔 후 한쪽에서만 비우승·비준우승 참가 `NS`를 `foldTeam`으로 통제 종료하고 두 복사본에 실제 `runOffseason` 전체를 호출했다. 양쪽 계획은 결산 전 NS 약 0.2772였으나, 종료하지 않은 쪽의 연간 상금 원장에는 0.3이 기록되고 종료한 쪽에는 해당 연도 원장이 없었다. 두 복사본은 시장 단계로 이동했으며, 종료 복사본의 합성 저장 복원 후 당시 참가 스냅샷 보존과 연간 결산 재호출 불변, 합성 원본 보존을 확인했다. 이 축소 포맷은 승인된 실제 지역·Worlds 대회를 주장하지 않으며, 대회 종료 후 구단 종료의 **법적 근거·청산 의무·확정 상금 채무**를 주입하거나 판정하지 않았다. 결과는 해당 구형 경로의 합성 관측으로만 보존하고 실제 사용자 채권 손실·R05 전체 위반·다중 스플릿 연간 수용으로 승격하지 않는다.
- **합성 이적료 채권과 상금 경로 분리:** `node scripts/prize-estate-invoice-observation.mjs`는 위 4팀·실제 6경기 축소 대회에서 구단 종료 전 기존 `settleTransferSigningFee`로 **합성 이적료 분할 청구 2**를 거래 양측 원장에 생성했다. 이는 선수 이적 자체를 실행한 사실이나 승인된 상금 채권을 뜻하지 않는다. `foldTeam`·`runOffseason` 이후에도 분할 청구는 양측 pending이었고, 세계 날짜를 **직접** 2028-01-07 만기로 옮겨 `processTransferPayments`를 호출하자 양측 paid 2, 종료 구단 현금 약 14.1→16.1, 지급 구단 98.5→96.5가 기록됐다. 이 사례에서 추가 청산 분배액은 0이다. 복원 후 중복 지급 처리는 불변, 합성 원본은 보존됐다. 같은 합성 결과의 기존 상금 계획 약 0.2772는 비교본 연간 상금 0.3과 달리 종료 구단에 새 연간 원장이 없었다. 인접 `club-estate-acceptance.mjs`는 기존 이적료·방출채무의 재원 예약, 분배·롤백·복원을 별도로 검사한다. **이적료 원장 동작이 미확정 상금을 확정 채권으로 만들거나 실제 구단 종료·상금 지급 의무를 입증하지 않는다.** 실제 계약·적법한 종료·주최자 채무·일별 세계 진행·사용자 저장과 R05 전체 수용은 미실행이다.
- **확정 상금의 입력·지급 경로 추적:** COMP-019는 공동순위의 *미확정 차등분*만 보류하고 기확정 채무는 보호하며, [BIZ-004](../rulebook/60-BUSINESS.md)는 유효 계약·지급기한·지급자의 가용자금과 미지급 채무를 구분한다. 아래는 해당 수용 조건에 필요한 근거와 확인한 기존 코드의 연결 범위다. 기존 코드 전체에 다른 구현이 절대 없다는 증명이 아니다.

  후속 구현 전 확인할 것은 당시 공표·계약 원본과 후속 결정, 지급자 및 채권자 식별, 확정액·기한·가용 재원, 미확정 차등분의 보류 및 분쟁 근거다. 재현 fixture는 이 사실을 명시적으로 제공하고 충분/부족 자금, 중복 결산, 저장 복원과 종료 구단 채권을 각각 검증해야 한다. 없는 계약이나 분배 비율을 채워 넣지 않는다. 현재 이 조건을 가진 fixture와 실제 저장 검증은 **NOT_RUN**이다.

- **조건부 저장 이벤트 소비자:** 현행 `negotiation-final.js:officialQueuedGameError`는 `s.patchLock`이 있으면 현재 엔진에 정의가 없는 `internationalMatchPatch`를 호출한다. `node scripts/patch-lock-reference-observation.mjs`는 별도 합성 이벤트에서 앞선 자원·시간 검사를 **stub으로 통과시켜** 이 분기만 호출했고 `ReferenceError: internationalMatchPatch is not defined`와 합성 DB 불변을 관찰했다. 이는 실제 생성·복원된 진행 경기나 실제 사용자 저장에서 해당 분기가 도달 가능하다는 증거가 아니다. 저장 호환성 판단에는 유효한 생산 경로, 과거 저장 provenance, 원본 보존·실제 복원 및 이벤트 재개 검증이 필요하다. 함수 부재를 임시 fallback이나 구형 저장 자동 변경으로 덮지 않는다.
- **실제 엔진 경기 작성자와 합성 저장 대조:** `node scripts/patch-lock-save-observation.mjs`는 합성 지역 세계의 실제 `prepareOfficialClockGame`으로 경기 이벤트를 준비하고, `packDB`/`unpackDB` 대조군의 `officialQueuedGameError`가 통과하는지 확인했다. 다른 복사본의 해당 시즌에만 가상의 `patchLock` ID·날짜를 **직접 주입**해 저장·복원한 후 `playOfficialGamesThrough`를 호출하면 앞선 검사를 stub하지 않아도 같은 `internationalMatchPatch` ReferenceError가 발생했다. 복원 상태의 저장 바이트와 별도 합성 원본 저장 바이트는 각각 불변이었다. 준비 이벤트의 관측 패치 ID는 이 입력에서 없었고, 주입 ID는 실재·공표된 지정판이 아니다. **현행 작성자가 patchLock을 생성했다거나 이 데이터가 적법한 과거 저장이라는 증거는 아니다.** 과거 배포 provenance·실제 저장의 해당 필드·경기 패치 원본은 계속 UNKNOWN이다.
- 후속 수용은 **실제 승인된 지정판·대회 시작 및 해당 판에 존재하는 챔피언**을 fixture로 제공하고, 국제/지역 공식 경기와 연습을 구분해 세계 정기 패치 전후의 경기 입력·풀·과거 결과·저장 복원을 비교해야 한다. 철회된 사고·임시 밴이나 핫픽스를 되살리지 않는다. 현재 개별 검사는 실패했고 실제 사용자 저장, 적법한 대회별 지정판·전체 정본 적합성은 `NOT_RUN`/`UNKNOWN`이다. 기존 테스트 제거·예상값 완화 또는 다른 브랜치 결과로 대체하지 않는다.

### C17 초기 영입 정보와 요구액 생성의 경계

### C29 사치세와 플로어의 산정 범위

- [#237의 2026-10-22 사용자 승인 기록](https://github.com/lkh0802a/LOL-GM/issues/237#issuecomment-6337472531)은 **캡·사치세는 상위 5명**, **플로어는 실제 비용 부담 선수단 전체**를 구분하고 임대 분담의 이중 집계를 금지한다. ### C31 공식 시리즈 선택권과 Fearless 이력

- [MATCH-002](../rulebook/50-MATCH.md)과 [#311·#234 원문 색인](CLAUSE_DECISION_MATRIX_2026_11_01.md)은 첫 세트의 대회 맥락별 권리, 다음 세트의 직전 패자 권리, Fearless 사용 이력과 실제 선택 보존을 구분한다. 국내 홈/시드와 국제 녹아웃 코인 토스는 서로 다른 맥락이며 이 색인은 원대화 후속 효력 전수 인증이 아니다.
- `competition.js:scheduledSeriesOptions`는 국내 라운드로빈에 `home`, 국내 플레이오프에 `seed`, 국제 녹아웃에 `coin`을 선택한다. `series.js:createSeriesSession`은 home/seed 입력에서 첫 인자를, coin 입력에서 시드 기반 선택자를 정하고 `playSeriesSessionGame`은 다음 선택자를 직전 패자로 갱신한다. 호출 측의 첫 인자가 실제 해당 대회의 홈/상위 시드인지와 코인 토스 이력은 각 대회별 별도 검증이 필요하다.

### B03 국제 성적의 당시 규정과 보관 시점

- [COMP-015](../rulebook/10-COMPETITIONS.md)는 시즌 개막 전 지역별 출전권을 공표하고, [구현 진입점 §12](../GAME_IMPLEMENTATION_ENTRYPOINT.md)는 초기 대회별 가중치·성적 점수와 당시 규정/지역 이력을 보존하며 적법한 후속 규정은 효력 발생 **이후**에 적용한다. 초기 숫자는 불변 세계법이 아니다. 해당 초기 규정의 실제 제정·공표·효력과 직접 대화 원문 전수는 별도 `UNKNOWN`/`AUDIT_PARTIAL`이다.
- `src/artifact/season.js:recordInternationalResults`는 완료 대회의 당시 지역 스냅샷이 없으면 기록을 만들지 않고, 이미 보관한 event ID는 다시 기록하지 않는다. 다만 **처음 보관할 때의** `internationalPolicy(db)`에서 대회 가중치와 성적 점수를 읽는다. `office-international.js:globalOffice`가 이 함수를 호출한다. 기존 `scripts/international-coefficients-acceptance.mjs`는 당시 지역 보존·저장·중복·3년 창을 검사하지만 대회와 최초 보관 사이에 효력이 다른 정책이 존재하는 상황은 이 검사에서 구성하지 않는다.
- `node scripts/international-policy-timing-observation.mjs`는 똑같은 합성 완료 대회와 우승자를 두 복사본에 두고, 최초 보관 전 한 복사본의 가중치/우승 점수만 3/8에서 1/4로 직접 바꾼다. 기준본은 3/8, 변경본은 1/4로 보관됐다. 보관 뒤 가중치를 2로 다시 바꿔 재호출하고 저장을 복원해도 변경본 기록은 1개·1/4로 유지됐으며 원본 합성 저장은 불변이었다. **직접 설정 변경은 실제 권한 있는 정책 공표나 실세계 시간 진행이 아니다.** 이 사례는 최초 보관 당시 설정에 대한 의존성과 보관 후 중복 방지의 차이를 보여 주며, 실제 사용자 이력의 소급 변경을 증명하지 않는다.
- **지역 점수 소비 대조:** 같은 두 합성 보관 결과를 `internationalRegionRatings`와 `compareInternationalRegions`에 넣으면 우승 지역 KR 점수는 기준 1.5, 변경 1.0이었고 지역 순서의 첫 두 항목은 각각 KR·CN과 CN·KR이었다. 변경본을 이후 설정 변경·재호출·저장 복원해도 변경본의 점수와 순서가 유지됐다. 이 값은 해당 합성 대회 하나와 참가 지역 구성에서 나온 것이며 실제 정책 발효, 실제 랭킹 변동이나 출전권 재배분을 실행·증명한 것은 아니다.
- 후속 수용에는 권한·공표일·효력 시각이 있는 실제 규정 버전, 대회 시작/완료/보관 시점, 당시 참가 지역·실제 결과와 이전 기록을 제공한다. 사전 효력·미발효·대회 후 개정·이미 보관된 사건·스냅샷 없는 구형 저장을 구분하고, 원본 보존·복원 및 같은 사건 중복 방지까지 확인한다. 실제 규정 발효 writer와 구형 저장 provenance, 대회별 역사 수용·이관은 `UNKNOWN`/`NOT_RUN`이다. 임의 정책 버전이나 역사 결과를 생성하지 않는다.

### B05 거부 불가형 바이아웃과 지급 계획

- [TRANS-005·007](../rulebook/30-TRANSFERS.md)은 구단 거부 불가형의 **계약상 행사·지급·선수 동의 조건**과 협상 개시권형의 최종 구단 합의를 분리한다. [#251의 선수·계약·재정 검증 기록](https://github.com/lkh0802a/LOL-GM/issues/251#issuecomment-6312211558)도 실제 계약과 분할 지급·채무·원자성·복원을 구분한다. GitHub 인수 기록은 원대화 및 후속 효력 전수 확인이 아니다.
- `contract-transfer-market.js:buyoutTransferError`는 거부 불가형의 **제안 총액**이 약정 금액 이상인지 검사하고, `state-player-actions.js:validatePlayerTransferAction`은 정규화된 계획의 **선지급액**에 대한 현금 가능성을 검사한다. `transfer-payments.js:settleTransferSigningFee`는 선지급 현금과 장래 분할 채무를 각각 기록한다. 이 경로만으로 계약상 분할 허용·행사 효력 시각 또는 원소속 구단의 최종 합의가 입증되는 것은 아니다.
- `node scripts/buyout-payment-observation.mjs`는 시장 단계를 직접 지정한 합성 세계에서 거부 불가형 2, 선지급 0, 30일 후 분할 2의 직접 `player.transfer`를 미리보기·실행했다. 실행은 성공했고 양측 현금은 100으로 그대로였으며 팀 소속은 변경되고 분할금은 `pending`이었다. 합성 저장 복원 후에도 `pending`이었고 원본은 불변이었다. 별도 전액 선지급 2 대조군은 실행 후 현금이 98/102였다. 이 사례는 선수 동의 검사와 기존 명령 경로를 실행하지만 **실제 계약의 지급 조건·원구단 합의·비라이선스 예외·실제 사용자 저장을 제공하지 않는다**. 따라서 이것만으로 계약 위반이나 실제 손실을 단정하지 않는다.
- **합성 분할금 만기·부족·복원 대조:** 위 진단의 이적 직후 복사본에서 만기 전 `processTransferPayments`는 2의 분할금을 `pending`으로 유지했다. 만기일 구매 구단 현금만 시험이 100에서 0.5로 낮추자 0.5가 판매자에게 지급되고 미지급 1.5가 `earned`로 남았으며, 양 구단 계약 사본은 같았다. 합성 저장을 복원해 같은 날 다시 처리해도 추가 지급은 없었다. 이후 구매 구단 현금을 시험이 2로 설정하자 남은 1.5가 지급되고 `paid=2`, `status=paid`가 됐으며, 재실행 시 저장 바이트 불변과 최종 복원 후 양측 사본 일치를 확인했다. 현금 변경은 통제 입력이지 실제 입출금이나 재원 획득의 증거가 아니다. 이 관찰은 해당 구형 분할 원장의 지급·복원 경로이며 계약상 분할 허용·바이아웃 행사 조건이나 실제 선수·사용자 저장의 정본 적합성을 입증하지 않는다.
- **양측 원장 불일치 합성 반례:** 부분 지급을 복원한 별도 복사본에서 판매자 측 지급액만 `0.5→0`으로 주입해 구매자 기록과 다르게 했다. `finance.transfer-payment`의 미리보기와 실행은 `invalid_invoice`로 거부했고, 그 손상된 입력을 `unpackDB`로 복원할 때도 양측 기록 불일치 오류가 났다. 거부 전후 손상 입력 바이트와 별도의 정상 부분지급 원본은 불변이었다. 이는 한 종류의 합성 손상에 대한 거부 관찰이지 실제 사용자 저장의 손상·복구, 모든 슬롯 격리 또는 모든 원장 무결성의 PASS가 아니다.
- **미결·완료 원장의 편측 부재:** 위 합성 부분 지급과 전액 지급 저장을 각각 복사해 판매자 측 해당 원장만 직접 삭제했다. 미결(`earned`) 복사본의 `unpackDB`는 양측 불일치로 거부했지만, 완료(`paid`) 복사본은 구매자 원장만 남은 상태로 복원됐다. 두 변형 입력 및 별도 합성 원본은 보존했다. 코드 `transfer-payments.js:validateStoredTransferState`의 양측 대조는 미결 행이 있을 때만 적용되며, `writeTransferDeal`은 구단별로 완료된 거래를 최대 10건 보관한다. 따라서 편측 부재가 곧 손상 또는 채무 미지급이라는 뜻은 아니다. 다만 완료 이적의 실제 계약·지급·과거 역사를 다른 보존 원장으로 추적할 수 있는지, 완료 기록의 정상 축약과 임의 삭제를 어떻게 구별할지는 이 실험에서 확인되지 않았다. 실제 사용자 저장의 원본·다른 슬롯 보호와 이관은 `NOT_RUN`이다.
- **완료 기록 축약의 합성 대조:** 지급 완료 저장의 별도 복사본에서 원 판매자와 제3구단 사이에 가상의 완료 원장 행 10건을 `writeTransferDeal`로 직접 기록했다. 추가 지급은 수행하지 않았다. 판매자 쪽 오래된 원장은 구단별 10건 제한으로 제거됐지만 최초 구매자 쪽 원장은 남았고, 이 합성 상태는 `unpackDB`로 복원됐다. 별도 지급 완료 원본 바이트는 불변이었다. 이는 편측 부재가 실제 축약 경로에서도 생성될 수 있음을 보여주는 코드 수준 대조이며, 가상의 10건이 실제 거래·실제 지급·실제 사용자 이력이라는 뜻은 아니다. 축약된 과거 거래의 계약·지급 근거가 다른 지속 원장에서 보존되는지와 이관 시 검증은 여전히 `UNKNOWN`/`NOT_RUN`이다.
- **양측 축약 뒤 남은 기록:** 완료된 기존 합성 이적의 양측 구단 각각에서 오래된 완료 원장을 밀어내도록 제3구단과 가상 완료 원장 20건을 직접 추가했다. 추가 대금 지급은 없었다. 양측 원본 거래 행이 모두 없어진 합성 저장을 복원해도 선수 `careerEvents`의 이적 상대·총액 2·선수 동의·분할 지급 **계획**과 구매/판매 구단의 `prepaid.transferPaid/Received` 합계 각 2는 남았다. 원본 지급완료 복사본의 이벤트·합계·바이트는 불변이었다. 그 합계는 개별 실제 지급일·지급액을 증명하는 거래별 지급 원장이 아니고, 20개 행은 실제 거래가 아니다.
- **합성 연간 결산 범위:** 위 상태의 별도 복사본에서 `closeFinances`를 직접 호출한 대조에서는 양 구단 `prepaid`가 비워지고 2027년 재정 이력의 구매 `exp.transfer=2`, 판매 `rev.transfer=2`와 선수 이적 이벤트 1건이 남았으며 복원 뒤도 같았다. 이 직접 호출은 실제 시즌 종료 시점을 재현하지 않는다. 코드상 구단 연간 이력은 최근 10개, 선수 이벤트는 최근 120개로 제한되므로 이 합성 1년 관찰을 영구 개별 지급 증거로 승격하지 않는다. 실제 계약·원장·시즌 경계 및 오래된 저장의 수용/보존은 `UNKNOWN`/`NOT_RUN`이다.
- 후속 검증에는 실재하는 각 바이아웃 계약의 금액·허용된 지급 일정·효력 시각·당사자 권한 및 시장/등록 조건을 제공하고, 계약상 전액 지급이 행사 조건인 경우와 유효한 분할 약정이 있는 경우를 분리한다. 선수 동의·매도자 합의 유무·지급과 미지급 원장·실제 소속/등록·기한 처리·중복 실행·실패 원본 보존/복원을 각각 비교한다. 원문 계약·적용 조건·실사용자 영향과 Rust 이관은 `UNKNOWN`/`NOT_RUN`이다. 분할을 세계 공통으로 금지하거나 허용하는 새 정책을 추정하지 않는다.

### B10 Worlds 경계 결정전과 선수 시상 집계

- [2026-11-12 P03 효력 기록](REMAINING_POLICY_AND_CONFLICT_RESOLUTIONS_2026_11_12.md)과 [COMP-022③](../rulebook/10-COMPETITIONS.md)은 실제 경계 결정전의 경기·선수 원본을 보존하되 정규 단계 MVP 통계에서 제외하고, 대회 전체 시상은 **사전 공표된 평가 범위가 포함할 때만** 별도로 반영한다. 당시 직접 대화 전문과 모든 후속 효력은 별도 `AUDIT_PARTIAL`이다.
- `competition-worlds.js:worldsStandings`는 결정전을 순위표 입력에서 제외한다. 한편 `competition.js:commitScheduledSeries`는 실제 경기 선수 줄을 `recordLines`로 전달하고, 이 함수는 정규/결정전 구분 없이 시즌 `pstats`에 누적한다. 같은 파일의 `finishStage`는 이 시즌 전체 집계를 단일 `mvp` 역사 필드에 사용한다. 이 필드가 사전 공표된 정규 전용 시상인지 전체 대회 시상인지는 해당 코드만으로 확정하지 않는다.
- 확장한 `node scripts/worlds-tiebreak-acceptance.mjs`의 합성 동률 양 경계(8·16)는 정규 Bo3 한 경기를 실제 실행해 선수 출전 30건을 기록하고 나머지 정규·초기 결정전 결과는 선수 줄 없는 통제 입력으로 구성했다. 이후 실제 결정 BO1은 각각 3·9경기였고 선수 출전 30·90건이 시즌 `pstats`에 추가됐다. 순위표 원래 3승·9세트승·SOS 18은 보존됐으며, 중간 저장 복원과 중단 없는 비교도 일치했다. **이는 해당 필드가 정규 전용 집계가 아니라는 관찰**이며 시상 규칙이 제공된 대회에서 실제 정규 MVP를 선정하거나 잘못 수상한 사례는 아니다.
- **시즌 집계의 MVP 기록 소비 대조:** 위 상태의 별도 복사본에 시험이 종료 브래킷과 마지막 경기 참조를 구성한 뒤 `finishStage`를 직접 호출했다. 16위 경계 사례에서 시즌 통계로 선택된 MVP는 실제 실행한 정규 경기에 없고 결정전만 6경기 출전한 합성 선수였다. 같은 종료 상태의 선수 통계를 실제 정규 Bo3 한 경기의 기록만으로 바꾼 대조군에서는 6경기 기준을 충족한 수상자가 없었다. 8위 사례는 두 경우 모두 수상자가 없었다. 나머지 정규·초기 결정전은 통제된 결과이고 종료 브래킷도 실제로 진행하지 않았으므로 이는 `pstats` 소비 경로의 반례이지 실제 대회 MVP 오선정이나 공표된 상의 범위에 관한 증거가 아니다. 실제 경기 원본을 지우거나 이 결과를 정상 규칙으로 고정하지 않는다.
- 후속 수용은 정규 경기 선수 원본과 결정전 원본을 모두 가진 동일 대회, 정규 전용 상과 결정전 포함/제외가 공표된 대회 전체 상, 정규 단계 전후 수상 후보·동률 및 저장 복원을 각각 비교한다. 실제 공표 시상 규정·기록 이관과 전체 대회/장기 시즌 수용은 `UNKNOWN`/`NOT_RUN`이다. 경기 원본을 삭제하거나 전체 `pstats`를 정규 전용으로 재해석하지 않는다.

### B04 중복 로컬 근속 시즌과 저장 검증

- [TRANS-014②](../rulebook/30-TRANSFERS.md)와 [기존 확정 운영 규칙 §2](../ROSTER_TRANSFER_LOCAL_RULES.md)은 유효한 부분 시즌을 1시즌으로 인정하면서 같은 시즌을 복수 이동으로 중복 누적하지 않는다. [C25 실행 대장](STEP3_COUNTEREXAMPLE_EXECUTION_REGISTER_2026_11_11.md)은 시즌 ID 유일성과 FA/임대 비누적을 별도 수용 조건으로 둔다. 해당 운영 기록은 직접 대화 전문 전체의 독립 열람을 의미하지 않는다.
- `local-service.js:localServiceRegistration`과 `processLocalServiceDaily`의 일반 누적은 `includes(db.year)`로 중복 삽입을 피한다. 반면 `validateStoredLocalService`는 시즌 배열의 정수 여부를 검사하지만 중복 여부는 검사하지 않으며 `checkLocalServiceQualification`은 서로 다른 시즌 수가 아니라 배열 길이를 기준으로 판정한다. 기존 `scripts/local-service-acceptance.mjs`는 같은 지역 이동·FA/타지역 임대·손상된 음수 일수 등을 검증하지만 중복 저장 배열은 해당 검사의 반례로 구성하지 않는다.
- `node scripts/local-service-duplicate-observation.mjs`는 **실제로 등록된 합성 선수의 한 시즌**으로 만든 저장 복사본에만 그 연도를 한 번 더 넣었다. 원본 대조군의 1개 시즌은 2시즌 요건에 미달했지만 합성 중복 `[2027,2027]` 복사본은 `unpackDB`에 수락됐고 `processLocalServiceDaily` 뒤 자격이 생성됐다. 합성 원본과 입력 JSON은 보존됐다. **중복은 시험이 직접 주입한 손상 데이터이며 정상 게임의 생성 경로나 실제 사용자 저장에 존재한다는 증거가 아니다.** 현재 시즌에 활성 로컬을 자동으로 변경한 사례도 아니다.
- **미래·비정수 시즌의 합성 대조:** 같은 실제 등록 2027년 한 시즌 복사본에만 2037년을 직접 추가하면 `unpackDB`가 수락하고 일일 처리 뒤 2027년 취득·2028년부터 선택 가능한 자격을 생성했다. 같은 위치에 2027.5를 추가한 별도 복사본은 정수 검증에서 복원을 거부했다. 두 합성 입력과 원본은 보존됐다. 추가 연도는 가상 손상값이며 실제 발생 경로·사용자 저장·유효한 장래 효력 근거가 아니다. 이 관찰을 자격 소급 취소 또는 자동 보정 정책으로 사용하지 않는다.
- 이 반례는 손상된 입력을 수용해 고유 시즌 수와 자격 판정이 달라지는 **합성 저장 무결성 경계**를 보여 준다. 실제 사용자 저장·발생 경로·발효 규정/기록 provenance는 `UNKNOWN`이다. 후속 담당 PR은 중복/비정수/미래 시즌과 적법한 부분 시즌·동일 시즌 이동·FA/타지역 임대·기존 자격/원장 보존, 실패 시 원본 바이트·다른 슬롯 보존과 합법적 복구 경로를 별도 검증해야 한다. 실제 저장 자동 보정·거부 정책이나 자격 소급 취소는 여기서 결정하지 않는다.
