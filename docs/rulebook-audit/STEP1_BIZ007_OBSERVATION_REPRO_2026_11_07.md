# BIZ-007 팬덤 관측 경계 — 승인·코드·통제 재현

- 승인 원문: [#237의 42번 사용자 승인](https://github.com/lkh0802a/LOL-GM/issues/237#issuecomment-6337928941)은 공개 경기·표본·인지도·실제 활동을 바탕으로 상업 가치를 산정하고 숨은 OVR·잠재력·비공개 진료/보고서 직접 소비를 금지한다. 숨은 실력이 실제 경기 및 이후 공개 평판을 통해 미치는 간접 효과는 허용한다.
- 룰북: [BIZ-007](../rulebook/60-BUSINESS.md)은 위 경계를 이미 명시한다. 이를 감사표에서 단순 부분 이관으로만 표시하던 상태를 교정한다. 원문 전수 효력 인증이나 게임 코드 수정을 의미하지 않는다.
- 기존 구현: 관찰한 main `bf670926efa74d5e105d774ff01dc320366954a3`의 [office.js](https://github.com/lkh0802a/LOL-GM/blob/bf670926efa74d5e105d774ff01dc320366954a3/src/artifact/office.js#L36)는 `updateHype`에서 선수의 `playerOvr`로 구단 스타 수를 만들고 팬덤에 더한다. 같은 파일 40행은 별도의 숨은 OVR 임계치로 지역 스타 수를 만들어 흥행에 더한다. 기존 세계 시간에서 이 함수를 호출하는 소비자는 `offseason.js`다.
- 통제 반례: 기존 `runEngineFixture`로 같은 새 세계·시드·선수단을 복제하고 공개 경기 시즌을 빈 상태로 유지한 채, 한쪽 선수 내부 속성만 20, 다른 쪽만 99로 바꾸고 실제 `updateHype`를 각각 실행했다. 지역 스타 수 **0→18**, 흥행 **43→56**, 세 구단 팬덤 `[32,30,55]→[36,36,59]`였다. 실제 세이브를 사용하지 않았다. 원본 임시 스크립트 `/tmp/lolgm-hype-observation-repro.mjs`의 재현을 `node scripts/audit-fandom-observation.mjs`로 보존한다. 이 도구는 관측 차이가 있으면 종료 코드 1을 반환한다. 이 값은 재현 환경의 관측값이지 승인된 게임 수치가 아니다. 첫 시도는 초기 선수단을 구성하지 않아 양쪽 모두 0으로 나왔으며, 선수단 구성 후 재현한 결과를 여기에 기재한다.
- 후속 수용: 같은 공개 기록·당시 시점·시드에서 비공개 속성만 바꾸면 직접 산정된 팬덤·흥행이 같아야 한다. 공개 경기·인지도·실제 활동이 달라진 경우 적법한 반응은 가능하다. 기존 경기 기록·관측 경계·세계 시계·원장을 재사용하며, 사용자/AI 동일 정보권한·저장 복원 및 계약 소비자 회귀를 확인한다. 구현 시 실제 관측 원본·#237 관련 PR 소유권·정본 선행조건을 먼저 확인한다.
