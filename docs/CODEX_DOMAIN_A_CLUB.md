## A1. 새 게임 · 감독/구단 선택 · 초기 선수단 · 저장 슬롯

- **담당:** 단계1·12, #241, #244; 국가·지역 1/2부는 #234·#239.
- **코드 조사 시작점:** `world.js`(`buildWorld/startCareer/setManagedTeam`), `roster.js`, `lineup.js`, `squad-preparation.js`, `ui-startup.js`, `ui-startup-storage.js`, `ui-setup.js`, `ui-market-initial.js`, `ui-initial-* .js`(실제 파일명은 manifest 참조), `ui-season.js`, `app.js`, `save.js`.
- **플로우:** 새 게임 누름 → 지역/리그/구단·디비전/저장 슬롯 선택 → 합법 선수 풀 생성 → 초기 제안·예산/로컬 자격 검증 → 계약 승인/필요한 등록/주전 조합 → 첫 일정/첫 공식 경기가 가능할 때만 진행 → 재접속 시 정확한 작업 단계.
- **점검:** 초기 풀의 5개 역할/합법 로스터 최저 인원·지역별 외국인/2군·대체 등록·무직 감독/재취업·구단주 권한; 새 구단을 구성할 때 상대 구단 재정·선수·FA 풀이 임의 중복/소멸하지 않는지. 팀 이름·로고/지역·구단 ID와 역할 변경을 분리. `worldConfig` 재생성 후 과거 슬롯이 바뀌지 않아야 함.
- **UI:** 선수 관심/비교 A/B/C·잠재력 추정·계약비용·등록 가능여부·영입 거부 이유가 첫 화면부터 연결. 실수로 구단을 바꾸거나 세이브를 덮어쓰는 조작에는 확인/되돌리기 가능 정책을 명확히 표시. '다음 필수 행동' 하나를 최상단에 배치하되 버튼이 엔진 액션까지 연결되어야 함.
- **반례:** 빈 슬롯과 손상 슬롯을 똑같이 '신규'로 처리하지 않음; 저장 도중 다른 슬롯 전환; 0명 팀/의료 결장; 초기 후보가 모두 타 구단과 계약; 첫 공식 등록 마감 직전/직후; 감독 무직·계약 종료·구단 해체; reload 후 같은 화면 선택. 무직이어도 AI 세계가 정상 진행되는지.
- **완료 증거:** 신규/재시작/저장된 각 플로우의 실제 명령과 `WorldAction` 결과, 선수 ID/소속·현금·등록·월드 날짜·저장 복원·모바일 버튼까지 고정 시드 인수 테스트. 이미 구현된 초기 FA 합법 공급 기능은 재작성 금지.

## A2. 선수 데이터 · 능력 · 챔피언 숙련 · 이름/신인

- **담당:** 단계2·3, #236; [#250 닉네임](https://github.com/lkh0802a/LOL-GM/issues/250), #239.
- **코드:** `player.js`, `development.js`, `content-naming.js`, `role-conversion.js`, `career.js`, `champs2.js`, `ui-player.js`, `ui-player-champions.js`.
- **모델:** 실능력 `attrs`, 가변 잠재력, 역할/챔피언/전술 숙련, 컨디션·폼·피로·평판·관계·계약 가치·관측 리포트를 **동일 숫자로 대체하지 않는다**. 세부 능력이 실제 경기/훈련 계산 소비자에서 읽히는지 역추적. 성장곡선은 선수별 요인/기회/코치/경기 수준/재활과 연결; 젊은 선수 자동 초대박, 고령 일괄 하락·확정 목표치 달성 금지.
- **신인:** 지역/국가·포지션·현역 FA 공급/은퇴·2부 육성·출전 경험과 신규 창단의 수급 충돌. `uniqNick`은 기존 이름 풀 200회 재시도 후 대체 문자열에 고유성 재검사를 하지 않는 코드 경계가 있으므로 의도적인 조합 고갈·고정 시드·수십 시즌 테스트. 동일한 닉네임/팀명/선수 ID·은퇴 후 동명 신인의 역사 식별자를 혼동하지 않는다.
- **수용:** 동일 선수·시드에서 유효한 출전/훈련·코치·역할·패치 노출만 달리한 paired-case가 실제 경기 행동/세부 숙련에 *설명 가능한* 영향을 줄 것. 선수가 부상·무직·임대·2군/상위리그로 이동할 때 성장·프로필·역사는 한 인물로 유지.
- **반례:** 포지션 전환 직후 상대 챔피언 경험/선발 적법성; 장기 휴식/재활; 기대 출전 미달·역할 약속; 같은 날 훈련+스크림 중복; 닉네임 충돌/계약 ID 충돌; 부상 선수의 공식 경기 강행.

## A3. 의료 · 질병 · 피로 · 재활 · 대체 등록

- **담당:** 단계2·5·6, #236·#241 및 [#248 정보 공개](https://github.com/lkh0802a/LOL-GM/issues/248).
- **코드:** `medical.js`, `practice-resources.js`, `registration.js`, `registration-match.js`, `ui-club-medical.js`, `ui-player.js`, `ui-squad-status.js`.
- **기존 규칙 보존:** 의료 확률/부상 종류·회복·후유증, 스태프와 시설의 회복 효과, 의료 대체 계약/등록·선발 제약 및 기존 의료 장기 테스트. 숫자를 마음대로 조정해 합격시키지 않는다.
- **실사용 연결:** 훈련/경기/스크림/이동 부하 → 매일 위험·발생 → 실제 결장/제한 출전·로스터/경기 가용성 → 재활 계획/대체 등록/급여 → 복귀 후 경기력·잔여 리스크 → 당시 의료/선수 역사. 각 이벤트의 소유 팀·시각을 보존.
- **비공개:** 내부 메디컬의 부위/잔여 정확 일수·진단과 타 구단에 **공개된** 결장/발표만을 구분. 타 팀 화면에 `medicalSummary`를 그대로 전달하는 경로를 정보 권한과 맞춰 검사. 상대 AI의 시야도 동일.
- **반례:** 결장·제한 출전 경계, 2군/모구단 긴급 대체·외국인 슬롯, 선수 계약 만료 중 부상, 정확한 같은 날 의료 tick 중복, 월말/대회 연속 경기, 부상 일수 0의 상태 전환, 저장/복원 중 재활.
- **검증:** 실제 발생률·연령/지역·회복 분포를 분리하고 기존 의료 핵심+seed shards+aggregate 테스트의 *원래 단언과 강도* 유지. 경미한 UI 텍스트 수정도 실제 정보 누출 여부를 검사.

## A4. 관계 · 팀워크 · 역할 약속 · 선수 불만 · 감독 커리어

- **담당:** 단계2·5·10·12, #236·#237·#241·#239.
- **코드:** `player-relations.js`, `role-conversion.js`, `lineup.js`, `state-player-actions.js`, `contract-negotiation.js`, `career.js`, `ui-player-commitments.js`, `ui-manager.js`.
- **인과 경로:** 계약상 역할/실제 공식 출전과 교체/국제전 가능성/로스터 이동 → 선수 만족·관계·신뢰 → 선수의 공개 반응/재계약/전술 수행·팀워크 변화 → 시즌별 경력 사건. 단발 선택으로 선수 모두에게 같은 팀 버프나 즉각 불만 폭발 금지.
- **감독:** 클럽으로부터 독립된 매니저 ID·현재 권한·계약/해임·새 구단 재취업/무직 경력을 유지. 구단 이직 후 **이전 구단의 비공개 스카우트/재정 자료를 감독 개인의 소유로 가져오지 않는다**. 직접 감독 결정은 AI 위임/직원 명령과 구분.
- **반례:** 후보 벤치와 장기 미출전, 의료 결장/강제 출전, 선수 요청 철회, 계약 갱신/시즌 경계, 친정팀 복귀, 주장급 선수 은퇴, 감독 해임 중 대기 계약/공식 밴픽. 같은 선수가 두 구단 선수단에 들어가는 일이 없어야 함.
- **제외:** 사용자가 제외한 별도 감독/직원 **인수인계 전용 시스템/화면을 새로 만들지 않는다**. 권한·기록·재정/계약 연속성 검사는 필요.

- **실제 사용:** 조사 승인 → 시간/출장/전문 인력·예산 소비 → 리포트 생성/변경 이력·시점 → 쇼트리스트/협상/밴픽 데이터 소비. 없는 표본과 낮은 성과를 구분, 공개 픽밴의 분모·패치/지역/포지션 필터 정확성.

- **반례:** 서로 다른 구단이 동일 선수에 대해 다른 지식, 감독 이직/스카우터 퇴사, 스태프 능력 비공개 계약, 경쟁자 미공개 영입 제안, 0/소표본/노후 리포트, 경력 초기·해외/2부, 세이브 및 원본 당시 관측 보존.

## A6. 선수 계약 · 재계약 · FA · 이적 · 에이전트 · 시간형 협상

- **담당:** 단계4, #224, #234, #225·#237; #241 원자성.
- **코드:** `contracts.js`, `contract-market-pricing.js`, `contract-market-behavior.js`, `contract-transfer-market.js`, `contract-negotiation.js`, `negotiation-final.js`, `contract-window.js`, `contract-contact-ai.js`, `contract-agreement.js`, `transfer.js`, `transfer-payments.js`, `player-representation.js`, `ui-negotiations.js`, `ui-negotiation-final.js`, `ui-market.js`.
- **단일 과정:** 관심 → 합법 접촉/스카우트·초기 제안 → 선수/구단/에이전트 심사 → 승인·거절·실제 역제안·경쟁 → **가계약/합의/독점/효력발생** 등 상태별 제한 → 감독이 실제 최종 확정하는 경우 최종 비용·로스터·이적 동의·마감 조건 재검사 → 금융 정산/소속 이전/등록/기록. 합의만으로 즉시 선수 소속 변경하지 않음.
- **시간 정책:** 이미 승인된 **기본 응답 2~8게임시간, 고민/경쟁 24~72게임시간**, 즉시 수락이 가능한 조건부 예외. 수동 시 단위 진행/다음 중요 사건까지 스킵은 실제 #234 세계시계와 동일. 무조건 수락/즉시 영입 금지.
- **오프시즌:** 최종 국제전 후 14일 소속팀 독점 협상/15일째 외부 접촉, 예정/실효 계약·계약기간·보장급/바이아웃/옵션/대표자 권리. 선수 역할/장기 목표·AI 구단의 예산·동의/거절을 동일 규칙으로 평가.
- **재정:** 연봉·이적료·보장·분할/채무·상호해지/방출 비용·선급·계약 옵션·예산 가용성과 미래 약속까지 진짜 원장에 반영. 마감/제안 취소·선수 이미 타 구단 계약·경쟁 bid에서는 부채/소속 한 번만 변경. 대기 합의는 슬롯/현금 예약이 아님(별도 유효 계약상 담보가 있을 때만 예외).
- **UI:** 여러 협상 카드에 누가 응답할 차례/게임 내 예상 시각·조건·타 구단 경쟁의 **합법 공개 범위**·선수 선택 이유·버튼(제안/기다림/거절/재제안/최종 확인)을 명확히. 소형 화면 닫기/뒤로가기/검색·필터/스크롤 유지, 최종 서명은 감독 명시적 의사결정.
- **반례:** 두 AI가 동시에 동의, 한 시간 내 마감/부상/예산 변경/계약만료, 미성년·외국인 제한, 대회 등록 마감, 미지급·구단 해체, 감독 해임 상태에서 대기 명령, 응답을 두 번 처리, 세이브 재개 후 제안 중복, 계약 '수락' 후 실제 총액 부족.
- **완료:** 적법 제안/거절·보장/동의/롤백/당시 약속·현금/등록/세계시간/UI/세이브를 하나의 인수 테스트로 증명. 이미 있는 `negotiation-final.js` 수동 승인 경계를 재구현/삭제 금지.
